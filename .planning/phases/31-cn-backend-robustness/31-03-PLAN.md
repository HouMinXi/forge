    keyword arguments to build_l1_provider signature, after the breaker parameter.

    Inside _provider(), at the llm_invoke call (line 288), pass max_attempts and

    Wrap the llm_invoke call and its LLMInvokeError catch (lines 287-326) in a
    pass-level retry loop: for pass_attempt in range(2). On the first attempt,
    if LLMInvokeError is caught and exc.retryable is True, print to stderr
    "code-forge: L1 pass '%s' failed, retrying..." % pass_name and continue to
    the next pass_attempt. On the second attempt (or if exc.retryable is False
    on the first), fall through to the existing INFRA finding creation code.

    CRITICAL: The existing except LLMInvokeError block at line 326 ends with
    `continue` which advances the OUTER pass loop (for pass_name, role ...).
    When the inner pass_attempt loop wraps this block, that `continue` would
    now advance the INNER loop instead of the outer one, causing non-retryable
    errors on attempt 0 to incorrectly proceed to attempt 1. Fix: replace the
    existing `continue` at line 326 with the pass_attempt loop's own control
    flow (break to exit inner loop after creating INFRA finding, then the outer
    loop's continue happens naturally via the _pass_succeeded flag check).

    The existing breaker.record_timeout() / record_other_error() calls stay in the
    final-failure path (not on retryable first failure). The existing
    breaker.record_success() call stays where it is (after successful response).

    NOTE: Prompt construction (lines 254-287 in factories.py) stays OUTSIDE the
    retry loop. The same prompt is reused on retry -- no need to rebuild it.

    The loop structure (explicit pseudo-code):

      # --- prompt construction happens HERE (before retry loop) ---
      # prompt = _build_pass_prompt(pass_name, role, ...)  [existing code]

      _pass_succeeded = False
      for pass_attempt in range(2):
          try:
              result = llm_invoke(prompt, backend=backend, ...)
              _pass_succeeded = True
              break   # exit INNER retry loop on success
          except LLMInvokeError as exc:
              if pass_attempt == 0 and exc.retryable:
                  print("retrying...", file=sys.stderr)
                  continue   # next INNER iteration (retry same pass)
              # final failure (attempt 1, or non-retryable on attempt 0):
              # create INFRA finding -- preserve existing breaker branching:
              all_candidates.append(StateFinding(...))
              if breaker is not None:
                  if exc.is_timeout:
                      breaker.record_timeout()
                  else:
                      breaker.record_other_error()
              break   # exit INNER retry loop (replaces old line-326 `continue`)

      if not _pass_succeeded:
          continue   # advance OUTER pass loop -- skip validate/coverage/findings

      # validate_reviewer_json, coverage guard, _json_to_state_findings run here
      # (only reached when _pass_succeeded is True)

    CRITICAL: the existing `continue` at factories.py:326 is REMOVED. It was
    the outer-loop advance. In the new structure, `break` exits the inner loop
    and `if not _pass_succeeded: continue` advances the outer loop explicitly.
    Without this explicit outer `continue`, the validate/coverage/findings code
    would run on failure (bug).

    Per D-31-06: L1 passes stay serial (the outer for pass_name, role in pass_configs
    loop is unchanged). ROBUST-04 is satisfied by HTTP retry + backoff in llm_invoke
    (serial dispatch naturally avoids rate-limit storms).
