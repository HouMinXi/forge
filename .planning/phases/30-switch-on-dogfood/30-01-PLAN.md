  <action>
    Add two new private functions to install_hooks.py, following the established
    _build_d12_precommit_block() pattern (returns a shell-script string fragment):

    1. _build_planning_leak_guard() -> str
       - Emits a shell block that runs: git diff --cached --name-only | grep -E '^\\.planning/|(^|/)CLAUDE\\.md$'
       - If matches found: prints "code-forge: BLOCKED: staged paths must never enter history:" to stderr, lists the matched paths, exits 1
       - This block runs BEFORE the non-code carveout because .planning/ must be blocked even for # docs commits (per D-30-05)
       - Place the function definition after _build_presubmit_block() (after line 312)

    2. _build_review_block(forge_invocation: str) -> str
       - First emits a `command -v {base_path} >/dev/null 2>&1` guard following
         the same pattern as _build_presubmit_block() (line 281). If the binary
         is not found, emit "review: code-forge not found, skipping" to stderr
         and SKIP the review (do NOT block). This handles CI/test environments
         where code-forge is not on PATH.
       - Then invokes: FORGE_SKIP_WORKTREE_CHECK=1 {base_path} review --baseline HEAD --head INDEX --max-total-rounds 2 --quiet
       - The base_path is derived from forge_invocation by stripping the trailing " gate-check" suffix (forge_invocation is "{path} gate-check")
       - Exit code handling in the shell block: exit 0 = continue; exit 2 = warn "review skipped (no backend configured)" to stderr but do NOT block; exit 5 (DELEGATED) = warn "review delegated (inline outlet)" but do NOT block; any other non-zero = print "review FAILED (exit $_RC)" to stderr and exit 1
       - Place after _build_planning_leak_guard()

    3. Extend generate_hook_content() signature:
       - Add parameter: planning_leak_guard: bool = False
       - When planning_leak_guard is True, prepend the planning-leak guard block BEFORE carveout_block
       - Add the review block AFTER presubmit_block but BEFORE the chain call (if chain_path) or before "exec gate-check" (if no chain_path)

    The updated hook execution order becomes:
      0a. .git jurisdiction check (git rev-parse --git-dir || exit 0) (D-30-06)
      0b. planning-leak guard (optional, when planning_leak_guard=True)
      1. carveout block (non-code commits exit 0)
      2. attestation
      3. built-in staged-diff check (D-12)
      4. presubmit runner
      5. LLM review (NEW)
      6. chain call (if chaining)
      7. exec gate-check (R1 test gate)

    Per D-30-06: the generated hook must silently skip in non-git directories.
    Add an explicit .git jurisdiction check at the very top of the generated hook
    (BEFORE the planning-leak guard): `git rev-parse --git-dir >/dev/null 2>&1 || exit 0`.
    This ensures non-git directories produce no output and no error (D-30-06).
    Without this, `git diff --cached` in non-git dirs prints "fatal: not a git
    repository" to stderr, violating the "no error, no output" requirement.
    The planning-leak guard goes after this .git check but before the carveout.
  </action>
