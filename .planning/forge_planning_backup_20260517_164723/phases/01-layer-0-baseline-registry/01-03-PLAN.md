Implement the tool execution engine per RESEARCH.md Pattern 4, with three additions from reviews.

1. Create `tests/test_runner.py` first. Use `unittest.mock.patch` to mock `shutil.which`, `os.path.isfile`, `os.access`, and `subprocess.run`. Test all behaviors above. Do NOT invoke real external tools in unit tests.

2. Create `src/forge/runner.py` with:

   - `_resolve_command(command: str) -> str | None`:
     - First try `shutil.which(command)` (handles PATH-based resolution)
     - If None and command contains os.sep (e.g., "scripts/checkpatch.pl"):
       - Check `os.path.isfile(command) and os.access(command, os.X_OK)`
       - If yes: return the command path (relative path to script)
     - Return None if not found either way
     - This addresses DeepSeek's finding: checkpatch.pl is a relative path, not on PATH. shutil.which alone misses it.

   - `capture_tool_version(command: str) -> str` (addresses Consensus #3 -- GATE-02 determinism):
     Round 8 R8-L7 (Mimo): the function returns one of three string KINDS that
     callers must distinguish:
       1. SENTINEL `"not_installed"` -- _resolve_command returned None
       2. SENTINEL `"unknown"` -- command ran but produced no usable output (empty
          stdout AND empty stderr after strip, or any exception caught)
       3. REAL version string -- e.g., `"shellcheck 0.11.0"`, `"ruff 0.15.13"`
     Both sentinels are lowercase snake-case and reserved -- no real tool prints
     `"not_installed"` or `"unknown"` as its --version output. Docstring MUST list
     all three return kinds with this distinction. state.json carries the literal
     string returned (no transformation); downstream consumers can pattern-match
     the sentinels to distinguish "tool absent" from "tool present but version
     unreadable" from "real version".
     - Resolve command via `_resolve_command()`
     - If not found: return "not_installed"
     - Run `subprocess.run([resolved_cmd, "--version"], capture_output=True, text=True, timeout=5, check=False)`
     - Round 7 R7-L2 (Kimi): some tools print version to stderr, not stdout (notably
       older `gcc`, some `cargo` subcommands, certain shell utilities). Try stdout
       first, fall back to stderr if stdout is blank:
       ```python
       text = result.stdout.strip() or result.stderr.strip()
       return text.splitlines()[0] if text else "unknown"
       ```
       This is the minimal change that recovers version info from stderr-only tools
       without changing the success path for stdout-emitting tools.
     - On any exception (timeout, OSError): return "unknown"
     - This is called once per tool at pipeline startup, NOT per file. The version string is recorded in state.json for GATE-02 reproducibility.

   - `run_tool(tool_config: ToolConfig, files: list[str]) -> tuple[str, int, str] | None`:
     - NOTE (Round 5 Kimi R5-M3): Return type is 3-tuple `(stdout, returncode, stderr)`,
       not 2-tuple. The stderr must be captured and propagated so that downstream code
       can populate ToolError.stderr with the tool's actual error output instead of an
       empty string. Without this, ToolError.stderr is always "" which defeats its
       diagnostic purpose.
     - Resolve command via `_resolve_command(tool_config.command)`
     - If not found and required=True: raise RuntimeError(f"Required tool not found: {tool_config.command}")
     - If not found and required=False: return None (log a note to stderr)
     - Build command: [resolved_cmd] + tool_config.args + files
     - If tool_config.working_dir == "cargo_root": do NOT append files to command (cargo clippy operates on crate, not individual files). Note (Round 3 DeepSeek H-2): the actual `_find_cargo_root()` function is NOT implemented in Phase 1. When working_dir="cargo_root", the runner skips appending files to the command but does NOT change the working directory. Clippy will only work if run from within a Cargo project root. This is sufficient for Phase 1 because clippy is optional (required=false) and will gracefully skip if it cannot find Cargo.toml. Full cargo_root detection (walking parent directories to find Cargo.toml) is deferred to Phase 2 when stdin-input mode is also added.
     - Run via `subprocess.run(cmd, capture_output=True, text=True, timeout=tool_config.timeout, check=False)`
     - NEVER use `shell=True` -- security requirement per RESEARCH.md threat model
     - On subprocess.TimeoutExpired: log warning, return None
     - On OSError/FileNotFoundError: log warning, return None
     - Return (result.stdout, result.returncode, result.stderr)

   - `run_tools(registry: dict[str, ToolConfig], files: list[str]) -> tuple[dict[str, tuple[str, int, str]], dict[str, str], list[str]]`:
     - EXPLICIT return shape (addresses Kimi H4 -- ambiguity in tool_results structure):
       * `tool_results: dict[str, tuple[str, int, str]]` -- keyed by tool name (NOT list of tuples).
         Each value is `(stdout: str, returncode: int, stderr: str)`. Look up by tool_name.
         The stderr field was added per Round 5 Kimi R5-M3 to propagate tool error output
         to ToolError.stderr for diagnostics.
       * `tool_versions: dict[str, str]` -- keyed by tool name, value is version string
         (e.g., "shellcheck 0.11.0") or "not_installed"/"unknown".
       * `tools_skipped: list[str]` -- tool names that were skipped (missing OR no
         matching files OR timed out).
     - Call `match_tools(registry, files)` ONCE before the per-tool loop (addresses
       Mimo F-04 -- avoid O(N * tools * files) repeated calls).
     - Iterate `sorted(registry.keys())` (Round 3 item 11 -- deterministic iteration
       order for GATE-02. Dict iteration order in Python 3.7+ is insertion order, which
       depends on YAML parse order. Sorting by tool name guarantees determinism regardless
       of YAML key ordering.)
     - For each tool_name in sorted(registry.keys()):
       - Capture version via `capture_tool_version(tool_config.command)` -> tool_versions[tool_name]
       - Look up matching files from match_tools result: `matching_files = matched.get(tool_name, [])`
       - If matching_files is empty: add to tools_skipped, continue (no files to lint)
       - Call `run_tool(config, matching_files)`
       - If result is None: add to tools_skipped list
       - Else: tool_results[tool_name] = (stdout, returncode, stderr)
     - This explicitly populates tool_versions (Consensus #3) and tools_skipped
       (DeepSeek: tools_skipped never populated).

   NOTE (Phase 1 scope -- addresses Kimi H2): checkpatch.pl requires PATCH input via
   stdin, not source file arguments. The current runner only supports file-argument
   tools. checkpatch.pl is therefore documented but NOT enabled by default in tools.yaml
   for Phase 1. Adding stdin-input mode (a new ToolConfig field `stdin_input: "diff" | "none"`
   and runner branch to pipe diff text) is tracked as a Phase 2 enhancement in CONTEXT.md
   deferred ideas. Plan 04 tools.yaml will include checkpatch with enabled: false.

Implement the delta computation module per RESEARCH.md Pattern 3 and LAYER0-02.

1. Create `tests/test_delta.py` first. Construct Finding objects directly and changed_lines dicts manually (no need for fixture files -- this is pure data filtering). Test all behaviors above including the multi-line range case per RESEARCH.md Pitfall 2.

2. Create `src/forge/delta.py` with:
   - `filter_delta(findings: list[Finding | ToolError], changed_lines: dict[str, set[int]]) -> tuple[list[Finding | ToolError], list[Finding | ToolError]]`:
     - Returns 2-tuple: (delta_findings, all_findings_full)
     - all_findings_full is a copy of the input list (addresses Mimo review: all_findings_full preserved before delta for reporter)
     - Round 8 R8-L2 (DeepSeek): use a SHALLOW copy via `list(findings)` (NOT
       `copy.deepcopy(findings)`). Finding and ToolError are frozen dataclasses
       (Plan 01) so their identity is sufficient -- no caller can mutate them, so
       deep copy adds cost without safety. Shallow copy is enough to give the
       reporter an independent list reference (so later mutations to the working
       list cannot affect the snapshot).
     - ToolError items are always included in delta_findings (tool errors are not filtered by line -- they represent tool-level failures that must be reported)
     - For each Finding:
       - Skip if finding.file not in changed_lines (file not in diff)
       - Get file_lines = changed_lines[finding.file]
       - Check if ANY line in range(finding.line, finding.end_line + 1) is in file_lines
       - If yes: keep the finding (it touches changed code)
       - If no: skip (pre-existing violation on unchanged line)
     - Return (delta_findings, all_findings_full)

   This function is pure (no I/O, no side effects). Same inputs = same outputs, satisfying GATE-02 determinism requirement.

   The 2-tuple return addresses Mimo's review finding that all_findings_full must be preserved before delta computation so the reporter can show "N pre-existing violation(s) in unchanged code."

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Tool binary execution | External tool processes executed via subprocess |
| Tool stdout -> forge | Output from external processes parsed by forge |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-01-07 | Tampering | runner.py subprocess | mitigate | Never use `shell=True`; always pass args as list to subprocess.run. Command constructed from registry + file list only. |
| T-01-08 | Spoofing | runner.py tool lookup | accept | `shutil.which()` resolves from PATH. Relative paths resolved via os.path.isfile + os.access. PATH is assumed trusted (user's environment). Document this assumption. |
| T-01-09 | Denial of Service | runner.py timeout | mitigate | Enforce timeout from ToolConfig (default 30s). TimeoutExpired returns None, does not block indefinitely. |
| T-01-10 | Spoofing | runner.py capture_tool_version | accept | Tool version captured via --version flag. A malicious binary could lie about its version. Low risk -- version is for reproducibility logging, not security enforcement. |
</threat_model>
