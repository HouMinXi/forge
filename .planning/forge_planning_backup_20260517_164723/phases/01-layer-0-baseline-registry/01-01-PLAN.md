     - Reject empty string: raise ValueError
     - Allow `--staged` and `--cached` as safe known flags (return as-is)
     - Reject other leading `-` (flag injection): raise ValueError
     - For all other inputs, enforce an ALLOWLIST regex (not just reject metacharacters):
       `^[A-Za-z0-9_./~@\^\-]+(?:\.\.[A-Za-z0-9_./~@\^\-]+)?$`
       Round 7 R7-L5 (DeepSeek): `^` and `-` placement inside the character class is
       fragile -- a literal `^` anywhere except first position works but is easy to
       break with future edits, and a literal `-` works at first/last but not middle.
       Both are now explicitly escaped (`\^`, `\-`) so reordering the class will not
       silently change semantics. The escaped form is unambiguous to every reader.
       This permits: branch names (`feature/foo`), tags (`v1.2.3`), commit hashes
       (`abc123`), HEAD references (`HEAD`, `HEAD~1`, `HEAD^`), remote refs
       (`origin/main`), commit ranges (`abc..def`, `HEAD~3..HEAD`), and the `@`
       character (for refs like `HEAD@`). Note: curly-brace syntax (`@{u}`,
       `@{upstream}`) is NOT permitted by this regex -- curly braces are excluded
       from the allowlist. Users should use explicit ref names instead.
       Reject everything else (backtick, $, ;, |, &, >, <, space, {, }, etc.)
       because they are NOT in the allowlist character class.

       * Exit 1: differences found (NORMAL -- return stdout containing diff)
       * Exit 128+: fatal git error (raise RuntimeError with stderr)
     - Implementation: `if result.returncode >= 128: raise RuntimeError(result.stderr or "git diff fatal error")`
       Otherwise return result.stdout (covers both exit 0 = no diff, and exit 1 = has diff).
     - This addresses Mimo F-03: git diff returns 1 when differences exist, NOT an error condition.
     - Note (Round 3 item 12): extra_args exists for future extensibility (e.g. --name-only).
       Currently unused by any caller in Phase 1 -- documented here to prevent confusion.

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| YAML config -> registry loader | User-editable .forge/tools.yaml could contain malicious YAML |
| User input -> diff_spec | CLI argument could be a flag injection attempt |
| git diff output -> diff parser | Diff text from git subprocess is generally trusted but could be malformed |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-01-01 | Tampering | registry.py YAML loading | mitigate | Use `yaml.safe_load()` exclusively -- never `yaml.load()` with FullLoader/UnsafeLoader. safe_load prevents arbitrary Python object instantiation. |
| T-01-02 | Tampering | git.py diff_spec | mitigate | `validate_diff_spec()` rejects leading `-` (except --staged/--cached), shell metacharacters (backtick, $, ;, pipe, &, >, <), and empty strings. Prevents flag injection into git subprocess. |
| T-01-03 | Tampering | diff.py input | accept | Diff text comes from git subprocess (trusted); malformed diff gracefully returns empty dict rather than crashing. Low risk. |
| T-01-04 | Tampering | git.py subprocess | mitigate | Never use `shell=True`; args as list. diff_spec validated before inclusion in command. |
</threat_model>
