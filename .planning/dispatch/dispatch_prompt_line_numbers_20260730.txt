## WHY THIS EXISTS

forge's commit gate is currently unpassable, and this is the last link in
the chain. Four other defects behind it are already fixed and waiting on
this one.

`verify.py` STEP C compares each `code_excerpts` entry against the diff
post-image, keyed by the `start_line` the reviewer reported. When that
number is off by one the whole attestation is voided:

    verify: FAIL -- excerpt content mismatch at src/code_forge/receipt.py:98

The quoted content is real and present in the file. Only the line number
is wrong.

## THE ITEM

Give the reviewer the line numbers instead of making it count them.

DECIDE AND ARGUE, do not assume:

  (a) The annotation format. It has to be unambiguous to a model, it must
      not stop the text reading as a diff (the `+`/`-`/` ` markers still
      carry meaning the reviewer needs), and it has to say something
      honest about deleted lines, which have NO post-image number at all.
      Whatever you pick, state what a `-` line shows and why.

  (b) Which sites get it, and how. Nine call sites doing their own string
      concatenation is the shape that produced this bug; a single shared
      helper applied where diff_text is prepared is the shape that
      prevents the next one. Argue your split between "sites whose output
      carries a line number" and "all of them", and say which sites you
      touched and which you deliberately did not.

  (c) Whether the token cost is acceptable. Annotating every line of
      every diff grows the prompt. Measure it on a real diff and say the
      number; if it is material, say what you would do instead.

## THE TRAP IN THIS ORDER

`canary_gen.py:347` sends `modified_diff`, NOT the original -- it is a
deliberately mutated diff used to check the reviewer catches a planted
bug. If you annotate from the unmutated text there, every canary line
number is wrong and the canary check silently degrades. Annotate from the
text actually being sent, or leave that site alone and say so.

Second trap: `_extract_post_image_lines` returns only lines present in
the hunks. It is not a whole-file map. Do not use it as one.

## ENVIRONMENT NOTES THAT COST ME HOURS TODAY

  - A fresh worktree has no .code-forge/gate.yaml (it is untracked). Copy
    it from the main tree and run `code-forge trust`, or the review
    silently falls back to user-level config.
  - The installed `code-forge` binary runs MAIN's src, not your
    worktree's. To exercise your own code use
    `env PYTHONPATH=$PWD/src python3 -m code_forge ...`.
  - `.code-forge/receipts/` has no per-run isolation. Delete
    receipt-*.json and state.json before every measurement or you will
    read a previous run's numbers.
  - LOCAL mode stops at an interactive prompt when a finding survives.
    Receipts are written before the prompt, so they are still usable.
  - Do not wait on work with `pgrep -f PAT`: the pattern matches your own
    shell's command line, so the loop never exits. Watch for the artifact
    instead.
