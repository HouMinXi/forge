## Why this exists (scope-challenge pre-answered)

The v3 flywheel (ledger -> eval growth -> escape intake ->
synthesis -> registry) starts here. Named top process risk:
"components built, ledger never fed" -- hence the dogfood hard
gate below. Three real consumers:
1. Phase 44 case generator: re-extracts reviewed diffs via
   base_sha/head_sha (the reviewed diff is NOT persisted anywhere
   today -- receipts hold excerpts only; verified).
2. Phase 42 claim_type oracle: consumes the axis_claim field
   (alignment memo, task T4).
3. Human ruling workflow: `ledger mark` / `ledger list`.
Do-nothing cost: review outcomes vanish at session end; the
self-evolution arc has no data source.

## Design decisions (ratified; do not relitigate)

- ESCAPED is LEDGER-side vocabulary ONLY. disposition.py's enum
  stays untouched (field changes there require a protocol version
  bump; runtime protocol stays v1).
- Ledger terminal states are a superset of disposition terminals:
  FIXED / DISPROVED(evidence_class) / DUPLICATE / ESCAPED.
- Append-only. No rewrites, no compaction in this phase.
