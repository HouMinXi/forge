**Staleness sweeps:**

`_sweep_stale_expansions(exp_data, ext_data, now_dt)`:
- `now_dt` is a datetime object (`datetime.now(timezone.utc)`). For each expansion with status=="pending": parse `created_at` via `datetime.fromisoformat(expansion['created_at'])`, then check if `(now_dt - created_at_dt) > timedelta(days=90)`:
  - Set expansion status = "auto_dismissed"
  - Find external finding by finding_id. If validated_dimension is None: set gap=True, validated_dimension="unknown". Otherwise leave unchanged.
  - Do NOT create gap candidate (per D5 spec: too stale for actionable gap analysis).
- Return count of auto-dismissed.

`_sweep_stale_candidates(gap_data, now_dt)`:
- `now_dt` is a datetime object. For each candidate with status in ("pending", "grouped"): parse `created_at` via `datetime.fromisoformat(candidate['created_at'])`, then check if `(now_dt - created_at_dt) > timedelta(days=180)`:
  - Set status = "auto_dismissed"
- Return count of auto-dismissed.

**Keyword expansion interactive review:**

`_review_expansions(exp_data, ext_data, config)`:
- Filter pending expansions (status=="pending", not auto-dismissed by sweep).
- For each pending expansion, display: proposed_dimension, unmatched_text, suggested_keywords.
- Prompt user: "[a]pprove / [r]eject / [s]kip / [q]uit"
- On approve:
  - Find external finding by finding_id FIRST (before any mutation). If not found: print warning "Warning: finding {finding_id} not found in external_findings, skipping", leave expansion status="pending", continue to next expansion.
  - If found: set expansion.status = "approved". Merge suggested_keywords into config keyword_dictionaries[proposed_dimension] (deduplicate). Set external finding validated_dimension = proposed_dimension, gap = False.
  - Update dimension_states via ensure_dimension_state: increment finding_count, set last_seen = now.
- On reject:
  - Find external finding by finding_id FIRST (before any mutation). If not found: print warning "Warning: finding {finding_id} not found in external_findings, skipping reject", leave expansion status="pending", continue to next expansion.
  - If found: set expansion.status = "rejected", set reclassified_to = gap_candidate_id (created below). Set external finding gap = True, validated_dimension = "unknown".
  - Create gap_candidate: id=gap-uuid, finding_id=expansion.finding_id, timestamp=(from ext finding), created_at=now, dimension_raw/text/text_hash/file/line/source (from ext finding), status="pending", group_id=None, reclassified_from=expansion.id.
- Handle EOFError/KeyboardInterrupt: save and return.
- Return modified flag.

**LLM grouping:**

`_group_candidates(gap_data, ext_data, config)`:
- Step 4 (from D5): Reset non-terminal candidates to status="pending", group_id=None. Skip candidates with status="grouped" (pending user action on a previous --propose recommendation) -- print count of skipped grouped candidates as info.
- Collect all pending candidates.
- If no pending candidates: print "No gap candidates to group." and return False.
- Call LLM via `_call_llm(prompt, backend, model, config, max_tokens=4096)` from llm_parser (lazy import: `from llm_parser import _call_llm, _get_backend, _parse_json_response`). Note: grouping response is a JSON array of groups with candidate_ids; 500 default is insufficient for 10+ candidates across multiple groups. Get `(backend, model) = _get_backend(config)`. If `_call_llm` returns None: print "Error: LLM call failed -- cannot group candidates. Check llm_backend/llm_model in config.json." to stderr, return early from `_group_candidates`. `run_gaps` continues to atomic_write changes from prior steps (staleness sweeps, expansion review) and prints the grouping error in its summary. This preserves partial progress while reporting the LLM failure.
  - **Prompt** (single string passed to `_call_llm` -- system and user content concatenated since `_call_llm` takes one prompt parameter):
    ```
    You are a code review dimension classifier. Group the following gap candidates by the code review dimension they represent. Each group should have a short proposed_dimension name (lowercase, underscores, e.g. 'supply_chain') and a one-line description.

    Candidates:
    {json_array of {"id": candidate_id, "dimension_raw": ..., "text": ...}}

    Return ONLY valid JSON. No markdown, no explanation.
    ```
  - **Expected response schema** (validated after LLM returns):
    ```json
    [{"proposed_dimension": "string", "description": "string", "candidate_ids": ["string"]}]
    ```
  - **JSON extraction**: use `_parse_json_response(response)` (imported from llm_parser) for consistent 3-level fallback (direct parse, strip fences, regex extract). If None: treat as LLM failure, return without writing groups.
  - **Validation** (on parsed JSON): (1) Must be a JSON array. (2) Each group must have all 3 fields. (3) Sanitize proposed_dimension: lowercase, replace non-`[a-z0-9_]` chars with underscore, truncate to 40 chars. If empty after sanitization: reject group. (4) All candidate_ids must exist in the pending candidates list. (5) No candidate_id appears in multiple groups. Validation failure at steps 1/2/4/5: print specific error to stderr, return without writing groups.
- Step 5: For each grouped candidate: status="grouped", group_id=assigned UUID.
- Write gap_groups.json (merge, not full overwrite): load existing gap_groups, retain groups whose status is still "pending" (user has not yet acted on them), append new groups from LLM. If a new group's candidate_ids overlap with an existing pending group's candidate_ids, the new group replaces the old one. Final structure: version=1, generated_at=now, groups=[...merged list...].
- Return True (grouping succeeded).
- LLM failure (any exception): print error to stderr, return False from `_group_candidates` without writing groups. `run_gaps` continues to atomic_write staleness/expansion results from prior steps, then prints "Warning: gap grouping failed (LLM error)" in its summary. Does NOT sys.exit -- partial progress from steps 1-3 is preserved. Note: D5 says "non-zero exit" but we deviate here intentionally to avoid losing staleness sweep + expansion review results.

**Group decision interaction:**

`_process_groups(gap_data, ext_data, exp_data, config)`:
- Load gap_groups. For each group with status=="pending":
  - Compute live non-terminal candidate count (re-check candidate statuses in gap_candidates).
  - If live count >= 3: group is proposal-ready. Display group info (proposed_dimension, description, candidate texts).
  - Prompt user: "[p]ropose / [r]eclassify to dim / [d]ismiss / [s]kip / [q]uit"
  - On propose (option a): leave candidates at status="grouped", group stays "pending". Print: "Group '{proposed_dimension}' ready for proposal. Run: forge --propose {group_id}" (user invokes --propose separately; no forward import to Plan 05). Skip to next group.
  - On reclassify (option b): prompt for target dimension. Validate target exists in keyword_dictionaries and is not archived. For each candidate: find ext finding by finding_id. If not found: print warning "Warning: finding {finding_id} not found, skipping candidate", skip this candidate. Otherwise: set validated_dimension=target_dim, gap=False. Merge suggested_keywords into target dim's keywords (deduplicated across all candidates). All candidates: status="reclassified". Group: filter candidate_ids, update count; if count==0: group status="dismissed". dimension_states[target_dim]: finding_count++ per candidate, last_seen=now (auto-create via ensure_dimension_state). Write audit record to keyword_expansion_queue for each candidate.
  - On dismiss (option c): group status="dismissed", all remaining non-terminal candidates in group: status="dismissed".
  - If live count < 3: display as "insufficient evidence" (not actionable). Skip to next group.
- Handle EOFError/KeyboardInterrupt: save and return.

**Main entry points:**

`run_gaps(approve_expansion_id=None)`:
- If approve_expansion_id: call approve_expansion_noninteractive and return.
- Load all data files.
- now_dt = datetime.now(timezone.utc)
- now = now_dt.isoformat()
- Step 1: _sweep_stale_expansions (pass now_dt for datetime arithmetic)
- Step 2: _sweep_stale_candidates (pass now_dt for datetime arithmetic)
- Step 3: _review_expansions (interactive)
- Step 4-5: _group_candidates (LLM grouping). Returns True on success, False on LLM failure or no pending candidates.
- Process groups: _process_groups (interactive) -- called if gap_groups.json contains any pending groups (check after _group_candidates, regardless of its return value). This ensures previously created pending groups are always reviewable even when no new candidates need grouping. Only print "Skipping group review due to LLM grouping failure." when _group_candidates returned False AND no pending groups exist in gap_groups.json.
- atomic_write all modified files (staleness sweeps and expansion results are written regardless of grouping outcome).

`approve_expansion_noninteractive(expansion_id)`:
- Load expansion queue. Find by id. Validate status=="pending" (exit non-zero if not).
- Apply same side effects as interactive approve (keywords added, ext finding updated, dimension_states updated).
- atomic_write. Print confirmation. Exit 0.

`run_reclassify(finding_id, target_dim)`:
- Per D4 --reclassify spec (all 5 side effects):
  1. External finding: validated_dimension = target_dim, gap = False.
  2. Derived entries: gap_candidates and keyword_expansion_queue entries whose finding_id matches AND status is non-terminal -> status="reclassified". Terminal entries left unchanged.
  3. suggested_keywords merged into target_dim's keyword_dictionaries entry (deduplicated).
  4. dimension_states[target_dim]: finding_count++, last_seen=now (auto-create if missing). dimension_states[old_dim]: finding_count-- (clamped to 0). If old_dim is "unknown", None, or not in dimension_states: skip decrement.
  5. Audit: write keyword_expansion_queue entry (status="approved", proposed_dimension=target_dim, etc.). Dedup key (proposed_dimension, text_hash): collision updates existing entry to "approved".
- Validate: target_dim must exist in keyword_dictionaries AND not be archived. If not, print error, exit 1.
- atomic_write all modified files.
