**cli/escalation.py**: Escalation health check monitor (LEARN-10).

File header: SPDX + Copyright. Docstring: "Escalation monitor -- self-sustaining health check for v2 upgrade triggers (LEARN-10)."

Imports: `json`, `os`, `sys` from stdlib. `datetime`, `timezone`, `timedelta` from datetime.

Constants:
```python
ESCALATION_FILE = os.path.join('.forge', 'escalation-status.json')
DEDUP_ERROR_THRESHOLD = 0.20  # 20% -- triggers LEARN-03
EDIT_CORRUPTION_THRESHOLD = 3  # 3+ corrupted edits -- triggers LEARN-04
DIMENSION_CHANGE_THRESHOLD = 10  # 10+ changes -- triggers LEARN-05
CHECK_INTERVAL_RUNS = 50  # every 50 pipeline runs
CHECK_INTERVAL_DAYS = 30  # or monthly
ROLLING_WINDOW_DAYS = 90  # 90-day window for dedup error rate
```

`load_escalation_status()`:
- Returns `{'version': 1, 'last_check': None, 'runs_since_check': 0, 'metrics': {}, 'alerts': []}` on missing/corrupt.

`should_run_check(escalation_data)`:
- Return True if:
  - last_check is None (never checked), OR
  - runs_since_check >= CHECK_INTERVAL_RUNS, OR
  - (now - last_check) > CHECK_INTERVAL_DAYS days
- Return False otherwise.

`compute_metrics(findings_data, external_data, config)`:
- **dedup_error_rate**: Filter external findings to 90-day rolling window (parse timestamp via `datetime.fromisoformat()` with Z-suffix compat: replace trailing `Z` with `+00:00` before parsing; compare against `now - timedelta(days=ROLLING_WINDOW_DAYS)`). Among those, find findings with `dedup_of != None` (total dedup attempts = denominator). For each such finding, look up the original finding by matching `id == dedup_of` in the same external_findings list. If original found and `original['validated_dimension'] != finding['validated_dimension']` (both non-None), count as false match (numerator). If original not found (deleted/missing), skip that pair entirely (exclude from both numerator AND denominator). Rate = numerator / adjusted_denominator (where adjusted_denominator = total dedup attempts minus skipped pairs). If denominator == 0, rate = 0.0.
  Note: In normal operation, dedup'd findings skip D4 classification, so validated_dimension stays null on the duplicate. The "both non-None" guard means the trigger only fires when a user manually reclassifies a dedup'd finding to a different dimension than its original via `--reclassify`. This is a known limitation of Level 1 -- the metric becomes meaningful at higher volumes where `--reclassify` is used frequently.
- **edit_corruption_count**: Load escalation status inside this function via `load_escalation_status()` (lazy import), then read `esc_data['metrics'].get('edit_corruption_count', 0)`. This counter is incremented by `run_propose` (Plan 05) when the LLM-generated SKILL.md.patch fails post-edit validation (patch doesn't apply or structural damage). At Level 1, `run_propose` discards failed patches and exits with error -- the counter records how many attempts failed. The counter persists in escalation-status.json across runs. When it reaches the threshold (3), it signals that LLM line-based editing is unreliable and AST-based edits (LEARN-04) should be considered.
- **dimension_change_count**: Count config dimension_states entries where added_at is not None AND status != "shadow" at migration time. Specifically: count entries added via `add_dimension` (user-initiated), NOT migration-auto-created shadow dims (doc_completeness, change_scope have added_at set by migration Step 3 but are not user additions). Implementation: count entries where `added_at is not None` and the dim is NOT in SHADOW_DIMENSIONS constant (lazy import from migration). This avoids premature LEARN-05 triggers from migration artifacts.
- **feedback_volume**: Count findings in findings.json with outcome in ('accepted', 'rejected'). Informational only.
- Return dict: `{'dedup_error_rate': float, 'edit_corruption_count': int, 'dimension_change_count': int, 'feedback_volume': int, 'computed_at': now}`

`check_triggers(metrics)`:
- Return list of (trigger_name, metric_value, threshold, recommendation) tuples for each crossed threshold:
  - dedup_error_rate > DEDUP_ERROR_THRESHOLD -> ("LEARN-03", rate, 0.20, "Rule-based deduplication is failing. Recommend upgrading to embedding classification.")
  - edit_corruption_count >= EDIT_CORRUPTION_THRESHOLD -> ("LEARN-04", count, 3, "Line-based SKILL.md edits are producing corrupted markdown. Recommend upgrading to AST-based edits.")
  - dimension_change_count >= DIMENSION_CHANGE_THRESHOLD -> ("LEARN-05", count, 10, "Enough dimension changes to justify structured evidence generation. Recommend structured evidence generator.")

`run_escalation_check(force=False)`:
- Load escalation status, findings, external findings, config.
- If not force and not should_run_check: return (no-op).
- Compute metrics.
- Check triggers.
- For each triggered alert, print to stderr:
```
[forge-escalate] {trigger_name} trigger met: {metric_name} {value} > {threshold} threshold.
  {recommendation}
  See .forge/escalation-status.json for details.
  Action: /gsd-plan-phase {trigger_name.lower()}-upgrade
```
- Update escalation_data: last_check=now, runs_since_check=0, metrics=computed_metrics, alerts=list of trigger dicts.
- atomic_write ESCALATION_FILE.

`increment_run_count()`:
- Load escalation status. Increment runs_since_check. atomic_write. Used by forge pipeline after each review run to track run count without running full check.
