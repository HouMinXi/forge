**cli/adapters/github_pr.py**: GitHub PR comment adapter.

File header: SPDX + Copyright Minxi Hou. Docstring: "GitHub PR source adapter -- fetches review and issue comments via gh api (D1)."

Imports: `json`, `subprocess`, `sys`, `re` from stdlib. Import `CanonicalFinding`, `BaseAdapter` from `adapters.base`. Import `List` from `typing`.

Class `GitHubPRAdapter(BaseAdapter)`:

Method `fetch(self, source_ref: str) -> List[CanonicalFinding]`:
- Parse `source_ref` as `"owner/repo#N"` format. `parts = source_ref.split('#')`. Validate `len(parts) == 2 and parts[1].isdigit()`; if not: print `f"Error: invalid --pr format '{source_ref}', expected 'owner/repo#N'"` to stderr, return empty list. `repo = parts[0]`, `pr_num = parts[1]`.
- Fetch review comments (inline on diff): `subprocess.run(['gh', 'api', '--paginate', f'repos/{repo}/pulls/{pr_num}/comments', '--jq', '.[]'], capture_output=True, text=True, timeout=60, check=False)`.
- Fetch issue comments (general PR comments): `subprocess.run(['gh', 'api', '--paginate', f'repos/{repo}/issues/{pr_num}/comments', '--jq', '.[]'], capture_output=True, text=True, timeout=60, check=False)`.
- Parse each line of stdout as JSON object (newline-delimited from --jq '.[]'). Handle empty stdout gracefully.
- Error handling: if returncode != 0, print to stderr and return empty list (not None -- adapter contract returns List).
- For each comment dict, create CanonicalFinding:
  - `source = "github_pr"`
  - `source_tool = _detect_source_tool(comment)` (see helper below)
  - `source_id = str(comment['id'])`
  - `timestamp = comment['created_at']` (already ISO-8601 from GitHub API)
  - `raw_source = comment.get('body') or ''`
  - `context = {"diff_hunk": comment.get('diff_hunk', None), "pr_url": f"https://github.com/{repo}/pull/{pr_num}", "path": comment.get('path', None)}`

Helper `_detect_source_tool(comment: dict) -> str`:
- First check: `user_info = comment.get('user') or {}`. If `not user_info` (null or missing user): return "unknown".
- Check `(user_info.get('type') or '') == 'Bot'` -> check login patterns (use `or ''` to handle null type value from API)
- `login = (user_info.get('login') or '').lower()` (guard against null login)
- Login pattern matching (case-insensitive): "qodo" in login -> "qodo", "coderabbit" in login -> "coderabbit", "copilot" in login -> "copilot", "github-actions" in login -> "github-actions"
- If user.type == 'Bot' but no pattern match -> "unknown"
- If `(user_info.get('type') or '') != 'Bot'` -> "human"

**cli/adapters/git_log.py**: Git log revert/fixup/squash adapter.

File header: SPDX + Copyright. Docstring: "Git log source adapter -- scans reverts, fixup!, and squash! commits (D1)."

Imports: `subprocess`, `sys`, `re` from stdlib. Import `CanonicalFinding`, `BaseAdapter` from `adapters.base`. Import `List` from `typing`.

Class `GitLogAdapter(BaseAdapter)`:

Method `fetch(self, source_ref: str) -> List[CanonicalFinding]`:
- `source_ref` is a branch name. Compute merge base: `subprocess.run(['git', 'merge-base', source_ref, 'HEAD'], capture_output=True, text=True, timeout=10, check=False)`. If fails, use source_ref directly as the range start.
- Search for reverts: `subprocess.run(['git', 'log', '--grep=^Revert ', '--format=%H|%aI|%s', f'{merge_base}..HEAD'], capture_output=True, text=True, timeout=30, check=False)`.
- Search for fixup!: `subprocess.run(['git', 'log', '--grep=^fixup! ', '--format=%H|%aI|%s', f'{merge_base}..HEAD'], capture_output=True, text=True, timeout=30, check=False)`.
- Search for squash!: `subprocess.run(['git', 'log', '--grep=^squash! ', '--format=%H|%aI|%s', f'{merge_base}..HEAD'], capture_output=True, text=True, timeout=30, check=False)`.
- For each match line, split on '|' to get commit_sha, timestamp, subject.
- Get diff for each commit: `subprocess.run(['git', 'diff', f'{sha}~1..{sha}'], capture_output=True, text=True, timeout=30, check=False)`.
- Create CanonicalFinding:
  - `source = "git_log"`
  - `source_tool = "git"`
  - `source_id = sha`
  - `timestamp = timestamp` (from --format=%aI, already ISO-8601)
  - `raw_source = subject` (commit message subject line)
  - `context = {"diff_hunk": diff_output[:2000], "commit_sha": sha, "branch": source_ref}` (truncate diff to 2000 chars)
- Deduplicate by SHA within the batch (same commit might match both revert and fixup patterns).

**cli/adapters/ci_log.py**: CI log file adapter.

File header: SPDX + Copyright. Docstring: "CI log source adapter -- reads local CI failure log files (D1)."

Imports: `hashlib`, `sys`, `os` from stdlib. Import `CanonicalFinding`, `BaseAdapter` from `adapters.base`. Import `List` from `typing`. Import `datetime`, `timezone` from `datetime`.

Class `CILogAdapter(BaseAdapter)`:

Method `fetch(self, source_ref: str) -> List[CanonicalFinding]`:
- `source_ref` is a local file path (from `--ci-file <path>`).
- Validate file exists: `os.path.isfile(source_ref)`. If not, print error to stderr, return empty list.
- Read file content: `open(source_ref, 'r', encoding='utf-8')` with try/except for IOError/UnicodeDecodeError.
- Compute base source_id: `hashlib.sha256(content[:1024].encode('utf-8')).hexdigest()`.
- Create a single CanonicalFinding (LLM parser may split into multiple findings with index suffix):
  - `source = "ci_log"`
  - `source_tool = "ci"`
  - `source_id = content_hash` (no index suffix -- the LLM parser adds `-0`, `-1`, etc. for multi-finding extraction per D1 spec)
  - `timestamp = datetime.now(timezone.utc).isoformat()`
  - `raw_source = content[:5000]` (cap at 5000 chars to limit LLM input)
  - `context = {"diff_hunk": None, "ci_output_excerpt": content[:1000]}`

**cli/llm_parser.py**: LLM-based structured finding extraction with configurable backend.

File header: SPDX + Copyright. Docstring: "LLM parser -- extracts structured findings from external review comments. Backend-agnostic: supports claude_cli, openai_compat, and anthropic backends (D2)."

Imports: `json`, `os`, `sys`, `hashlib`, `re`, `subprocess`, `dataclasses` from stdlib. Import `CanonicalFinding`, `ExtractedFinding` from `adapters.base`. Import `List`, `Optional`, `Tuple`, `Union` from `typing`.

**Backend abstraction:**

`_get_backend(config)`:
- Read `backend = config.get('llm_backend', 'claude_cli')` and `model = config.get('llm_model', 'claude-sonnet-4-6')`.
- Return `(backend, model)`.

`_call_llm(prompt, backend, model, config, max_tokens=500)` -> `Optional[str]`:
- **max_tokens cap**: For `anthropic` backend, cap max_tokens at `min(max_tokens, 8192)` (Anthropic model output limit). For `openai_compat`, cap at `min(max_tokens, 16384)` (most providers support this; some may support more). For `claude_cli`, max_tokens is not applicable (CLI manages output length). Log a warning if the requested max_tokens was capped.
- **`claude_cli`** (default, zero SDK dependency): `subprocess.run(['claude', '-p', prompt], capture_output=True, text=True, timeout=120)`. Return `result.stdout.strip()` (raw LLM text). Do NOT use `--output-format json` -- it wraps output in Claude Code metadata, not raw LLM JSON. Caller (`extract_finding_from_comment`) passes this string to `_parse_json_response` for JSON extraction. This uses the existing `_invoke_claude` pattern from forge_cli.py (line 1800).
- **`openai_compat`** (DeepSeek, Kimi, GLM, any OpenAI-compatible API): use module-level cache via `global _openai_client, _openai_cache_key` (both initialized to `None` at module level). Compute `cache_key = (config.get('llm_base_url') or 'https://api.openai.com/v1', os.environ.get('OPENAI_API_KEY') or config.get('llm_api_key') or '')`. If `_openai_client is None or _openai_cache_key != cache_key`: `import openai; _openai_client = openai.OpenAI(base_url=cache_key[0], api_key=cache_key[1]); _openai_cache_key = cache_key`. Subsequent calls with same config reuse the cached client; config changes trigger re-initialization. Call `client.chat.completions.create(model=model, messages=[{"role": "user", "content": prompt}], max_tokens=max_tokens, response_format={"type": "json_object"})`. Return `response.choices[0].message.content`. On `response_format` 400 error (e.g. DeepSeek json_schema unsupported): retry without `response_format`, relying on prompt-level JSON instruction.
- **`anthropic`** (direct Anthropic SDK): `import anthropic; client = anthropic.Anthropic()`. Call `client.messages.create(model=model, max_tokens=max_tokens, messages=[{"role": "user", "content": prompt}])`. Iterate `response.content` to find first block with `type == "text"` and return its `.text` (skip thinking blocks -- DeepSeek v4 via Anthropic-compat may return multiple thinking blocks before text). If no text block found: return None.
- On unrecognized backend value: `print(f"Error: unknown llm_backend '{backend}'. Valid values: claude_cli, openai_compat, anthropic", file=sys.stderr)`. Return None.
- On ImportError (SDK not installed): print specific message "Error: {backend} backend requires '{package}' package. Install it or switch llm_backend to 'claude_cli'." Return None.
- On any API/subprocess error: print warning to stderr, return None.

**Prompt (shared across all backends):**

`_build_extract_prompt(raw_text, diff_hunk, file_path, ci_mode=False)` -> `str`:
```
Extract structured code review finding(s) from this comment.

Comment:
{raw_text}

Diff context:
{diff_hunk or 'No diff context available'}

File: {file_path or 'Unknown'}

[If ci_mode: "This is a CI log that may contain MULTIPLE distinct failures. Return a JSON ARRAY of findings, one per distinct failure." Otherwise: "Return a single JSON object."]

Each finding must have these fields:
- dimension_raw: free-text description of the concern category (do NOT use a canonical dimension name -- describe what the reviewer is worried about)
- confidence: 0-1 how faithfully this extraction represents the original comment
- suggested_keywords: array of 2-5 keywords characterizing the concern (include terms that capture hidden implications -- e.g. "classic race condition" implies "thread safety", "locking", "shared state")
- text: one-sentence structured finding description
- file: code file path (null if general comment)
- line: line number as integer (null if general comment)

Return ONLY valid JSON. No markdown, no explanation.
```

**JSON extraction (shared):**

`_parse_json_response(raw_response)` -> `Optional[Union[dict, list]]`:
- Try `json.loads(raw_response)` directly.
- If JSONDecodeError: strip markdown code fences (`re.sub(r'```(?:json)?\s*|\s*```', '', raw_response).strip()`), retry `json.loads`.
- If still fails: try extracting first `{...}` or `[...]` block via regex.
- Return parsed JSON or None.

**Field validation (shared):**

`_validate_finding(data)` -> `Optional[ExtractedFinding]`:
- confidence: must be float 0-1 (clamp). Default 0.5 if missing/invalid.
- suggested_keywords: must be list of strings. Default [] if missing.
- dimension_raw: must be non-empty string. Return None if missing.
- text: must be non-empty string. Return None if missing.
- file: str or None. line: int or None.
- Return ExtractedFinding from validated fields.

**Main functions:**

`extract_finding_from_comment(raw_text, diff_hunk, file_path, backend, model, config, ci_mode=False)` -> `List[ExtractedFinding]`:
- Build prompt via `_build_extract_prompt(raw_text, diff_hunk, file_path, ci_mode)`.
- Call `_call_llm(prompt, backend, model, config)`. If None: return [].
- Parse response via `_parse_json_response`. If None: return [].
- If result is dict: wrap in list `[result]`.
- If result is list: use as-is.
- Validate each item via `_validate_finding`. Return valid ExtractedFindings.

`extract_findings(canonical_findings: List[CanonicalFinding], config: dict = None) -> List[Tuple[CanonicalFinding, ExtractedFinding]]`:
- If config is None: load via `load_config()` (lazy import from forge_cli).
- Get `(backend, model) = _get_backend(config)`.
- For each CanonicalFinding:
  - `ci_mode = (canonical.source == "ci_log")`.
  - Call `extract_finding_from_comment(canonical.raw_source, canonical.context.get('diff_hunk'), canonical.context.get('path'), backend, model, config, ci_mode)`.
  - For each returned ExtractedFinding at index i: if `ci_mode and i > 0`: clone canonical via `dataclasses.replace(canonical, source_id=f"{canonical.source_id}-{i}")` (CI multi-finding needs distinct source_ids for dedup). Append (canonical_or_clone, extracted) tuple unconditionally (the clone is conditional, the append is not -- all findings from LLM are kept regardless of source type).
  - If no results: print warning to stderr with source_id, continue.
- Return list of tuples.

Define `compute_text_hash(text: str) -> str`:
- Return `hashlib.sha256(text.encode('utf-8')).hexdigest()`.
- Used by the dedup pipeline in Plan 03 and stored in external_findings.json.

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| gh API -> adapter | External GitHub API responses are untrusted input |
| LLM output -> parser | LLM response text may contain malformed JSON or injection attempts |
| CI log file -> adapter | User-provided file path may not exist or contain unexpected content |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-03-04 | Tampering | LLM prompt injection via malicious PR comments | mitigate | Parse LLM output strictly via json.loads(); validate field types (confidence clamped 0-1, suggested_keywords must be list); never execute LLM output as code |
| T-03-05 | Information Disclosure | API keys in environment | mitigate | SDK reads from env var automatically; never log or print the key; error messages reference the backend name and required package, not key values |
| T-03-06 | Tampering | gh api response manipulation | accept | gh CLI handles TLS; response is parsed as JSON; fields are type-checked before use; low-value target (review metadata only) |
| T-03-07 | Denial of Service | Large CI log file | mitigate | Cap raw_source at 5000 chars, ci_output_excerpt at 1000 chars; prevents unbounded memory from large log files |
| T-03-08 | Tampering | Path traversal in --ci-file | mitigate | os.path.isfile() validation; file is read-only, not executed; no directory traversal risk in read operation |
</threat_model>
