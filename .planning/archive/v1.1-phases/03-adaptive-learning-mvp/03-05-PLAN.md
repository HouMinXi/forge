**Proposal generation (D6):**

`run_propose(group_id)`:
- Load gap_groups. Find group by group_id. Validate: (1) group exists, (2) group status == "pending".
- Load gap_candidates. Re-check live count: count candidates in group's candidate_ids whose status is "grouped" (the status set by _group_candidates in Plan 04). Validate count >= 3. If any validation fails: print error to stderr, sys.exit(1).
- Load external_findings to get full finding data for each candidate (via finding_id). Validate all finding_ids exist in external_findings; skip candidates with missing findings (print warning per missing id). If remaining candidates < 3 after skipping: print error, sys.exit(1).
- Load config via `load_config()` (lazy import from forge_cli) for LLM backend settings.
- Call LLM via `_call_llm(prompt, backend, model, config, max_tokens=40960)` from llm_parser (lazy import: `from llm_parser import _call_llm, _get_backend, _parse_json_response`). Get `(backend, model) = _get_backend(config)`. Note: proposal generation needs significantly more tokens than finding extraction (default 500) because the response contains 4 large JSON keys (skill_md_patch, evidence_md, seed_test_diff, readme_md). Set high to avoid truncation -- actual usage depends on proposal complexity; API bills by actual output, not the cap.
- **Proposal LLM prompt** (single call, JSON response):
  ```
  Generate a proposal bundle for a new code review dimension.

  Dimension name: {proposed_dimension}
  Description: {group_description}

  Source findings:
  {json_array of candidate texts, dimension_raw, suggested_keywords, file, line}

  Return ONLY valid JSON with these 4 keys:
  - skill_md_patch: unified diff (--- a/skills/forge/SKILL.md / +++ b/...) adding the dimension as a new numbered checklist item under the appropriate section
  - evidence_md: markdown document with # Evidence heading and ## Finding N subsections
  - seed_test_diff: unified diff (--- /dev/null / +++ b/tests/seed_tests/seed_diffs/{dim}.diff) adding a synthetic test case
  - readme_md: markdown with # Proposed Dimension heading, description, keyword list, and usage instructions

  Return ONLY valid JSON. No markdown fences, no explanation.
  ```
- Parse response via `_parse_json_response`. Extract 4 keys. Write each to its respective file in the proposal directory. If any key missing: print warning, write available files only.
- Build keywords.json deterministically: flat array from suggested_keywords of external findings referenced by candidates (via finding_id), deduplicated, sorted.
- **Proposal file formats (H5)**:
  - `SKILL.md.patch`: unified diff format (`--- a/skills/forge/SKILL.md` / `+++ b/skills/forge/SKILL.md`). Adds a new section under the appropriate dimension heading with dimension name, description, and review checklist items derived from candidate findings.
  - `evidence.md`: markdown with `# Evidence for {dim_name}` heading, then one `## Finding {N}` subsection per candidate showing source, text, file, line, and why this constitutes a gap.
  - `seed_test.diff`: unified diff that creates a new synthetic test file for the dimension. The file must exercise the new dimension (e.g., for "supply_chain" dim, a file introducing a dependency confusion scenario). Format: standard unified diff with `--- /dev/null` / `+++ b/tests/seed_tests/seed_diffs/{dim_name}.diff` (new file creation).
  - `keywords.json`: flat JSON array of lowercase strings, sorted alphabetically, deduplicated. Example: `["dependency confusion", "supply chain", "typosquatting"]`.
  - `README.md`: markdown with `# Proposed Dimension: {dim_name}` heading, one-paragraph description, keyword list, evidence summary, and instructions for `forge --add-dimension {dim_name} --keywords-file keywords.json`.
- Directory naming: proposed_dimension from gap_groups, lowercased, sanitized to `[a-z0-9_]` (non-matching chars replaced with underscore), truncated to 40 chars. Empty after sanitization -> `dim_{group_id[:8]}`.
- Crash safety: write to `.forge/proposals/.tmp-{dim_name}/`, then `os.rename` to `.forge/proposals/{dim_name}/`. Existing directory: `shutil.rmtree` + rename (best-effort per D6 spec).
- Post-edit validation (two-step): (1) Run `subprocess.run(['git', 'apply', '--check', patch_path], capture_output=True)` to verify patch applies cleanly (runs in repo root where `skills/forge/SKILL.md` exists). If exit code != 0: validation failure. (2) Actually apply patch to a temp copy: create tmpdir with matching directory structure `os.makedirs(os.path.join(tmpdir, 'skills', 'forge'), exist_ok=True)`, copy SKILL.md to `os.path.join(tmpdir, 'skills', 'forge', 'SKILL.md')`, run `subprocess.run(['git', 'apply', os.path.abspath(patch_path)], cwd=tmpdir)` (use absolute path for patch since cwd changes), read the patched file from `os.path.join(tmpdir, 'skills', 'forge', 'SKILL.md')`. Check: result has at least one `#` heading (valid markdown), and result is not shorter than original by >20% in lines. Validation failure at either step: try to increment `edit_corruption_count` in escalation-status.json (lazy import: `from escalation import load_escalation_status, ESCALATION_FILE` and `from forge_cli import atomic_write`; load, increment `metrics.edit_corruption_count`, write back). Wrap the escalation import in try/except ImportError (escalation.py may not exist yet if Plan 06 hasn't been executed -- in that case, skip the counter increment silently). Discard patch, print error, sys.exit(1).
- **PR pipeline (LEARN-06)**: After proposal files are written (but BEFORE status update):
  1. Branch: check if `forge/dim-{dim_name}` exists via `git rev-parse --verify`. If exists: `git checkout forge/dim-{dim_name}`. If not: `git checkout -b forge/dim-{dim_name}`. This handles retries after prior PR pipeline failures.
  2. Stage proposal files: `subprocess.run(['git', 'add', '-f', f'.forge/proposals/{dim_name}/'], check=True)`. Use `-f` to force-add even if `.forge/` is in `.gitignore` (proposal files are meant to be reviewed in the PR).
  3. Check for staged changes: `subprocess.run(['git', 'diff', '--cached', '--quiet'], capture_output=True)`. If exit code == 0 (no staged changes -- proposal files already committed from a prior retry): skip commit step, proceed to push. Otherwise commit: `subprocess.run(['git', 'commit', '-m', f'forge: propose new dimension {dim_name}\n\nBased on {len(candidate_ids)} external review findings suggesting a gap in {dim_name} coverage.'], check=True)`.
  4. Push: `subprocess.run(['git', 'push', '-u', 'origin', f'forge/dim-{dim_name}'], check=True)`.
  5. Create PR with body template:

  6. Return to original branch: `subprocess.run(['git', 'checkout', original_branch], check=True)`.
  - The entire PR pipeline (pre-steps + steps 1-5) is wrapped in try/except (CalledProcessError, FileNotFoundError). This includes the pre-step git commands below:
  - Pre-step: check for uncommitted changes via `subprocess.run(['git', 'status', '--porcelain'], capture_output=True, text=True)`. If stdout is non-empty: print "Warning: uncommitted changes detected. Stashing before branch creation." and run `subprocess.run(['git', 'stash', '--include-untracked'], check=True)`. Set `stashed = True` flag. In the finally block (after step 6 or except), if `stashed`: run `result = subprocess.run(['git', 'stash', 'pop'], capture_output=True, text=True)`. If result.returncode != 0: print `f"Warning: git stash pop failed: {result.stderr}"` to stderr (merge conflicts may need manual resolution).
  - Pre-step: save original branch: `original_branch = subprocess.run(['git', 'rev-parse', '--abbrev-ref', 'HEAD'], capture_output=True, text=True).stdout.strip()`. If `original_branch == "HEAD"` (detached HEAD state): use full SHA instead via `original_branch = subprocess.run(['git', 'rev-parse', 'HEAD'], capture_output=True, text=True).stdout.strip()`. On CalledProcessError: attempt `subprocess.run(['git', 'checkout', original_branch], capture_output=True)` to restore branch, then print `f"forge: PR pipeline failed at step {step_name}: {exc}"` to stderr, exit 1. Proposal files remain in .forge/proposals/ for manual retry. On FileNotFoundError: handle per tool:
