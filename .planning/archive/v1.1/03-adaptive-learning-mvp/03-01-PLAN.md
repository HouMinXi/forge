1. `CanonicalFinding` -- pre-LLM canonical schema from adapter (adapter-set fields):
   - `source: str` -- "github_pr" | "git_log" | "ci_log"
   - `source_tool: str` -- "human" | "qodo" | "coderabbit" | "copilot" | "github-actions" | "unknown" | "git" | "ci"

   - `timestamp: str` -- ISO-8601 original event time
   - `raw_source: str` -- original unprocessed text

2. `ExtractedFinding` -- post-LLM structured finding (LLM-extracted fields):

   - `text: str` -- one-sentence structured finding description
   - `file: Optional[str]` -- code file path (None if general)
   - `line: Optional[int]` -- line number (None if general)

Define abstract base class `BaseAdapter(ABC)`:
   - `@abstractmethod def fetch(self, source_ref: str) -> List[CanonicalFinding]`: Fetch and normalize raw input from the source. `source_ref` is the CLI argument value (PR ref, branch name, file path).

All field names and docstrings must use ASCII only (no em dashes, no smart quotes).

Define `migrate_to_dimension_states(config, findings_data)`:
Note: `skill_md_path` parameter removed -- shadow dims are now hardcoded via `SHADOW_DIMENSIONS` set (R2 fix), so SKILL.md is not read during migration.

Guard: if `'dimension_states' in config`: return immediately (already migrated).

Step 0: If `'keyword_dictionaries' not in config`: set `config['keyword_dictionaries'] = dict(SEED_KEYWORD_DICTIONARIES)` (deep copy via dict()).

Step 1: Use module-level constant `SHADOW_DIMENSIONS` (defined at top of migration.py alongside DIMENSION_RENAME_MAP and SEED_KEYWORD_DICTIONARIES): `SHADOW_DIMENSIONS = {'doc_completeness', 'change_scope'}` (from SKILL.md lines 468-473). Do NOT attempt to parse SKILL.md display names -- the mapping is fragile and unnecessary since the shadow set is small and stable.

Step 2: Rename dimensions in findings.json BEFORE step 3. For each finding in `findings_data.get('findings', [])`: if `finding.get('dimension', '')` is in `DIMENSION_RENAME_MAP`: replace with canonical name. Already-canonical names are untouched (idempotent).

Step 3: Create dimension_states from keyword_dictionaries keys. For each dim in `config['keyword_dictionaries']`:
   - Count findings with this canonical dimension name (from step 2 renamed data)
   - Determine status: if dim in shadow_dims -> "shadow", else "active"
   - Set `now = datetime.now(timezone.utc).isoformat()`
   - Create entry: `{"status": status, "last_seen": now, "finding_count": count, "added_at": now if status == "shadow" else None, "consecutive_eval_failures": None, "seed_test_status": None}`
   - Store in `config['dimension_states'][dim]`

Step 4: Override from promoted_dimensions. First, apply DIMENSION_RENAME_MAP to promoted_dimensions list (same rename as step 2, so legacy names like "state_management" become "concurrency" before lookup). Then for each dim in the renamed list: if dim in `config['dimension_states']`: set status to "active". If dim NOT in `config['dimension_states']` (promoted but no keywords yet -- edge case from manual config edits): create a minimal entry with status="active", finding_count=0, last_seen=now, added_at=None, consecutive_eval_failures=None, seed_test_status=None, and add an empty keyword list to keyword_dictionaries.

Step 5: Delete promoted_dimensions: `config.pop('promoted_dimensions', None)`.

Return nothing -- config and findings_data are mutated in place. The caller is responsible for atomic_write.

Define `ensure_dimension_state(config, dim)`:
Implements the fallback rule from CONTEXT.md: if dim is in keyword_dictionaries but missing from dimension_states, auto-create entry. Status depends on whether dim is a permanent shadow dimension: `status = "shadow" if dim in SHADOW_DIMENSIONS else "active"`. Other fields: finding_count=0, last_seen=current timestamp, added_at=None, consecutive_eval_failures=None, seed_test_status=None. Returns the entry (existing or newly created).

Define `run_migration_if_needed(config_path, findings_path)`:
Convenience function that loads config and findings, calls `migrate_to_dimension_states(config, findings_data)` if needed, and writes both files back via atomic_write imported from forge_cli (lazy import inside this function to avoid circular imports). Prints status message: "forge: migrated to dimension_states ({N} dimensions)" or "forge: dimension_states already present, skipping migration".
