### Motivating gap (user-named, PM-confirmed)

The reviewer's knowledge is a time-smeared world average (training
corpus) plus docs-latest (context7); the build environment is a
version-pinned specific reality. Today forge speaks with uniform
confidence across that gap and never discloses which world a finding
was reasoned against. The flaw is not weak generality -- all code is
specific to an environment -- it is UNDECLARED specificity. Same shape
as the fleet's map-vs-territory axiom, recursed into the review layer:
doc-grounded review and environment ground truth are orthogonal.

### Governing decision: three authorities of a fix (constitution)

1. DIAGNOSE (find + verify findings): forge owns fully.
2. PROPOSE (draft fix + evidence): forge may EARN per-finding -- a
   proposal ships only with fail-before/pass-after evidence produced
   in the declared environment (Phase 53a). DELIVERY IS DEFINED as
   emitting a patch ARTIFACT -- a unified diff attached to the
   receipt / SARIF output or written under forge's own artifact
   directory -- plus its evidence bundle; never applied state.
   Internally, attempting a fix is encouraged as a false-positive
   filter (fix-as-evidence); emitting one is gated
   (fix-as-delivery).
3. APPLY (mutate the caller's tree / accept): the CALLER, always.
   Rationale: a fix is a claim about counterfactual code, and only
   the intent owner can accept it (AI-correction-is-a-claim; the
   flywheel _truncate catch-and-fix was legitimate precisely because
   forge owned that intent). LLM callers rubber-stamp diffs, so their
   acceptance MUST be run-based (re-execute the evidence bundle),
   never read-based.

Binding constraint, effective immediately: the AutoFixer interface is
already live in the machine (machine.py:36, factories.py:17,
outlet_c.py:15) with StubAutoFixer as the implementation. No phase may
swap in a delivering AutoFixer before Phase 53a's evidence machinery
exists, and no forge surface (CLI/MCP/hook) may ever write to the
reviewed tree's CODE -- "reviewed tree" excludes forge's own artifact
directory (.code-forge/), where state.json / receipts / ledger writes
are normal operation. Component split: the 53a execution organ only
RUNS code and produces evidence, never drafts fixes; a delivering
AutoFixer (post-53a, if ever) drafts proposals and consumes the organ
for evidence -- two components, one-way dependency. Violation of
authority 3 is a review-blocker, not a style issue.

### Phase 51 BASIS-DISCLOSE (small; prereq 43; no prompt change)

Every emitted finding carries an epistemic basis, surfaced in receipts
and SARIF: deterministic-executed | llm-trained | llm-docs-latest |
llm-docs-pinned (the last only meaningful after 52). Basis is derived
MECHANICALLY from pass provenance (deterministic axes -> executed; LLM
axes -> trained, or docs-latest when a docs pack was injected) --
never model-self-reported; a model asked for its own authority
confabulates. Report layer refuses basis-less findings (hook, not
hope). Composes with 42: claim_type = WHAT is claimed, basis = ON WHAT
AUTHORITY; two orthogonal columns on the same finding. Two mechanical
sub-fields preserve the gradient the enum alone would lose:
falsification_survived (bool) and convergence_rounds (int) -- both
already computed by the pipeline, no new judgment. Expected
distribution is honestly lopsided: most findings will read
llm-trained until 52/53a land; that uniformity is the true state,
not disclosure theater -- the tag's discriminating value grows as
pinned-docs and executed evidence become available.
Acceptance: bug-inject -- strip basis from one finding at the seam ->
report layer rejects (RED) -> restore -> GREEN. One real review run
shows the basis distribution in the delivery briefing.
