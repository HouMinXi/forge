## Goal

Emit SARIF 2.1.0 to stdout in CI mode + one-line summary to stderr. Pure
data transformation: read final State (post state-machine) + tool_versions
+ forge version -> build SARIF log dict -> json.dumps. CI integrators
(GitHub Actions, GitLab CI) parse SARIF for PR comment generation; forge
does NOT generate PR comments directly.

Scope: output formatting ONLY. No new state machinery, no changes to
02-01..02-05 state schema or behavior. State.py NOT extended (avoids
Pattern A cascade per 4-sub-plan pattern data).

## Requirements (1 plan req + 5 integration responsibilities)

- **LAYER0-07**: SARIF 2.1.0 stdout emission in CI mode. Level mapping
  CONFIRMED -> `error`, UNCERTAIN -> `warning`, DISMISSED -> emitted
  with `suppressions[{kind: "external"}]`, FIXED -> emitted with
  `suppressions[{kind: "inSource"}]` + fix commit ref. `tool.driver.semanticVersion`
  populated with forge version + L0 tool versions. Stderr one-line
  summary matching regex
  `^forge: (PASS|FAIL|ESCALATED) findings=\d+ confirmed=\d+ uncertain=\d+ dismissed=\d+ fixed=\d+$`.
- **Integration responsibility 1 (CI-only emission)**: emission happens
  ONLY when `mode == Mode.CI`. LOCAL mode does NOT emit SARIF (state.json
  is the canonical artifact for LOCAL). Wire point: cli.py `_run()`
  after `_run_hold_loop` returns terminal verdict, before main() maps to
  exit code.
- **Integration responsibility 2 (tool_versions sourcing)**: re-call
  `capture_tool_version(tool_config.command)` per registry entry at
  SARIF build time. Cheap (each tool runs `--version` only; no scan).
  Avoids touching 02-02 StateMachine constructor + avoids state.py
  schema extension.
- **Integration responsibility 3 (fix commit ref for FIXED findings)**:
  v2.0 ships StubAutoFixer which does NOT actually commit fixes; FIXED
  findings in v2.0 have no real commit. SARIF emits `suppressions[{kind:
  "inSource"}]` with `properties.fix_commit = null` placeholder; Phase 4
  real autofixer will populate. Document as v2.0 limitation.
- **Integration responsibility 4 (PENDING / non-terminal handling)**:
  CI never returns PENDING (no HOLD in CI per GATE-01b). The defensive
  flow when GATE-01b is violated (caller bug):
  (a) `_run_hold_loop` returns PENDING in CI mode
  (b) `_emit_ci_output` reached (CI branch unconditional after _run_hold_loop)
  (c) `build_sarif_log` raises ValueError with "GATE-01b" in message
  (d) cli.main()'s existing exception handler catches, returns exit 1
  (e) NO SARIF emitted on stdout (raise fires BEFORE print)
  Note: main() does NOT have an early PENDING guard before _run; the
  PENDING-as-EXIT_PASS mapping in 02-05 main() applies ONLY to LOCAL
  mode (HOLD-pause semantics). CI mode PENDING is a hard error.
- **Integration responsibility 5 (anchor / evidence_files passthrough)**:
  StateFinding.anchor (optional dict) and evidence_files (optional list)
  surface as SARIF `properties.anchor` and `properties.evidence_files`
  respectively. Absent (None) -> field omitted entirely (NOT emitted as
  null) to keep SARIF output compact.

### `src/forge/sarif.py`

```python
# SPDX-License-Identifier: AGPL-3.0-or-later
"""LAYER0-07: SARIF 2.1.0 emission for CI mode.

Pure data transformation: State + tool_versions -> SARIF log dict.
Caller (cli.py CI path) handles I/O.
"""
from __future__ import annotations

from typing import Any, Optional   # R4 B1: Optional used by _suppressions_for

from .disposition import Disposition
from .state import State, StateFinding, Verdict


SARIF_VERSION = "2.1.0"
SARIF_SCHEMA_URI = "https://json.schemastore.org/sarif-2.1.0.json"


# Disposition -> SARIF level. DISMISSED + FIXED use "note" (lowest severity)
# because they are emitted-but-suppressed per LAYER0-07; the suppressions
# array does the actual non-blocking signaling.
DISPOSITION_TO_LEVEL: dict[Disposition, str] = {
    Disposition.CONFIRMED: "error",
    Disposition.UNCERTAIN: "warning",
    Disposition.DISMISSED: "note",
    Disposition.FIXED: "note",
}


# Disposition -> suppressions array. CONFIRMED + UNCERTAIN have no
# suppressions (raw, blocking-relevant signal). DISMISSED + FIXED carry
# kind=external + kind=inSource respectively per LAYER0-07.
# R3 M4: explicit dispatch on all 4 known states + ValueError default.
# Silent None on unknown disposition (e.g., enum gained 5th state) would
# emit wrong SARIF; loud raise surfaces the issue at deploy time.
def _suppressions_for(disposition: Disposition) -> Optional[list[dict[str, Any]]]:
    """Return suppressions array or None to omit."""
    if disposition in (Disposition.CONFIRMED, Disposition.UNCERTAIN):
        return None   # no suppressions key
    if disposition == Disposition.DISMISSED:
        return [{"kind": "external"}]
    if disposition == Disposition.FIXED:
        return [{
            "kind": "inSource",
            "properties": {"fix_commit": None},   # v2.0 placeholder
        }]
    raise ValueError(
        "unknown Disposition %r; sarif.py mapping table needs update"
        % disposition
    )


def build_sarif_log(
    state: State,
    tool_versions: dict[str, str],
    forge_version: str,
) -> dict[str, Any]:   # R2b L7: dict[str, Any] used consistently throughout module
    """Build SARIF 2.1.0 log dict.

    Raises:
        ValueError: state.verdict is PENDING. CI never PENDINGs (no HOLD
            in CI per GATE-01b); reaching this is a caller bug.
    """
    if state.verdict == Verdict.PENDING:
        raise ValueError(
            "build_sarif_log called with PENDING verdict; CI mode does "
            "not enter HOLD (GATE-01b). Caller bug."
        )
    return {
        "$schema": SARIF_SCHEMA_URI,
        "version": SARIF_VERSION,
        "runs": [_build_run(state, tool_versions, forge_version)],
    }


def _build_run(
    state: State,
    tool_versions: dict[str, str],
    forge_version: str,
) -> dict[str, Any]:
    """Build SARIF run dict.

    R1 H2: `tool.driver.rules` is intentionally NOT populated in v2.0.
    Rationale: v2.0 fingerprints are sha256(tool:file:line:rule_id)[:16]
    placeholders (Phase 3 replaces with semantic_hash). Generating rule
    definitions from opaque hashes adds JSON noise without integrator
    value. Integrators that need rule[] can construct from results;
    v2.x adds rules[] when fingerprint generation evolves (Phase 3).
    Documented as known v2.0 limitation in Out of Scope.
    """
    return {
        "tool": {
            "driver": {
                "name": "forge",
                "semanticVersion": _build_semantic_version(
                    forge_version, tool_versions
                ),
                "informationUri": "https://github.com/HouMinXi/forge",
                # R1 H2: rules[] omitted in v2.0 (see docstring).
            },
        },
        "results": [_finding_to_result(f) for f in state.findings],
    }


def _build_semantic_version(
    forge_version: str,
    tool_versions: dict[str, str],
) -> str:
    """LAYER0-07: 'forge <version> [<tool>=<ver> ...]' for reproducibility.

    Sorted tool list -> deterministic output for byte-equality testing.

    R1 L3 constraint: tool names MUST be alphanumeric + dash/underscore
    (matches Phase 1 registry.py validation regex). Names containing
    `=` or `]` would corrupt the format string -- pre-validated upstream
    by registry loader; this builder trusts the input.
    """
    tools_str = " ".join(
        "%s=%s" % (t, v) for t, v in sorted(tool_versions.items())
    )
    if tools_str:
        return "forge %s [%s]" % (forge_version, tools_str)
    return "forge %s []" % forge_version


def _finding_to_result(finding: StateFinding) -> dict[str, Any]:
    """Convert StateFinding -> SARIF result dict."""
    result: dict[str, Any] = {
        "ruleId": finding.fingerprint,
        "level": DISPOSITION_TO_LEVEL[finding.disposition],
        "message": {"text": finding.description},
        "locations": [_build_location(finding)],
    }
    suppressions = _suppressions_for(finding.disposition)
    if suppressions is not None:
        result["suppressions"] = suppressions
    # R2b L3: properties always non-empty (source field always present).
    # Drop the `if properties` guard -- it was dead code.
    result["properties"] = _build_properties(finding)
    return result


def _build_location(finding: StateFinding) -> dict[str, Any]:
    """Build SARIF physicalLocation.

    R1 H1 fix: bounds-check line_range. Production line_range is always
    a 2-element list (02-02 _default_l0_runner sets [f.line, f.end_line];
    snapshot reload preserves list[int]). Defensive guard handles
    malformed state.json (corrupted file, partial write, future schema
    change): empty -> startLine=1 endLine=1; single-element -> endLine
    mirrors startLine.
    """
    # R2b L1: line_range >2 elements -> first/second used; extras silently
    # ignored. line_range is conventionally exactly 2; >2 indicates
    # upstream schema drift (not a v2.0 supported case).
    line_range = finding.line_range
    if not line_range:
        start = end = 1
    elif len(line_range) == 1:
        start = end = line_range[0]
    else:
        start = line_range[0]
        end = line_range[1]
    return {
        "physicalLocation": {
            "artifactLocation": {"uri": finding.file},
            "region": {
                "startLine": start,
                "endLine": end,
            },
        },
    }


def _build_properties(finding: StateFinding) -> dict[str, Any]:
    """Optional fields (anchor, evidence_files, error) -> properties dict.

    Absent fields are OMITTED, not emitted as null. Keeps SARIF compact
    for integrators that pretty-print.
    """
    props: dict[str, Any] = {}
    if finding.anchor is not None:
        props["anchor"] = finding.anchor
    if finding.evidence_files is not None:
        props["evidence_files"] = finding.evidence_files
    if finding.error is not None:
        props["error"] = finding.error
    props["source"] = finding.source   # always present (L0 or L1)
    return props


def format_summary(state: State) -> str:
    """One-line stderr summary per LAYER0-07.

    Format matches regex:
      ^forge: (PASS|FAIL|ESCALATED) findings=\\d+ confirmed=\\d+
      uncertain=\\d+ dismissed=\\d+ fixed=\\d+$

    Verdict.PENDING is rejected (CI never PENDINGs; caller guards).
    """
    if state.verdict == Verdict.PENDING:
        raise ValueError(
            "format_summary called with PENDING verdict; CI mode does "
            "not enter HOLD (GATE-01b). Caller bug."
        )
    counts = {
        Disposition.CONFIRMED: 0,
        Disposition.UNCERTAIN: 0,
        Disposition.DISMISSED: 0,
        Disposition.FIXED: 0,
    }
    for f in state.findings:
        # R1 M1 fix: direct access (counts pre-initialized with all 4 enum
        # values). KeyError on unknown disposition is the CORRECT failure
        # mode -- signals that Disposition enum gained a 5th state and
        # counts dict needs updating (better than silent drop via .get()).
        counts[f.disposition] += 1
    total = len(state.findings)
    return (
        "forge: %s findings=%d confirmed=%d uncertain=%d "
        "dismissed=%d fixed=%d" % (
            state.verdict.value, total,
            counts[Disposition.CONFIRMED],
            counts[Disposition.UNCERTAIN],
            counts[Disposition.DISMISSED],
            counts[Disposition.FIXED],
        )
    )
```

def _run(args, env, cwd: Path) -> Verdict:
    # ... existing 02-05 pipeline through Step 7 ...
    with ForgeLock(lock_path):
        verdict = _run_hold_loop(...)
        # R1 B2 + R2b L6: emission INSIDE lock scope, AFTER terminal verdict.
        # Rationale: emission is fast (<10ms typical) so holding lock costs
        # nothing; release-then-emit would allow concurrent forge to acquire
        # and emit before our SARIF reaches stdout (small race window
        # observable in CI scripts piping output).

            _emit_ci_output(state_path, registry)

def _emit_ci_output(
    state_path: Path,
    registry: dict[str, "ToolConfig"],   # R1 M4 typed + R2b M1: no cwd param
    post_emit_hook: Optional[Callable[[], None]] = None,  # R2b M3 test seam
) -> None:
    """LAYER0-07: SARIF stdout + summary stderr in CI mode.

    Re-loads state from disk for canonical view (catches any save_state
    divergence). Re-captures tool_versions per Integration 2 (avoids
    02-02 StateMachine constructor surface change).

    R2b M1: cwd parameter removed (was unused; state_path is absolute).
    R2b M2: load_state returns None -> silent return (no log warning).
      Rationale: SARIF is best-effort output, NOT canonical artifact;
      state.json is canonical. Silent return matches "skip SARIF when
      state absent" semantics. Risk table aligned.
    """
    final_state = load_state(state_path)
    if final_state is None:
        return  # R2b M2: silent; state.json is canonical, SARIF best-effort
    tool_versions = {
        name: capture_tool_version(tc.command)
        for name, tc in registry.items()
    }
    log_dict = build_sarif_log(
        final_state, tool_versions, forge_version=__version__
    )
    print(json.dumps(log_dict), file=sys.stdout)
    print(format_summary(final_state), file=sys.stderr)
    # R2b M3: test seam -- caller can probe lock state mid-emission.
    # R3 B1: duplicate send block deleted (was copy-paste artifact from R2b L6).
    if post_emit_hook is not None:
        post_emit_hook()

## Success Criteria

2. **LAYER0-07 tool.driver.name**: `runs[0].tool.driver.name == "forge"`
3. **LAYER0-07 semanticVersion**: matches `"forge <ver> [<tool>=<ver> ...]"` with sorted tool list; empty tool_versions -> `"forge <ver> []"`
4. **LAYER0-07 disposition -> level mapping**: CONFIRMED -> "error"; UNCERTAIN -> "warning"; DISMISSED + FIXED -> "note"
5. **LAYER0-07 suppressions**: CONFIRMED + UNCERTAIN have NO suppressions key; DISMISSED -> `[{"kind": "external"}]`; FIXED -> `[{"kind": "inSource", "properties": {"fix_commit": null}}]`

## Risks & Mitigations

| Risk | Severity | Mitigation |
|------|----------|------------|
| **Pattern A: StateFinding shape assumption mismatch** | High | Task 2 explicit audit; all fields read are listed; if state.py changes between commits, re-grep before commit |
| **SARIF 2.1.0 schema drift between Microsoft revisions** | High | hardcode SARIF_VERSION = "2.1.0" constant; document in module docstring; if Microsoft publishes 2.2.0, treat as v2.x candidate (not auto-upgrade) |
| **capture_tool_version slow / fails for some tools** | Medium | re-call is per-tool (typically <10 tools); each calls --version (millisecond-scale); on failure (tool removed mid-run), capture returns empty string -- semanticVersion still emitted as "forge <ver> [tool=]" which is degraded but not crash |
| **load_state returns None at emission unexpected** | Medium | SC-17 defensive: silent return without error (best-effort SARIF; state.json is canonical). State machine SHOULD have persisted at round end (02-02 _persist_state at end of _execute_round). If absence happens, it's a 02-02 product bug, not 02-06 concern. R5 L-1: aligned with R2b M2 / SC-17 / docstring (no log warning). |
| **stdout pollution (json.dumps with default=str fails on non-serializable)** | Medium | StateFinding fields are all JSON-serializable primitives + list[int] + Optional[dict]; no datetime / Path / Decimal that need custom encoder; explicit test (b)+(p) covers full shape |
| **json.dumps key ordering changes across Python versions** | Low | Python 3.7+ guarantees dict insertion order; SARIF readers don't care about key order; SC-19 deterministic byte output relies on insertion order which is platform-stable |
| **Verdict.PENDING reached at emission (caller bug)** | Low | SC-12 defensive ValueError; main()'s existing exception handler catches and returns exit 1 (R4 B2: no pre-_run PENDING guard; defensive raise is sole mechanism). |
| **Disposition enum extension in future (5th state)** | Low | DISPOSITION_TO_LEVEL is dict; new state would KeyError in _finding_to_result; explicit (not silent) failure; v2.x mapping addition is single-line |
| **CI exit code coupling with SARIF emission** | Low | exit code is computed by main() AFTER _run returns; SARIF emission is side-effect during _run; if json.dumps raises, exception propagates to R3-L2 catch in main() -> exit 1 with traceback (acceptable: SARIF generation bug surfaces as CI failure) |
| **Large state.findings (1000s) -> slow json.dumps + huge stdout** | Low | v2.0 expected scale: <100 findings per PR; if real workload pushes higher, streaming SARIF (json.JSONEncoder + iterencode) is v2.x optimization |
| **fix_commit null placeholder confuses SARIF parsers expecting commit SHA** | Low | SARIF spec allows null for properties values; integrators that error on null can be addressed by filtering FIXED suppressions client-side; v2.0 documented limitation |

## Reviewer Focus (when 02-06-PLAN goes to gsd-review)

- **Disposition -> SARIF level decision**: DISMISSED + FIXED use level=note (lowest severity) + suppression. Alternative: level=none. Chose "note" because SARIF spec says results array entries with level=none are "no severity" (informational only); we want them VISIBLE (per LAYER0-07 "visible but not blocking") so "note" is the proper level. Verify against SARIF spec section 3.27.10.
- **Suppression schema completeness**: SARIF 2.1.0 suppression objects can include `state` (accepted/underReview/rejected), `justification`, `kind`. v2.0 ships kind only. Verify integrators (GitHub Code Scanning) accept minimal kind-only form.
- **PENDING defensive vs silent return**: chose ValueError because PENDING in CI is a guaranteed caller bug (CI never HOLDs per GATE-01b); silent skip would mask the bug. Alternative: log warning + skip.
- **tool_versions re-capture vs threading**: re-capture is cheap (--version flag per tool); threading from 02-02 would require constructor change (Pattern A risk). Re-capture chosen.
- **state reload vs in-memory**: reload from disk catches any save/load divergence and ensures canonical view. Costs one file read. Acceptable for CI mode (one-shot).
- **JSON schema validation as test gate**: Task 12 is OPTIONAL. Should it be MANDATORY? Trade-off: dev-dep `jsonschema` adds 1 import vs schema-validation-by-hand. Recommend OPTIONAL for v2.0 (manual verification on representative samples); MANDATORY in v2.x once we have CI dogfooding.
- **fix_commit null vs omitted**: chose null because the field semantically exists for FIXED findings (just unpopulated in v2.0). Omitting would suggest the field never applies; null suggests "applies but unknown". Phase 4 will populate.
- **informationUri hardcoded URL**: hardcoded to repo URL. Alternative: configurable via env. Recommend hardcode for v2.0 (single project); make configurable in v2.x if forks need it.

## Open Questions

1. **forge_version source**: pulled from `forge.__version__`. Should we also include git commit SHA (build-time vs runtime)? v2.0 = pyproject version only. v2.x candidate to add `__commit__` injected at build time.

2. **anchor schema**: StateFinding.anchor is `Optional[dict]` -- shape undefined in 02-01. 02-06 passes it through verbatim. Risk: SARIF parsers may not understand custom anchor schema. Acceptable for v2.0 (anchor is forge-internal forensic data; integrators ignore unknown properties).

3. **`runs[0]` vs multiple runs**: single run aggregating all tools chosen. Alternative: per-tool runs[]. Single run is simpler; integrators expecting one-run-per-tool would need to adapt. v2.x candidate.

4. **stderr summary on PASS**: should PASS emit summary? Currently YES (per regex spec). Some CI users may consider no-output-on-PASS a feature. Counter-argument: integrators may want to know PASS was reached vs forge silent-fail. Recommend: always emit (current).

5. **(R1 B2 RESOLVED) CI emission on ForgeLock release order**: emission happens INSIDE ForgeLock context (still holding lock). R1 caught pseudocode-vs-text contradiction (text said inside, pseudocode showed outside); pseudocode corrected. Alternative: emit AFTER release. Current (inside) is fine since emission is fast; outside would allow concurrent forge invocations to acquire while we emit (acceptable but adds tiny race window). v2.0 = inside; reconsider only if emission becomes slow.

6. **JSON pretty-print vs compact**: `json.dumps(log_dict)` produces compact output. SARIF integrators expect compact; humans reading raw SARIF may want pretty. v2.0 = compact (matches integrator expectation); v2.x could add `--pretty-sarif` flag.
