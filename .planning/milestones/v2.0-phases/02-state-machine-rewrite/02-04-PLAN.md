  env: Mapping[str, str], stdout_isatty: bool) -> Mode`. Pure function;

- **STATE-08**: Intra-round ordering -- L0 detect runs first, L0 autofix
  loop completes, ONLY THEN L1 detect runs against post-fix code. 02-02
  shipped a single `_execute_round` that does L0+L1 detect inline; 02-04
  refactors to split L0 phase from L1 phase so L1 sees post-fix code.
  Refactor is internal to `_execute_round`; constructor surface unchanged.
- **STATE-09**: CI fresh-start -- CI mode MUST NOT load any prior
  state.json (would silently inherit human-DISMISSED findings into shared
  CI runs). Implementation: pre-`StateMachine.run()` guard. If
  `mode == Mode.CI` AND `.forge/state.json` exists, log
  "ignoring prior state.json in CI mode" and skip the load. LOCAL mode
  load behavior unchanged (uses 02-01 `load_state` if file present).
- **STATE-11**: File lock -- `.forge/forge.lock` contains holder PID.
  Acquire via `O_CREAT|O_EXCL`. On EEXIST: read PID, `kill -0 <pid>`
  to test liveness; alive -> log + exit 3 (BUSY); dead -> log "removing
  stale lock from dead PID N" + retry acquire. Released on clean exit
  AND on SIGINT/SIGTERM. SIGKILL leaves stale lock cleaned on next run.
- **HOLD-resume UX** (deferred from 02-02 R1 B5 + R2-3): when state machine
  returns `Verdict.PENDING` (HOLD entered), 02-04 provides `run_hold_ui()`
  that prints each UNCERTAIN finding, prompts for `c|d|s` (confirm /
  dismiss / skip), records dispositions into state.json, returns control
  to caller to re-invoke StateMachine. CLI integration is 02-05's job;
  the UX function is here.
- **ESCALATED-frozen predicate** (deferred from 02-02 DISPO-05(c) /
  R2-3): after HOLD resume, when StateMachine starts the next round, if
  ANY finding has `disposition == CONFIRMED AND fix_attempts[fp] >= MAX`
  AND was previously promoted (tracked via new field, see below), exit
  ESCALATED immediately. Do not wait for MAX_TOTAL_ROUNDS exhaustion.
- **`hold_reason` State field + `promoted_fingerprints` set** (deferred

  additive fields in `State`:

      fingerprints that hit MAX_FIX_ATTEMPTS and got promoted CONFIRMED

```python
# SPDX-License-Identifier: AGPL-3.0-or-later
"""STATE-06 mode resolution.

Pure precedence function: CLI flag > FORGE_MODE env > TTY default.
"""
from __future__ import annotations

from typing import Mapping, Optional

from .state import Mode


VALID_MODE_STRINGS = {"local": Mode.LOCAL, "ci": Mode.CI}


def resolve_mode(
    cli_arg: Optional[str],
    env: Mapping[str, str],
    stdout_isatty: bool,
) -> Mode:
    """Resolve effective Mode given inputs.

    Precedence (highest first):
      1. cli_arg if not None (CLI --mode flag value)
      2. env["FORGE_MODE"] if present
      3. default: Mode.LOCAL if stdout_isatty else Mode.CI

    String values are case-insensitive ("local", "Local", "LOCAL" all OK).
    Invalid string (anywhere) raises ValueError with the offending value.

    Args:
      cli_arg: value from argparse --mode (None if not provided)
      env: os.environ or test-injected mapping
      stdout_isatty: result of sys.stdout.isatty() at process start

    Returns:
      Mode.LOCAL or Mode.CI

    Raises:
      ValueError: cli_arg or env value not in {"local", "ci"} (case-insensitive)
    """
    if cli_arg is not None:
        return _parse_mode_string(cli_arg, source="--mode")
    env_value = env.get("FORGE_MODE")
    # M3 + L1 fix: empty string ("") is treated as "not set" (fall through
    # to TTY default). Whitespace-only ("  ") is NOT treated as empty --
    # it reaches _parse_mode_string, gets stripped to "", fails the lookup,
    # raises ValueError. Rationale: empty env var is a common shell idiom
    # for "unset"; whitespace-only is a likely user typo and deserves loud
    # failure rather than silent fall-through.
    if env_value is not None and env_value != "":
        return _parse_mode_string(env_value, source="FORGE_MODE env")
    return Mode.LOCAL if stdout_isatty else Mode.CI


def _parse_mode_string(value: str, source: str) -> Mode:
    """Lower + lookup; raise with source attribution on miss."""
    key = value.strip().lower()
    if key not in VALID_MODE_STRINGS:
        raise ValueError(
            "invalid mode %r from %s (expected: local|ci)" % (value, source)
        )
    return VALID_MODE_STRINGS[key]
```

```python
# SPDX-License-Identifier: AGPL-3.0-or-later
"""STATE-11 file lock with PID liveness probing.

Race-safe atomic acquire via O_CREAT|O_EXCL. Stale-PID recovery via
os.kill(pid, 0) liveness check.
"""
from __future__ import annotations

import os
import signal
from pathlib import Path
from types import TracebackType
from typing import Optional, Type


class ForgeLockBusy(Exception):
    """Raised when another live forge process holds the lock.

    .pid attribute carries the holder PID for caller logging.
    """

    def __init__(self, pid: int, path: Path):
        self.pid = pid
        self.path = path
        super().__init__(
            "another forge process is running (PID %d, lock %s)"
            % (pid, path)
        )


class ForgeLock:
    """Context manager + explicit release().

    Usage:
      with ForgeLock(Path(".forge/forge.lock")) as lock:
          ... do forge work ...
      # released on normal exit OR on exception in body OR on SIGINT/SIGTERM.
    """

    def __init__(self, path: Path):
        self.path = path
        self._held = False
        self._original_sigint = None
        self._original_sigterm = None

    def __enter__(self) -> "ForgeLock":
        acquire_lock(self.path)
        self._held = True
        self._install_signal_handlers()
        return self

    def __exit__(
        self,
        exc_type: Optional[Type[BaseException]],
        exc: Optional[BaseException],
        tb: Optional[TracebackType],
    ) -> None:
        self.release()

    def release(self) -> None:
        if self._held and self.path.exists():
            # Defensive: only remove if PID matches ours (prevents
            # accidental removal of a different process's lock).
            try:
                stored = int(self.path.read_text().strip())
                if stored == os.getpid():
                    self.path.unlink()
            except (ValueError, FileNotFoundError):
                pass
            self._held = False
        self._restore_signal_handlers()

    def _install_signal_handlers(self) -> None:
        """R1 B1 fix: save + chain previous handler.

        signal.signal() is process-wide. Naively overwriting clobbers any
        handler installed by CLI (02-05), test harness, or user code.
        Correct behavior: save the prior handler; in our handler do our
        cleanup, then dispatch to the prior handler so its semantics are
        preserved (SIG_DFL -> default action; SIG_IGN -> ignore; callable
        -> invoke).
        """
        def _make_chained_handler(prev):
            def _handler(signum, frame):
                # Step 1: best-effort release (never raise from handler body).
                try:
                    self.release()
                except Exception:  # noqa: BLE001 (handler must not propagate)
                    pass
                # Step 2: chain to previous handler so caller semantics survive.
                if callable(prev):
                    prev(signum, frame)
                    return
                if prev == signal.SIG_IGN:
                    return
                # R3-12 fix: SIG_DFL or None -> raise KeyboardInterrupt
                # uniformly for BOTH SIGINT and SIGTERM, so caller's
                # try/finally (e.g., HOLD state persistence) executes.
                # Python has no default Python-level handler for SIGTERM;
                # without our intercept the process would terminate
                # without cleanup. Uniform KeyboardInterrupt simplifies
                # caller error handling.
                raise KeyboardInterrupt
            return _handler
        prev_sigint = signal.getsignal(signal.SIGINT)
        prev_sigterm = signal.getsignal(signal.SIGTERM)
        self._original_sigint = prev_sigint
        self._original_sigterm = prev_sigterm
        signal.signal(signal.SIGINT, _make_chained_handler(prev_sigint))
        signal.signal(signal.SIGTERM, _make_chained_handler(prev_sigterm))

    def _restore_signal_handlers(self) -> None:
        if self._original_sigint is not None:
            signal.signal(signal.SIGINT, self._original_sigint)
            self._original_sigint = None
        if self._original_sigterm is not None:
            signal.signal(signal.SIGTERM, self._original_sigterm)
            self._original_sigterm = None


def acquire_lock(path: Path) -> None:
    """Acquire `path` exclusively. Recovers from stale PID locks.

    Algorithm:
      1. Try O_CREAT|O_EXCL create. Write own PID. Done if success.
      2. On FileExistsError: read PID from existing lock file.
      3. If file unreadable / PID not int: treat as stale, remove + retry.
      4. If PID readable: probe `os.kill(pid, 0)`:
         - OSError ESRCH (no such process): stale, remove + retry.
         - OSError EPERM (process exists but we lack signal perm):
           treat as alive (conservative; cross-user same-host scenario).
         - No exception: process alive -> raise ForgeLockBusy(pid, path).
      5. Single retry (after stale removal). Second EEXIST raises
         ForgeLockBusy with PID=-1 (race condition: someone else
         re-acquired between our remove and our retry).

    Raises:
      ForgeLockBusy: another live forge holds the lock.
      OSError: filesystem error (parent dir missing, EACCES, etc).
    """
    path.parent.mkdir(parents=True, exist_ok=True)
    for attempt in range(2):
        try:
            fd = os.open(
                str(path),
                os.O_CREAT | os.O_EXCL | os.O_WRONLY,
                0o644,
            )
            try:
                os.write(fd, ("%d\n" % os.getpid()).encode("ascii"))
            finally:
                os.close(fd)
            return
        except FileExistsError:
            if attempt == 1:
                raise ForgeLockBusy(-1, path)
            _handle_existing_lock(path)
        except IsADirectoryError:
            # R1 H6 fix: path resolved to a directory (typo or stale
            # .forge/forge.lock/ subdirectory). Raise a typed OSError
            # so the caller surfaces a clear message instead of crashing
            # mid-acquire with an obscure FileExistsError path.
            raise OSError(
                "lock path %s is a directory, not a file (remove it manually)"
                % path
            )


def _handle_existing_lock(path: Path) -> None:
    """Read PID; check liveness; remove if dead. Raises ForgeLockBusy if alive."""
    try:
        pid = int(path.read_text().strip())
    except (ValueError, FileNotFoundError):
        # Unreadable -> treat as stale.
        try:
            path.unlink()
        except FileNotFoundError:
            pass
        return
    try:
        os.kill(pid, 0)
        # No exception = process alive
        raise ForgeLockBusy(pid, path)
    except ProcessLookupError:
        # ESRCH: stale
        try:
            path.unlink()
        except FileNotFoundError:
            pass
    except PermissionError:
        # EPERM: conservatively treat as alive
        raise ForgeLockBusy(pid, path)
```

```python
# R1 H2 fix: canonical signature. All references in plan, tasks, tests

def run_hold_ui(
    state: State,
    state_path: Path,

    output_fn: Callable[[str], None] = print,

    """Prompt human for each UNCERTAIN finding.

    For each finding with disposition == UNCERTAIN:
      - Print summary (id, file:line, description).
      - Prompt: "[c]onfirm / [d]ismiss / [s]kip / [q]uit: "
      - "c" -> set disposition CONFIRMED
      - "d" -> set disposition DISMISSED
      - "s" -> leave UNCERTAIN, move on
      - "q" -> raise HoldAborted (M6 fix: explicit quit option)
      - invalid -> reprompt (no penalty)
      - EOF -> raise HoldAborted (M7 fix: same exception class as "q";
        message is generic, not stdin-specific)

    After loop: clear state.hold_reason, rebuild dispositions cache,
    persist via save_state.

    Idempotent: if zero UNCERTAIN findings, returns immediately with
    no I/O (caller may invoke unconditionally after PENDING return).

    R1 H5 fix: dispositions cache rebuild uses `f.id` (NOT
    `f.fingerprint`), matching 02-02 product convention at state.py:178.
    Invariant: for L0 findings, `id == fingerprint` (set by adapter); for
    L1 findings, `id` is the unique entry identifier while `fingerprint`
    is the FP-04 dedup key. `dispositions` is keyed by `id`;
    `fix_attempts` and `promoted_fingerprints` are keyed by `fingerprint`.
    """
    uncertain = [
        f for f in state.findings if f.disposition == Disposition.UNCERTAIN
    ]
    if not uncertain:
        state.hold_reason = None
        save_state(state, state_path)
        return

    output_fn(
        "HOLD: %d UNCERTAIN finding(s) need human disposition."
        % len(uncertain)
    )
    for finding in uncertain:
        _prompt_one(finding, input_fn, output_fn)

    state.hold_reason = None
    # H5 fix: key by f.id (matches 02-02 state.py:178 convention).
    state.dispositions = {f.id: f.disposition for f in state.findings}
    save_state(state, state_path)


def _prompt_one(
    finding: StateFinding,
    input_fn: Callable[[str], str],
    output_fn: Callable[[str], None],
) -> None:
    """Inner per-finding prompt loop (reprompts on invalid input)."""
    output_fn(
        "  [%s] %s:%d-%d  %s"
        % (
            finding.id,
            finding.file,
            finding.line_range[0],
            finding.line_range[1],
            finding.description,
        )
    )
    while True:
        try:
            choice = input_fn(
                "    [c]onfirm / [d]ismiss / [s]kip / [q]uit: "
            ).strip().lower()
        except EOFError:
            raise HoldAborted("HOLD UX aborted by user")  # M7 generic msg
        if choice in QUIT_INPUTS:
            raise HoldAborted("HOLD UX aborted by user")  # M6 explicit quit
        if choice == "s":
            return  # leave UNCERTAIN
        if choice in VALID_INPUTS:
            finding.disposition = VALID_INPUTS[choice]
            return
        output_fn("    (invalid input %r; expected c/d/s/q)" % choice)


def check_escalated_frozen(state: State) -> bool:
    """DISPO-05(c) predicate: re-CONFIRM of promoted finding -> ESCALATED.

    R1 H4 guard: returns True ONLY when state has been through HOLD
    resume at least once. Mechanism: HOLD entry sets state.hold_reason
    to a non-None string; run_hold_ui clears it back to None on completion.
    Therefore "promoted_fingerprints non-empty AND hold_reason is None"
    means "promotion happened AND HOLD UI subsequently completed". This
    avoids any theoretical race where the predicate could fire mid-promotion
    BEFORE HOLD entry (would be wrong because the finding's flip from
    CONFIRMED -> UNCERTAIN + promoted_fingerprints.add() must be observed
    together; H4 belt-and-suspenders prevents the read-tear hypothesis).

    Returns True iff ALL of:
      - state.hold_reason is None (we are NOT currently in HOLD entry)
      - state.promoted_fingerprints is non-empty (at least one promotion
        happened in this or a prior session)
      - AT LEAST ONE finding has:
          * disposition == Disposition.CONFIRMED
          * fingerprint in state.promoted_fingerprints
          * state.fix_attempts.get(fingerprint, 0) >= MAX_FIX_ATTEMPTS_PER_FINGERPRINT

    Reason: a finding in promoted_fingerprints has already exhausted its
    fix budget AND been promoted to UNCERTAIN once. If after HOLD UX it
    is back to CONFIRMED, the human deliberately accepted it as a real
    defect that auto-fix cannot resolve. Continuing the loop would just
    burn rounds; exit ESCALATED now (per DISPO-05 spec line 47).
    """
    if state.hold_reason is not None:
        return False
    if not state.promoted_fingerprints:
        return False
    for finding in state.findings:
        if (
            finding.disposition == Disposition.CONFIRMED
            and finding.fingerprint in state.promoted_fingerprints
            and state.fix_attempts.get(finding.fingerprint, 0)
            >= MAX_FIX_ATTEMPTS_PER_FINGERPRINT
        ):
            return True
    return False
```

## Reviewer Focus (when 02-04-PLAN goes to gsd-review)

- **STATE-08 refactor correctness**: does splitting _execute_round really preserve all 02-02 test invariants? Trace fix_attempts increment path through the new flow.
- **STATE-09 guard placement** (R2-L9 resolved): SETTLED at `run()` entry, NOT `__post_init__`. `run()` keeps construction cheap (allows test fixture creation without state.json side effects). `__post_init__` alternative is dropped from active design.
- **ESCALATED-frozen single round-trip**: predicate fires on next round AFTER HOLD resume. Should it fire BEFORE the round runs (avoid wasted L0 call) or AFTER (consistent with normal flow)? Chosen: BEFORE (at iteration top).
- **promoted_fingerprints vs fix_attempts as marker**: could we use `fix_attempts >= MAX` alone? No -- a first-time CONFIRMED that just hit MAX is the promotion event itself, not a re-confirm. Need an explicit "has been promoted before" marker.
- **HOLD UX function signature**: input_fn / output_fn injection vs. global stdin/stdout monkeypatching for tests? Chosen injection: explicit, no global state, robust to parallel pytest.
- **lock signal handler vs. atexit**: signal handler chosen because atexit runs only on normal interpreter shutdown; SIGTERM / SIGINT need explicit handler to release before re-raise.
- **EPERM as alive**: cross-user same-host lock conflict shows as BUSY rather than silent takeover. Trade-off: same-user-different-uid (e.g. docker user) sees spurious BUSY. Acceptable for v2.0 (single-user dev tool primary use case).

## Open Questions

1. **HOLD UX persistence on partial completion** -- if human starts disposing findings then hits EOF mid-way, do we persist partial dispositions before raising HoldAborted? Current design: NO (atomicity preserved). Alternative: persist on every input. Recommend NO for v2.0 (one-shot atomic UX); reconsider if user feedback shows lost progress is painful.

2. **Lock holder PID format** -- `"<pid>\n"` ASCII vs. JSON `{"pid": N, "started_at": "..."}`. Plain int is simpler and shell-greppable. JSON allows future extension (held_by_user, started_at). Recommend plain int for v2.0; document migration path in lock.py header for future telemetry.

3. **(RESOLVED inline by R1 H4 fix)** ESCALATED-frozen verdict text -- now includes up to 3 fingerprints with "..." suffix when more (see machine.py extension code above). State.json bloat bounded; debugging signal preserved.

4. **(RESOLVED by D1-CORRECTION + R5-2)** STATE-08 CI mode L1 invocation -- premise was wrong. CI MUST invoke L1 per LAYER0-07 (SARIF includes L1 candidates). Original alternative "skip L1 in CI" is REJECTED. Final design: `_run_l1_phase` called in both modes; CI distinguishes only by skipping autofix loop (STATE-03). Question closed.

5. **`mode_resolver.resolve_mode` arg order** -- (cli_arg, env, isatty) matches precedence order. Alternative: keyword-only for clarity at call sites. Recommend positional (small fn, 3 args fits).

6. **(D2-CORRECTED, opened by R5 implementation)** DISMISSED disposition persistence across L0 re-detect: human DISMISSes a finding via HOLD UI, exits forge, re-invokes. 02-02 `_apply_promotion_stickiness` only preserves UNCERTAIN (DISPO-05 sticky path); L0 re-detect of the same fingerprint will produce a fresh CONFIRMED, bypassing the human's DISMISSED decision. This is a UX gap but NOT a v2.0 spec violation (no REQUIREMENTS line mandates DISMISSED stickiness across L0 re-detect). Candidate resolutions:
   (a) Extend `_apply_promotion_stickiness` to also preserve DISMISSED (mirrors UNCERTAIN sticky logic); breaks symmetry of "DISMISSED is human-only choice" semantic.
   (b) Add a separate "dismissed_fingerprints: set[str]" in State (like promoted_fingerprints but for DISMISSED); cross-session UX persistence with explicit data structure.
   (c) Document as known v2.0 limitation; v2.x ships sticky DISMISSED via mechanism (a) or (b) after telemetry shows pain.
   **Recommend (c) for v2.0**. Track as v2.x candidate; do NOT scope into 02-04 or 02-05.
