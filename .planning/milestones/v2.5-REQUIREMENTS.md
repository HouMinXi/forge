# Requirements: Forge

**Defined:** 2026-06-15
**Milestone:** v2.5 Releasable + Cross-Repo
**Core Value:** No code ships without surviving three consecutive clean review
cycles; a green verdict is honest or declares what it did not verify.
**Spine:** forge becomes externally adoptable and can review a logical change
spanning multiple repos as one joint unit.

## Founding Principle

The three-cycle pre-commit pipeline is the sole gate. Advisory axes surface
context but never block. A green verdict claims what it verified and declares
what it did not.

## Active Requirements (v2.5)

### Config Legibility (Phase 24)

- [ ] **CONFIG-01**: A user or LLM can fill gate.yaml correctly without reading
  source code, because every field self-documents its type, default, and valid
  values via inline comments and a gate.schema.json schema directive.
- [ ] **CONFIG-02**: A corpus round-trip test validates that gate.schema.json
  and the real loader agree on every covered case (valid/invalid snippets
  each judged by both); loader-only constraints are listed in $comment and
  tested against the loader separately.

### Cross-Repo Merge Review (Phase 25)

- [ ] **CROSS-01**: A single logical change that physically spans >=2 repos is
  reviewed as one joint unit -- both diffs appear in a single review context
  and the verdict reflects both. The single-repo path is unchanged.

### Cross-Repo Contract Context (Phase 26)

- [ ] **CROSS-02**: When reviewing repo B, an opt-in recipe pulls repo A's
  contract/spec (e.g. kernel YNL spec) into reviewer context as a read-only
  reference. Repo A is not reviewed. A missing spec yields a graceful empty
  digest, never an error.

### Cross-Repo Impact via register (Phase 27)

- [ ] **CROSS-03**: A change to repo A's interface surfaces impacted call sites
  in repo B, computed over a cross-repo graph (code-review-graph register),
  as an ADVISORY finding. Absent register/db degrades gracefully to SKIP
  (never crash, never silent pass).
