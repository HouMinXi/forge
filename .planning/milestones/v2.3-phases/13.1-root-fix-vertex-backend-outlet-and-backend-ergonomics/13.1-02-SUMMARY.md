# Phase 13.1 Plan 02: Vertex Stage A -- CLI Backend Probe Bypass Summary

**One-liner:** `probe_backend` returns `ProbeResult(ok=True)` immediately for any named cli backend, enabling Vertex AI via `claude -p` subprocess without requiring `claude auth status` to succeed.

## What Was Built

Modified `probe_backend` in `src/code_forge/backend.py` to bypass the reachability probe for explicitly-configured cli backends. The bypass fires after the cache check and before the type-dispatch block:

```python
if backend.type == "cli" and backend.name != "session-default":
    return ProbeResult(ok=True)
```

This allows users to configure a Vertex AI backend in `gate.yaml` as `type: cli` with Vertex env vars (`CLAUDE_CODE_USE_VERTEX`, `ANTHROPIC_VERTEX_PROJECT_ID`, `CLOUD_ML_REGION`, `GOOGLE_APPLICATION_CREDENTIALS`). The `_invoke_cli` subprocess inherits `os.environ`, so the env vars pass through without any invocation change.

Also updated `probe_backend` docstring to document the bypass behavior, and added `TestProbeBypass` class to `tests/test_backend.py` with three tests covering all three paths.

## Decisions Made

- **Bypass placement:** After cache read, before type dispatch. Cache hits still short-circuit before reaching the bypass.
- **Bypass key:** `backend.name != "session-default"` reuses an existing invariant without adding a new `BackendConfig` field.
- **No cache write on bypass:** Returns immediately at O(1) cost; no file I/O needed.
- **Joint commit for tasks 1+2:** Separating would leave `BackendConfig` imported but unused between commits.
