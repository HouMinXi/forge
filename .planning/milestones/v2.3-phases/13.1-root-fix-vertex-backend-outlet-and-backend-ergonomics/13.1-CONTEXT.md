# Phase 13.1: root-fix -- vertex backend + outlet and backend ergonomics - Context

**Gathered:** 2026-06-05
**Status:** Ready for planning

<domain>
## Phase Boundary

Fix two design debts exposed when forge was run in a real consumer worktree:
(1) zero-config execution silently falls through to `claude -p` subprocess,
causing 120s timeout + 0-token billing trap; (2) backend auth model only
supports static env-var keys, blocking Vertex AI (GCP OAuth) and future
Bedrock (SigV4). Additionally resolve the outlet/backend naming collision
that confused even Opus 4.6 reading the source.

Two commit waves in one phase:
- **Wave 1** (zero breaking): fail-fast default, Vertex stage A (cli+env),
  `code-forge init` subcommand
- **Wave 2** (breaking, separate commits): outlet naming refactor with
  deprecated aliases, Vertex stage B (native api format)

</domain>

<decisions>
## Implementation Decisions

### W1-a: FAIL-FAST default (zero-config)
- **D-01:** When `configs==[]` (no gate.yaml backend, no --backend) AND no
  --outlet/FORGE_OUTLET: do NOT probe DEFAULT_BACKEND. Raise CliError listing
  three explicit configuration outlets:
  (1) gate.yaml backends (persistent; see `code-forge init`)
  (2) --backend-url/-format/-key-env/-model (one-off)
  (3) FORGE_OUTLET=inline (review in THIS session; uses main quota)
  State that implicit `claude -p` is disabled: it nests a subprocess and
  bills the main account.
- **D-02:** Explicitly configured cli backend (user deliberately wants
  `claude -p`) remains fully supported. Only the IMPLICIT zero-config
  fallthrough is blocked.
- **D-03:** LOCKED invariant (outlet_resolver.py:13-18) gains a new clause:
  "No implicit claude -p fallthrough: when no backend is explicitly configured
  and no FORGE_OUTLET is set, CLI refuses to probe and raises CliError with
  configuration guidance." The existing "backend unreachable -> CliError"
  clause is preserved as the second guard.

### W1-b: Vertex stage A (cli + env injection)
- **D-04:** Vertex stage A uses type:cli backend in gate.yaml with Vertex env
  vars injected at runtime (CLAUDE_CODE_USE_VERTEX=true,
  ANTHROPIC_VERTEX_PROJECT_ID, CLOUD_ML_REGION,
  GOOGLE_APPLICATION_CREDENTIALS). _invoke_cli already inherits os.environ.
- **D-05:** Explicitly configured cli backend bypasses probe (trust
  configured). probe_backend continues to inherit os.environ for any probe
  that does run (confirmed: _probe_cli does not strip env).
- **D-06:** Deliverable: documentation + one gate.yaml cli example with
  Vertex env vars + probe bypass confirmation.

### W1-c: code-forge init subcommand
- **D-07:** `code-forge init` generates a gate.yaml template containing:
  CN api backends (Phase 13 five-backend set), a commented Vertex cli backend
  example, test: placeholder, and outlet explainer comments.

### W2-a: Outlet naming refactor (BREAKING)
- **D-08:** Rename outlet value "cli" to "subprocess". inline and subagent
  unchanged.
- **D-09:** Old value "cli" accepted as deprecated alias with stderr warning.
  No hard rejection. PyPI already published (code-review-forge 2.0.0a1) --
  hard break hits existing users.
- **D-10:** Update sites: VALID_OUTLET_STRINGS (outlet_resolver.py:40),
  dispatch (cli.py:644-649), --outlet choices (cli.py:233), docstring/invariant
  block, SKILL.md, all docs, all tests. Add regression tests asserting old
  values still resolve with deprecation warning.

### W2-b: Vertex stage B (native api format)
- **D-11:** VALID_API_FORMATS += "vertex". Implement _invoke_vertex in
  llm_invoke.py. New BackendConfig fields: project_id, region, credentials
  path.
- **D-12:** google-auth is an OPTIONAL dependency: pyproject.toml `[vertex]`
  extra. `pip install code-review-forge[vertex]`. Without it, vertex format
  is unavailable but other functionality is unaffected.
- **D-13:** Wire code reference: WebFetch official Vertex AI Claude docs
  during research/plan phase. Do NOT hand-write rawPredict from memory.
  Verify: endpoint URL shape, anthropic_version in body, model-id naming
  on Vertex, express mode (API key without OAuth) availability.
- **D-14:** Return real usage/token counts from Vertex response so the api
  path has actual cost data (vs cli path's 0 per D-07 cost tracking).

### Claude's Discretion
- Error message wording for the W1-a CliError (content decided, exact prose
  is implementer's call)
- `code-forge init` YAML template formatting and comment style
- Internal naming of _invoke_vertex helper functions

</decisions>
