<objective>
W1-a: Fail-fast default for zero-config execution.

Purpose: When a user runs `code-forge review` with no gate.yaml, no --backend flags, and no FORGE_OUTLET, the current code silently probes DEFAULT_BACKEND (the session-default `claude -p` subprocess), which causes a 120s timeout and bills the main account. This plan adds a guard that raises CliError with actionable guidance listing three configuration outlets.

Output: Modified outlet_resolver.py with zero-config guard, updated cli.py to pass configs context, new tests.
</objective>

    1. Add a new parameter `configs` (type: list, default []) to the resolve_outlet signature. This carries the loaded BackendConfig list from cli.py so resolve_outlet knows whether any backends are configured.

    2. Add a new parameter `has_explicit_backend` (type: bool, default False) to indicate that the caller assembled an inline backend via --backend-url/format/key-env/model flags.

    3. BEFORE the existing "Step 3: backend reachability" block (before line 174), insert a zero-config guard:
       - Condition: `configs` is empty AND `has_explicit_backend` is False AND we reached this point (meaning cli_value was None/empty, FORGE_OUTLET was unset, and gate.yaml had no outlet field).
       - Action: raise CliError with this message:
         "No review backend configured. Choose one:\n"
         "  1. gate.yaml backends (persistent): create .code-forge/gate.yaml\n"
         "  2. --backend-url/--backend-format/--backend-key-env/--backend-model (one-off)\n"
         "  3. FORGE_OUTLET=inline (review in THIS session; uses main quota)\n"
         "Implicit `claude -p` is disabled: it nests a subprocess and bills the main account."

    4. Per D-02, if configs is NOT empty (user deliberately configured a backend in gate.yaml), the guard does not fire and the existing reachability probe runs as before.

    5. Update the module-level docstring (lines 4-21) to add the new LOCKED invariant clause per D-03. After the existing "Backend unreachable with no explicit override raises CliError" bullet, add:
       "  - No implicit claude -p fallthrough: when no backend is explicitly\n"
       "    configured and no FORGE_OUTLET is set, CLI refuses to probe and\n"
       "    raises CliError with configuration guidance."

    6. In cli.py, hoist `cfgs = _load_gate_backends(gate_yaml_path)` out of the _reachability closure to just before the resolve_outlet call (around line 630). Then update the resolve_outlet call at line 638 to pass configs=cfgs and has_explicit_backend=(has_inline or bool(args.backend)). This covers both --backend-url/format/key-env/model (inline) AND --backend <name> (named selection). Update the _reachability closure to use the already-loaded cfgs variable.

    7. In outlet_resolver.py, update the default reachability_fn (line 158-161) to thread `configs` through to resolve_backend: `backend = resolve_backend(env, configs=configs, cli_value=None)`. Currently it hardcodes `configs=[]`, which means the actual probe resolves against empty configs even when configs is non-empty. This is a latent API inconsistency -- cli.py always provides a custom reachability_fn, but the default should be correct for any caller.
