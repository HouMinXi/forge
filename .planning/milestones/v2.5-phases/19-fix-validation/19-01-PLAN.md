    - classify_fixval_candidate(changed_files: list[str]) returns FixvalCandidate(test_files, non_test_files) when BOTH test and non-test files present; returns FixvalSkip(reason) when only one kind or neither
    - Test file detection uses patterns: tests/test_*.py, *_test.py, test_*.py, *.test.ts, *.spec.ts, *_test.go (per RESEARCH.md D-07)
    - parse_fixval_waiver(commit_message: str, env: dict | None = None) returns the reason string if waiver is present via either channel, else None. Dual-channel waiver (HIGH-2 fix):
      Channel 1: FIXVAL_WAIVER env var (primary at pre-commit time, because the commit message is not yet finalized when pre-commit runs). Example: `FIXVAL_WAIVER="flaky network test" git commit -m "fix: ..."`
      Channel 2: "Fixval-Waiver:" trailer in commit_message (works at commit-msg stage, post-commit, or CI). Case-insensitive key match, value is the rest of the line stripped.
      Either channel triggers a waiver. Empty reason (whitespace-only after strip) returns None from both channels (D-04: reason required).
    - run_fixval(candidate, test_cmd, cwd, commit_message, diff_text) returns FixvalResult with status PASS/BLOCK/SKIPPED/WAIVED plus findings list plus advisories list:
      a. If diff_text is None -> status=SKIPPED with reason "non-git review, no diff available" (guard for non-git modes where ResolvedReview.git_diff is None)
      b. Check waiver via parse_fixval_waiver(commit_message, env=os.environ). If waiver reason found (from FIXVAL_WAIVER env var OR Fixval-Waiver trailer) -> status=WAIVED, one AdvisoryFinding recording the waiver reason and channel used. Empty reason returns None (D-04: reason required).
      c. Baseline guard: construct run_env = os.environ.copy() with PYTHONPATH=os.path.join(str(cwd), "src"). Call mutation._run_baseline_guard(scoped_cmd, run_env, str(cwd), allow_strip_retry=True) where scoped_cmd = test_cmd + candidate.test_files (same scoped command used for the revert test, to prove the scoped command is valid). Handle all 3 return statuses: "passed" -> continue, "skip" -> SKIPPED, "needs_strip_retry" -> strip VIRTUAL_ENV from run_env, add PYTHONPATH, retry with allow_strip_retry=False (matching mutation.py:326-331 pattern).
      d. Revert: derive revert patch from diff_text (the SAME diff used by classify -- guarantees source agreement, fixes MED-3 staged-vs-unstaged mismatch). Parse diff_text with unidiff.PatchSet, filter to non-test files only (skip files matching TEST_PATTERNS), serialize back via str(filtered_patchset), write to temp file. If non-test patch is empty -> status=SKIPPED("no non-test changes to revert"). Apply `git apply -R <tempfile>` to revert. If apply fails -> status=SKIPPED("revert patch failed"). Use try/finally: revert in try block, restore via `git apply <tempfile>` (forward re-apply) in finally block.
      e. Run scoped_cmd (test_cmd + candidate.test_files) via subprocess.run with timeout from gate.yaml test config (same pattern as _run_baseline_guard / _run_l2_phase; default 600s). If any test FAILs -> status=PASS (test is not hollow). If all PASS -> status=BLOCK (hollow test detected). TimeoutExpired -> status=SKIPPED with reason.
      f. Restore: always runs in finally block via `git apply <tempfile>` (forward re-apply of the same patch used for revert). This is safe for both staged-only and mixed staged+unstaged scenarios. Never use `git checkout --` (destroys unstaged work).
    - FixvalResult dataclass has: status (FixvalStatus), findings (list[StateFinding]), advisories (list[AdvisoryFinding]), block_message (str). The findings field is populated by the status-specific logic above; machine.py reads result.findings directly. CRITICAL: BLOCK -> one DISMISSED StateFinding with source="FIXVAL", fingerprint="fixval-hollow", id="FIXVAL_HOLLOW" (DISMISSED, NOT CONFIRMED -- the actual block is via Verdict.FAIL set by machine.py; using CONFIRMED would prevent re-convergence on subsequent runs because _fixpoint_reached checks for CONFIRMED findings). PASS -> empty findings. SKIPPED -> one DISMISSED with id="FIXVAL_SKIPPED". WAIVED -> one DISMISSED + advisory in advisories list.
    - run_overfit_guard(candidate, test_cmd, cwd) returns list[AdvisoryFinding]. Applies a variable-rename transform to the first .py file in non_test_files (Python only -- skip non-.py files with empty list return). Save the ORIGINAL file bytes before any transform. Uses ast.parse + ast.NodeTransformer to rename a local variable (append _renamed suffix). Writes transformed code via ast.unparse (Python 3.9+). Validates transform via ast.parse before writing. Runs test in try/finally: finally block ALWAYS restores original bytes verbatim (never re-unparse to restore -- ast.unparse is lossy, strips comments/formatting). If test breaks after rename -> advisory "test may be overfitting to variable names". If test still passes -> empty list. Advisory only (D-03), never a StateFinding.

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| diff input | Unified diff text from git; could contain adversarial file paths |
| commit message | User-supplied text; waiver trailer is parsed from it |
| subprocess (git apply, test cmd) | Shell execution with user-controlled paths |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-19-01 | Tampering | git apply -R (revert) | mitigate | Always restore via forward `git apply <saved-patch>` in finally block; `git checkout --` would destroy unstaged work |
| T-19-02 | Spoofing | Fixval-Waiver trailer | accept | Waiver is visible in git log and review output; abuse is attribution, not prevention |
| T-19-03 | Tampering | subprocess test cmd | mitigate | test_cmd comes from gate.yaml (already trust-gated by Phase 17 SEC-01); no shell=True |
| T-19-SC | Tampering | npm/pip/cargo installs | mitigate | No new packages installed; all imports are from existing forge codebase |
</threat_model>
