    Implementation approach:
    - If diff_text is None or empty, return []
    - Parse diff headers to extract file paths: regex r'^diff --git a/(?:.*?) b/(.+)$' captures
      only the part AFTER 'b/' (stripping the b/ prefix). Example: 'diff --git a/gate.yaml b/gate.yaml'
      captures 'gate.yaml', NOT 'b/gate.yaml'. Skip segments before the first valid diff --git header.
    - Split diff into per-file sections at "diff --git" boundaries
    - Filter to sections where path == "gate.yaml" or path starts with ".code-forge/"
    - For matching sections, parse @@ hunk headers to extract new-file start line:
      regex r'@@ -\d+(?:,\d+)? \+(\d+)(?:,\d+)? @@' captures new_start
    - Initialize line_number = new_start at each hunk header
    - For context lines (no prefix or space prefix) and + lines, increment line_number
    - For - lines, do NOT increment (they are old-file lines)
    - Process lines IN THE LOOP (not collected then matched afterward -- line_number must be
      captured at the point each line is encountered, not after the loop ends):
      For each line in the hunk:
        - If line starts with "+" (but not "+++"): this is a new-line
          1. Strip the leading '+' (diff syntax, not file content)
          2. Regex-match the stripped content against DANGER_PATTERN
          3. If match: construct StateFinding with current line_number
          4. Increment line_number
        - If line starts with "-": skip (old-file line, do NOT increment line_number)
        - If line starts with "@@": parse hunk header, reset line_number to new_start (do NOT increment)
        - If line starts with "\\": skip ("\ No newline at end of file" metadata, do NOT increment)
        - Otherwise (context line, starts with " " or no prefix): increment line_number
    - DANGER_PATTERN: re.compile(r'^\s*(' + '|'.join(re.escape(f) for f in DANGEROUS_FIELDS) + r')\s*:')
    - Import DANGEROUS_FIELDS from .trust (do NOT redefine)
    - Design note (D-15 deviation): D-15 says "output formatted as SARIF, parsed by
      existing parse_semgrep / _parse_sarif". danger_score_from_diff constructs
      StateFinding directly instead of SARIF round-trip because it parses diff text
      (not semgrep output). The SARIF path applies to the taint sub-capability
      (which actually invokes semgrep). This deviation is intentional and avoids
      constructing synthetic SARIF JSON only to immediately destructure it.
    - Construct StateFinding per match:
      - id = fingerprint = f"danger-score:{file_path}:{field_name}:{line_number}"
      - source = "L0"
      - disposition = Disposition.CONFIRMED
      - file = file_path
      - line_range = [line_number, line_number]
      - description = f"Dangerous config field '{field_name}' added to {file_path}"

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| diff input -> danger-score | Diff text comes from git or user; parsed for config field names |
| semgrep subprocess | External tool invocation; output parsed as SARIF JSON |
| source_files -> semgrep | File paths passed to external process |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-18-01 | Tampering | danger-score diff parsing | mitigate | Only scan files matching gate.yaml or .code-forge/* path prefix; regex anchored to line start |
| T-18-02 | Spoofing | semgrep SARIF output | accept | Semgrep runs locally; output trusted as local tool output |
| T-18-03 | Information Disclosure | semgrep stderr | mitigate | stderr captured by subprocess.run, not forwarded to user beyond D-06 message; error messages truncated to 200 chars |
| T-18-04 | Denial of Service | semgrep timeout | mitigate | subprocess.run timeout=120s prevents hang; TimeoutExpired caught and recorded as infra_error |
| T-18-SC | Tampering | pip install semgrep | accept | semgrep is a well-known package (>10M downloads); not installed by forge, user-managed |
</threat_model>
