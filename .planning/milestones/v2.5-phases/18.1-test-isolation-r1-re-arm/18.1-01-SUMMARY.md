# Plan 18.1-01 Summary: Test Suite Git Isolation + Regression Guard

## What was built

Hardened the forge test suite against real-repo .git pollution caused by
git subprocess calls escaping tmp_path isolation in test_install_hooks.py.

1. **Session-scoped GIT_CEILING_DIRECTORIES fixture** (`tests/conftest.py`):
   - Autouse session fixture sets `GIT_CEILING_DIRECTORIES` to the real repo root
   - Blocks all child subprocess `git` commands from walking up past tmp_path
   - Uses `Path(__file__).resolve().parent.parent` (no subprocess for repo root)
   - Restores original env var value on teardown

2. **Per-test monkeypatch ceiling** (`tests/test_install_hooks.py`):
   - `monkeypatch.setenv("GIT_CEILING_DIRECTORIES", str(tmp_path.parent), prepend=os.pathsep)`
   - Added to all 18 tmp_path-using test methods in test_install_hooks.py
   - Appends to session fixture ceiling (does not overwrite)
   - Pure unit tests (TestHookAttestation, TestResolveForgeLiveness) unchanged

3. **Regression guard** (`tests/conftest.py`):
   - `pytest_sessionstart`: snapshots `.git/config`, `.git/hooks/` contents (with sha256
     hashes), `refs/heads/`, `HEAD`, and repo-root dotfiles
   - `pytest_sessionfinish`: re-captures and diffs; any drift triggers
     `sys.stderr.write(diagnostic_diff) + sys.exit(1)` (not `pytest.fail()` -- pytest
     swallows messages raised in sessionfinish via the inner exception handler)
   - Resolves `.git` via `git rev-parse --absolute-git-dir` (worktree-safe)
   - Uses `session.config.stash[pytest.StashKey[dict]()]` (pytest 7+ API)

## SC 1 Evidence (pollution confirmed)

Scratch clone `/tmp/forge-repro-$$` confirmed that running `pytest tests/test_install_hooks.py`
without isolation wrote `core.hooksPath` and `user.name`/`user.email` into the real
repo's `.git/config`. Code path: `resolve_hooks_dir` -> `git rev-parse --show-toplevel`
with `cwd=tmp_path` (no .git) -> git walked up to real `.git` -> wrote config.
`GIT_CEILING_DIRECTORIES` blocks this walk at the repo root.
