# Phase 18.1: Test Isolation + R1 Re-arm - Context

**Gathered:** 2026-06-11

<domain>
## Phase Boundary

Fix the test suite pollution that writes to the real repo's .git (core.hooksPath,
user identity, stub hooks, fixture commits on live branches). Then re-arm the R1
pre-commit gate with a non-code carve-out so docs/config commits don't deadlock.

Scope: test infrastructure isolation, regression guard, pre-commit hook carve-out,
and R1 re-arming. No new review axes or pipeline features.

</domain>

<decisions>
## Implementation Decisions

### Test isolation mechanism
- **D-01:** Two-layer isolation. Primary: `GIT_CEILING_DIRECTORIES` env var set
  to the real repo root via a session-scoped autouse fixture in `conftest.py`.
  This prevents git from walking up the directory tree when a subprocess runs in
  `tmp_path`. Secondary: monkeypatch of subprocess calls as a belt-and-suspenders
  backup for any code path that bypasses the env var.
- **D-02:** `test_install_hooks.py` tests get explicit per-test
  `monkeypatch.setenv('GIT_CEILING_DIRECTORIES', ...)` calls rather than relying
  solely on the conftest fixture. More verbose but makes the isolation contract
  visible in each test.

### Regression guard
- **D-03:** Implement as a pytest plugin (not a conftest fixture). Uses
  `pytest_sessionstart` / `pytest_sessionfinish` hooks to snapshot and compare
  `.git` state.
- **D-04:** Guard checks ALL of: `.git/config` (config drift), `.git/hooks/`
  directory contents (stub hook injection), `refs/heads/` branch refs (fixture
  commits on live branches), `HEAD` pointer (unexpected commit), and any other
  dotfiles under `.git/` that change.
- **D-05:** On drift detection, the plugin calls `pytest.fail()` with a diagnostic
  diff showing exactly what changed (before vs after snapshot). Loud failure, not
  a warning.

### Pre-commit non-code carve-out
- **D-06:** The generated pre-commit hook checks staged file suffixes via
  `git diff --cached --name-only`. If ALL staged files are non-code, skip
  `code-forge verify --quiet` and `code-forge gate-check`.
- **D-07:** Code file extensions (trigger verify): `.py`, `.sh`, `.bash`, `.js`,
  `.ts`, `.jsx`, `.tsx`, `.go`, `.rs`, `.c`, `.h`, `.rb`, `.java`. Any staged file
  matching these suffixes forces the full verify+gate-check pipeline.
- **D-08:** Non-code = everything NOT in the code extensions list. This is a
  positive match on code (safer default: unknown extensions trigger verify).

### R1 re-arming
- **D-09:** Hard ordering enforced: isolation fix (D-01/D-02) and regression
  guard (D-03/D-04/D-05) land BEFORE hook arming. The armed hook runs the full
  test suite on every code commit -- the suite must be safe first.
- **D-10:** R1 end-to-end: `code-forge install-hooks` succeeds, a code commit
  triggers the suite and blocks on a NEW failure, and the `.planning` pre-push
  guard stays live. Verified by integration test.

### Claude's Discretion
- Plugin registration mechanism (entry_points vs conftest import vs pytest_plugins)
- Snapshot format (hash-based vs file-list-based comparison)
- Whether the regression guard plugin lives under `tests/` or `src/code_forge/`

</decisions>

## Existing Code Insights

### Reusable Assets
- `GIT_CEILING_DIRECTORIES` is a native git env var -- no code needed in git itself
- `seed_tests/run_seed_tests.py` pattern: `git -c user.email=... commit` avoids
  persistent config writes entirely
- `conftest.py` already exists in `tests/` -- add fixtures there

### Established Patterns
- All test files creating git repos use `tmp_path` fixture + `subprocess.run(cwd=tmp_path)`
- Production functions accept `cwd: Optional[Path]` for testability
- `install_hooks.py` uses dependency injection for `run_cmd` parameter

### Integration Points
- `conftest.py` session fixtures affect all test files -- single point of change
- Pre-commit hook template is generated by `install_hooks.py:_hook_content()`
- The hook runs `code-forge verify --quiet && exec code-forge gate-check`

</code_context>
