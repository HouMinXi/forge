## 1. Root Cause Analysis

### Pollution vectors identified

**11 test files** run `subprocess.run(["git", "config", ...], cwd=...)` to set
`user.name`, `user.email`, or `core.hooksPath`. All pass `cwd=tmp_path` or
`cwd=repo` (a subdirectory of `tmp_path`).

**The leak mechanism:** If `git init` in `tmp_path` fails silently, or if a test
runs a git command BEFORE `git init`, git walks up the directory tree from
`tmp_path` to find the nearest `.git`. Since `tmp_path` is under the pytest
process's working directory (which is the forge repo), git finds the REAL repo's
`.git` and writes config there.

**Prime suspect:** `tests/test_install_hooks.py` line 294:
```python
subprocess.run(["git", "config", "core.hooksPath", "/custom/hooks"], cwd=tmp_path)
```
This is AFTER `git init` on line 288, so it should be safe. But if `git init`
fails (e.g., permission issue on CI), the `check=True` would raise -- however
the test catches no exception before the config write.

**Secondary vectors:**
- `tests/test_baseline.py:29-33` -- `git config user.email/name` with `cwd=tmp_path`
- `tests/test_cli_phase1_compat.py` -- 3 test methods, same pattern
- `tests/test_cli_integration.py`, `test_integration.py`, `test_pseudo_refs.py`,
  `test_cli_lock.py`, `test_baseline_integration.py` -- all same pattern

**Safe pattern already in use:**
- `tests/seed_tests/run_seed_tests.py:254` -- `git -c user.email=... commit`
  (per-command flags, no persistent config write)
- `tests/test_eval_corpus.py:163` -- same `-c` flag pattern

### Production code cwd patterns

`src/code_forge/install_hooks.py:228`: `cwd = Path.cwd()` as fallback when
`cwd=None`. Tests always pass explicit `cwd=tmp_path`, but any code path that
omits `cwd` would use the real working directory.

`resolve_hooks_dir()` line 63: `git rev-parse --show-toplevel` with `cwd=str(cwd)`.
If `cwd` is inside the real repo (not its own git root), this returns the REAL
repo root, and hooks are written to the REAL `.git/hooks/`.

`cli.py:853-900`: All CLI entry points use `Path.cwd()` -- safe in production
(user is in their repo) but dangerous in tests if any test changes working
directory without restoring it.

### Existing conftest.py

```python
# tests/conftest.py (entire file)

def _skip_worktree_check(monkeypatch):
    monkeypatch.setenv("FORGE_SKIP_WORKTREE_CHECK", "1")
```

Zero git isolation. This is the root cause.

## 2. GIT_CEILING_DIRECTORIES Behavior

`GIT_CEILING_DIRECTORIES` is a colon-separated list of absolute paths. Git will
not walk above any listed directory when searching for `.git`. Setting it to the
real repo root prevents any subprocess in `tmp_path` from discovering the real
`.git` if `tmp_path` doesn't have its own.

**Key behaviors:**
- Applies to ALL git commands (config, rev-parse, init, etc.)
- Does NOT affect `git init` (init creates a new `.git`, doesn't search upward)
- Does NOT affect commands that explicitly pass `--git-dir=`
- Multiple paths separated by `:` (or `;` on Windows)
- Must be absolute paths

**Interaction with test fixtures:**
- `tmp_path` is under `/tmp/pytest-xxx/` which is OUTSIDE the repo tree
- `subprocess.run(cwd=tmp_path)` sets child process cwd
- BUT the pytest PROCESS itself runs from the repo root
- Any git command without explicit `cwd` (e.g., from `Path.cwd()` fallback) hits
  the real `.git`
- Setting `GIT_CEILING_DIRECTORIES` in the pytest process env propagates to ALL
  child processes via `subprocess.run` (unless env is explicitly overridden)

**Best practice:** Set ceiling to the repo root itself. This blocks upward
traversal through the repo boundary for any subprocess that inherits the env.

## 3. Pytest Plugin Implementation

### Plugin hooks

- `pytest_sessionstart(session)` -- called after collection, before test execution.
  Snapshot `.git` state here.
- `pytest_sessionfinish(session, exitstatus)` -- called after all tests complete.
  Compare snapshot. Modify `exitstatus` if drift detected.

### Snapshot strategy

Hybrid approach:
- `.git/config`: `git config --list --local` output (portable across git versions)
- `.git/hooks/`: directory listing with file hashes
- `refs/heads/`: `git for-each-ref refs/heads/ --format='%(refname) %(objectname)'`
- `HEAD`: `git rev-parse HEAD`

### Registration options

**conftest.py inline** -- define `pytest_sessionstart`/`finish` directly in
conftest.py. Simplest, project-specific, no packaging overhead. Recommended
for forge's own test suite (not a general-purpose plugin).

### Diagnostic output

On drift, produce a clear before/after diff showing exactly which `.git/` state
changed:
```
FATAL: Test suite modified real .git state!
Changed: .git/config
  - [no core.hooksPath]
  + core.hooksPath = /custom/hooks
Changed: .git/hooks/
  + pre-commit (new file)
```

## 4. Pre-commit Hook Non-code Carve-out

### Shell implementation sketch

```sh
CODE_EXTS='\.py$|\.sh$|\.bash$|\.js$|\.ts$|\.jsx$|\.tsx$|\.go$|\.rs$|\.c$|\.h$|\.rb$|\.java$'
HAS_CODE=$(git diff --cached --name-only | grep -E "$CODE_EXTS")
if [ -z "$HAS_CODE" ]; then
    echo "code-forge: skipping verify (non-code commit)" >&2
    exit 0
fi
exec code-forge gate-check
```

### Edge cases

- **Deleted code files**: `git diff --cached --name-only` includes deletions.
  Deleting a `.py` file should trigger verify (could break imports). Correct.
- **Files with no extension** (`Makefile`, `Dockerfile`): no match, treated as
  non-code. Acceptable for forge's use case.
- **Empty commits**: no staged files, skip. Correct.
- **Binary files with code extension** (e.g., compiled `.pyc`): matched by name.
  `.pyc` files should not be committed anyway (gitignored).

### Integration

Modify `_hook_content()` in `install_hooks.py` to generate the carve-out
template. The carve-out goes BEFORE the `exec code-forge gate-check` line.
