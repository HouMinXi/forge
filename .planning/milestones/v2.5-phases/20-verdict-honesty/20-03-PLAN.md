<objective>
Extend the eval scoring system to support RUNTIME advisory axis and fix
E1-E6 corpus entries.

Purpose: The eval scorecard must measure the RUNTIME axis (SC5). Unlike
blocking axes (TRUST, FIXVAL) where "caught" means the verdict changed to
HOLD, advisory axes are scored by content match: does the advisory text
contain expected keywords? This plan adds: (1) expected_advisory field to
CorpusEntry, (2) advisory_caught scoring helper using case-insensitive
keyword substring matching (D-12), (3) RuntimeAxisHook registered in the
eval runner, (4) corrected E1-E6 corpus entries with expected_advisory
keywords and fixed expected_verdict values per D-06.

Output: Modified corpus.py, scorer.py, runner.py; updated corpus.yaml; new
test_runtime_eval.py
</objective>

    CRITICAL (H1+F1+DS-R3 fix): Advisory scoring uses a SEPARATE field, not
    caught_count. Reason: caught_count drives actual_verdict calculation
    (caught_count >= majority threshold -> actual_verdict = "HOLD"). If advisory
    scoring writes to caught_count, a RUNTIME-only entry with keyword match
    would get actual_verdict="HOLD" even though forge returned PASS -- corrupting
    the eval result.

    Architecture:
      - Add advisory_caught_count: int to EvalResult (default 0). This is a
        NEW field independent of caught_count.
      - caught_count stays for verdict-match (forge exit code). advisory_caught_count
        is for advisory keyword match. They never interfere.
      - In the runner's PER-RUN loop (where it already reads the review state
        for each run), BEFORE the temp dir is cleaned up:
        (a) Read advisory-findings.json from the review temp directory.
        (b) Concatenate RUNTIME-axis advisory finding descriptions, EXCLUDING
            id="runtime-smoke-summary" (its description contains surface names
            that would false-positive keyword matches in eval scoring).
        (c) Call advisory_caught(concat_text, entry.expected_advisory).
        (d) If True, increment a per-run advisory_hit counter.
      - After N runs, compute advisory majority (2-of-3 = advisory_caught).
        Set advisory_caught_count = number of runs where advisory_caught was True.
      - actual_verdict is computed ONLY from caught_count (verdict-match), unchanged.

    SCORING in compute_summary (scorer.py):

      - For dual-axis entries (ttl_class: expected_verdict == "HOLD" AND
        expected_advisory non-empty): "caught" = verdict_caught (caught_count

        NOT gate the overall caught classification. Rationale: FIXVAL is the
