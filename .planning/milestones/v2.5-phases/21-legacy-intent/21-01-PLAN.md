git blame --porcelain block format (empirically verified):
```
<40-hex-sha> <orig-line> <final-line> [<count>]   # header
author <name>                                       # only on FIRST occurrence of sha
author-mail <email>
author-time <unix-ts>
author-tz <+HHMM>
committer ...
summary <first-line-of-commit-msg>                  # only on first occurrence
[boundary]
[previous <sha> <filename>]
filename <filename-in-commit>
\t<actual line content>                             # TAB prefix, marks end of block
```
For repeated SHAs: only `<sha> <orig> <final>` + `filename` + `\tcontent` -- no author/summary.
Staged lines: SHA = "0000000000000000000000000000000000000000", author = "Not Committed Yet".

    and remain a D-06 violation to address separately; do NOT claim "log" in git.py's

    Implementation requirements (all from RESEARCH.md Pattern 3):
    - Signature: git_blame(file_path: str, repo_root: Path) -> dict[int, dict]
    - Returns: {final_line_number: {"sha": str, "author": str, "subject": str}}
      where final_line_number is 1-indexed.
    - Guard: if shutil.which("git") is None: return {} (DELIBERATE DIVERGENCE: existing
      git.py functions raise RuntimeError on missing git; git_blame returns {} instead
      because it runs in an advisory axis where failures must degrade gracefully, not
      crash. Add a comment in code: "Advisory axis: return {} instead of raising").
      (partial match to existing git.py contract:
      every public function checks for git binary, raises or returns gracefully if absent).
    - Command: wrap in try/except subprocess.TimeoutExpired → return {}:
        try:
            result = subprocess.run(["git", "blame", "--porcelain", "--", file_path],
                cwd=repo_root, capture_output=True, check=False,
                timeout=60, encoding="utf-8", errors="replace")
                # encoding+errors: author names may be non-UTF-8; replace avoids UnicodeDecodeError
        except (subprocess.TimeoutExpired, OSError):
            return {}  # OSError: git removed/permission changed after shutil.which passed
    - Return {} on non-zero returncode (never raise). Return {} on empty stdout.
    - Per-line parsing order (CRITICAL -- must check in this order):
      1. Tab prefix check FIRST: if line.startswith("\t"), it is a content line
         (the blamed source code). Record blame_map[current_final_line] = {...sha_cache...}.
         Do NOT apply SHA header check on tab-prefixed lines -- a source line containing
         a 40-hex string would be falsely identified as a new SHA header.
      2. Guard: parts = line.split(); if not parts: continue  (skip empty lines)
      3. SHA header detection: len(parts) >= 3 and len(parts[0]) == 40 and
         all(c in '0123456789abcdef' for c in parts[0].lower()).
         (.lower() for defensive robustness; git-blame output is lowercase per docs.)
         Hex-only, NOT isalnum() (isalnum() accepts 'G', 'Z', etc.).
         When matched: current_sha = parts[0]; current_final_line = int(parts[2])
         (parts[1]=orig-line, parts[2]=final-line in blamed file, 1-indexed).
         current_final_line is the key used in blame_map when the tab-line is reached.
    - boundary/previous lines: do NOT match the 40-hex-char condition; safely ignored
      (document this in a comment: "boundary/previous lines are non-hex, safely skipped").
    - SHA cache: dict[str, dict] -- populated ONLY on FIRST occurrence of a SHA (the block
      that has "author " and "summary " metadata lines). On repeated SHA blocks (second,
      third occurrence), metadata lines are absent -- do NOT update sha_cache (would
      overwrite correct cached values with empty strings). Condition: only write
      sha_cache[sha] when "author" metadata was seen in THIS block.
    - filename line ("filename "): marks end of header block -- finalize sha_cache entry
      IF author was seen; mark current_sha as "processed" to skip repeated blocks.
    - Tab-prefixed line ("\t"): record blame_map[current_final_line] = sha_cache.get(current_sha, {"sha":current_sha,"author":"unknown","subject":""}).
    - author line: raw_line[7:] (strip "author ")
    - summary line: raw_line[8:] (strip "summary ")
    - Do NOT strip author-mail separately -- the "author" field is name only
      (D-04: attribution format uses author_name, not email).

      git diff HEAD -- src/code_forge/git.py | grep '^+' | grep -P '[^\x00-\x7F]'
