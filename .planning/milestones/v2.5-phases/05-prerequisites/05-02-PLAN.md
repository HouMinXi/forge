<objective>
Implement the pluggable review-backend abstraction (BACKEND-01, Phase-5 half) and the backend-agnostic reachability probe (CLI-05). This is the module Phase 7 adapter implementations extend.

Purpose: forge must support review backends beyond a hard-bound `claude -p`. Phase 5 locks (a) the backend config schema {name, type, format?, base_url?, api_key_env?, model} (D-27), (b) the active-backend resolution order FORGE_BACKEND > config default > session-model default (D-27), with the DEFAULT backend being the session model -- a plain `claude -p` with no --model pin (D-26), and (c) a backend-agnostic reachability probe that is NOT an inference call (D-28): for a cli/claude backend it runs `claude auth status --json`; for an api backend it checks the configured api_key_env is present.

Output: src/code_forge/backend.py with BackendConfig, ProbeResult, load_backend_configs(), resolve_backend(), resolve_auth_timeout(), probe_backend(), invalidate_probe_cache(), DEFAULT_BACKEND + comprehensive TDD tests.

Scope boundary (D-30): Phase 5 locks the abstraction + config + resolution + probe ONLY. The actual HTTP clients for the two API wire formats (OpenAI-format POST /v1/chat/completions, Anthropic-format POST /v1/messages) and the cli wrappers that RUN a review pass land in Phase 7 (Outlet A dispatcher). This module does NOT make any inference / chat-completions call. probe_backend only verifies reachability.

NON-GOAL (D-26, hard, not deferred): forge NEVER analyzes the diff (code complexity, change size, or any added dimension) to auto-select a backend or model. The user configures the model; forge follows the session model by default. resolve_backend takes config + env only -- it has no diff parameter and must never gain one.
</objective>
