<objective>
Implement toolchain auto-detection for Python projects (CLI-03) and the detect_and_init function that code-forge review will call when tools.yaml is missing (CLI-04/D-20).

Purpose: Users running code-forge review in a Python project with no tools.yaml get L0 linting from auto-detected ruff/pylint/flake8 without manual config. This plan delivers all three: ruff and pylint via [tool.*] detection, flake8 via flake8-config-file detection (flake8 has no pyproject.toml support) plus a dedicated text-output parser.
Output: src/code_forge/detect.py with detect_toolchain(), generate_tools_yaml(), detect_and_init() + comprehensive TDD tests. Note: Phase 5 generates tools.yaml only. gate.yaml is deferred to Phase 6/7 per D-23 resolution (gate.yaml requires test gate + outlet field which are Phase 6/7 scope).

Known Limitations: ruff, pylint, and flake8 are all fully supported linters in this plan (each has a tools_yaml_entry and a parser reachable via PARSER_DISPATCH, with its output_format in registry _KNOWN_FORMATS). Dispatch keys: ruff uses output_format="sarif" (shared _parse_sarif), pylint uses "pylint_json" (NEW parse_pylint added by this plan), flake8 uses "flake8" (NEW parse_flake8). This plan FIXES a confirmed pre-existing defect where ruff/pylint tools_yaml_entry specs emitted output_format values ("ruff_json"/"pylint_json") that had no PARSER_DISPATCH key, which would KeyError when parse_output ran the auto-generated tools.yaml at L0. mypy is still detected as a Python tool (listed in PYTHON_TOOL_REGISTRY) but is NOT included in generated tools.yaml because it has no tools_yaml_entry (no parser, mypy output_format not in _KNOWN_FORMATS). A Python project whose ONLY detected tool is mypy (no ruff/pylint/flake8) will trigger the D-02 error stop from generate_tools_yaml. mypy format support remains a follow-up task requiring a new parser added to PARSER_DISPATCH and mypy added to registry.py _KNOWN_FORMATS.
</objective>
