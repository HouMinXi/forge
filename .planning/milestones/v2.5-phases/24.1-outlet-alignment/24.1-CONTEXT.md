1. GOAL + WHY IT SITS HERE
   Goal: the review OUTLET (A subprocess / B inline / C subagent) is a
   TRANSPORT choice for the L1 LLM step ONLY. Everything else -- phase
   sequence, reset rule, convergence threshold, falsification gate,
   verdict + receipt semantics -- is identical across all three. Same
   diff + same gate.yaml => same verdict, whichever outlet ran.
   Why between 24 and 25: Phase 25 (cross-repo merge review) builds
   review orchestration ON TOP of the outlets. On a 3-way-forked base
   the joint-unit verdict would depend on which outlet ran. Align the
   base before building on it.

2. VERIFIED GROUND TRUTH (file:line -- the geology; do NOT re-discover)
   THE FLOW IS DEFINED ONCE, IN CODE, FOR TWO OF THE THREE OUTLETS:
   - StateMachine (machine.py) is the flow. `_execute_round` (machine.py:647)
     runs L0 + L1 + L2 + e2e + coverage every round; docstring (machine.py:648)
     "both modes run L0+L1+L2+E2E each round". run() (machine.py:165) dispatches
     LOCAL/CI then runs advisory axes once after convergence (machine.py:180).
   - Reset rule = BINARY `_fixpoint_reached` (machine.py:766-811): a round is
     clean iff zero NEW CONFIRMED, zero FIXED->CONFIRMED, zero unfixed
     CONFIRMED, zero UNCERTAIN -- NO severity tiering. Non-clean resets
     consecutive_clean_rounds to 0 (machine.py:465-468); converge at
     clean_round_threshold (default 3).
   - L2 (mutation) and e2e per-round runners are NO-OP in A too: the
     StateMachine fields default to no-op lambdas (machine.py:142-147) and
     _run_hold_loop (cli.py:1549) does NOT inject them. ONLY outlet_c stubs
     them explicitly. So per-round mutation/e2e feed NO outlet's verdict.
     Mutation R2 gates only via CI async cross-run path (machine.py:204-343)
     and the standalone `mutation-check` subcommand (cli.py:1636). e2e R3
     gates only via the `e2e-check` subcommand (cli.py:1744). LOCAL review
     verdict contains neither. (The MUTANT-survivor counter in _run_local,
     machine.py:442-461, is dormant on the normal A path -- nothing feeds it.)

   THE THREE OUTLETS TODAY:
   - A (subprocess) cli.py:1549 builds StateMachine with real registry
     (loaded cli.py:1271), real l1_provider (build_l1_provider + backend),
     backend-backed falsifier (build_falsifier(engine, backend), cli.py:1447),
     5 advisory runners (taint/runtime/graph/daemon/legacy, cli.py:1543-1570),
     default REAL l0_runner. Writes receipts per round (machine.py:695).
   - C (subagent) outlet_c.py:85 builds the SAME StateMachine -- docstring
     "same StateMachine that Outlet A uses" -- BUT: l0_runner stubbed
     (outlet_c.py:95), l2/e2e stubbed (97-98), registry={} (94), NO advisory
     runners, falsifier built WITHOUT backend (outlet_c.py:47, self-marked
     "thread one through before Outlet C goes live"). Only L1 (spawn_fn,

4. DECISIONS LOCKED
   D1  Alignment is defined at the RIGHT LAYER per outlet:
       - A <-> C = IMPLEMENTATION alignment (same StateMachine, same injected
         legs; only L1 transport differs). Achievable, mostly parameter wiring.
       - {A,C} <-> B = SEMANTIC alignment only. Inline cannot run the
         StateMachine -- inline IS the session. Do NOT try to make inline call
         machine.py. B aligns by executing the SAME flow CONTRACT, not the
         same code.
   D2  C full-leg target = inject into run_outlet_c the same real legs A uses:
       real registry (cli.py:1271), backend-threaded falsifier, the 5 advisory
       runners; DROP the l0 stub (use default _default_l0_runner with the real
       registry); make l2/e2e the SAME no-op default A uses (not a special
       stub), so C carries zero extra divergence. The falsifier-backend fix is
       MANDATORY not optional: a no-backend falsifier cannot run the L1
       anti-hallucination gate, so today's C is not "fewer legs" -- it is a
       BROKEN core gate.
   D3  ONE canonical reset rule. Direction = TIERED (SKILL.md P0/P1/P2/P3),
       because it is the documented intended evolution and avoids the
       binary-reset non-convergence pathology (a steady P2 stream resets every
       round under binary => never converges). machine.py `_fixpoint_reached`
       + the _run_local reset step get upgraded to severity-aware; P3 density
       thresholds come from the existing P3-THRESHOLD-RESEARCH.md (planner
       reads it; do NOT re-derive).
   D4  Inline honesty (minimal B alignment floor): inline must NOT return a
       value that masquerades as a real gate-PASS. Add a distinct DELEGATED
       result (verdict/exit-code) meaning "CLI did not gate; review delegated
       to session + external R1", OR have inline emit a real receipt+verdict
       from the session. Floor = DELEGATED marker. Full parity = deferred
       unless the release-gating decision (section 6) pulls it in.
   D5  SINGLE SOURCE OF TRUTH. The flow contract (phase order, reset rule,
       convergence threshold, falsification-gate requirement, verdict meanings)
       is defined ONCE; both the StateMachine and SKILL.md derive from / cite
       it, with a drift guard (test or CI check) that FAILS when the two encode
       different rules. This is what prevents re-divergence -- the reset rule
       already drifted precisely because it is written twice.
