    Six additions to docs/configuration.md, each at the most natural insertion
    point in the existing document structure:

    Bug 1 (FORGE_LLM_TIMEOUT_S install note): Near the existing
    FORGE_LLM_TIMEOUT_S documentation (around line 99), add a note that this
    environment variable requires a build that includes the timeout override
    (forge v2.5+ or later). Users on an older installation should update
    via "pip install --upgrade code-forge" or reinstall from source. This is
    an informational note, not a behavioral change. Use the release version
    tag (not the commit hash) -- end users running pip install cannot look up
    commit SHAs.

    Bug 2 (anthropic-format URL append): Near the existing base_url
    documentation (around line 147-148, which already mentions "including
    version path for OpenAI"), add explicit documentation that format:anthropic
    appends /v1/messages to the configured base_url. Example: if base_url is
    "https://proxy.example.com/anthropic", the actual request goes to
    "https://proxy.example.com/anthropic/v1/messages". Users must NOT include
    /v1/messages in base_url for anthropic-format backends. Contrast with
    format:openai which expects base_url to include the version path.

    Bug 3 (implicit claude -p warning): Near the outlet/subprocess
    documentation (around line 34), clarify that the warning "Implicit claude
    -p is disabled" fires only when no backend is explicitly configured and
    the resolver would fall back to the implicit claude CLI default. Setting
    command: claude (or a proxy binary path) in gate.yaml backends is the
    EXPLICIT configuration and does NOT trigger the warning. The warning
    exists to prevent silent fallback to an expensive Anthropic Pro session
    when the user intended to use a cheaper backend.

    Bug 6 (model selection guide): Add a new section "Model Selection" (or
    subsection under an existing backends section). Content: forge's 9-pass
    review sends 3 L1 prompts per round (qodo/expert/adversarial) for
    multiple rounds. Each prompt contains the full diff + review context.
    Reasoning models (opus, sonnet-extended, mimo-pro, deepseek-reasoner)
    add substantial thinking overhead per pass, multiplied by 9+ passes.
    Recommended: use a fast non-reasoning model (haiku, mimo, deepseek-chat,
    glm-4) as the primary review backend. Reserve reasoning models for
    single-pass deep analysis or falsification. Table format with model
    categories and their suitability for multi-pass vs single-pass.

    Bug 8 (third-party API proxy): Add a subsection "Third-Party API Proxies"
    distinguishing two usage patterns: (a) CLI outlet with a proxy binary
    (type: cli, command: /path/to/proxy-binary) -- the proxy binary replaces
    claude and must accept the same stdin/stdout contract; (b) API outlet
    with a proxy URL (type: api, base_url: https://proxy.example.com/...) --
    the proxy must implement the OpenAI or Anthropic API format. Note that
    the "authenticated session" phrase in the existing docs (around line
    34-35) refers to the default claude CLI which uses the user's Anthropic
    account; third-party proxies use their own authentication via api_key_env.

    Troubleshooting table (Bug 7 replacement): Add a section "Backend
    Troubleshooting" at the end of the backends documentation. Table format
    with columns: Symptom | Likely Cause | Fix. Cover at least these rows:
    - "L1 pass always times out" -> backend too slow or unreachable -> raise
      FORGE_LLM_TIMEOUT_S or switch to a faster model
    - "unexpected response structure" -> backend returned non-JSON or
      truncated response -> check max_tokens setting, ensure >= 16384
    - "Implicit claude -p is disabled" warning -> no backend configured ->
      add a backends section to gate.yaml or set FORGE_OUTLET=inline
    - "LLM subprocess failed" -> CLI binary not found or crashed -> verify
      the command path exists and is executable
    - "schema validation failed" -> backend returned valid JSON but wrong
      structure -> check that the backend supports the expected API format
    - "lock busy" -> another forge process is running -> wait or check for
      stuck processes
    - exit code 6 (TIMEOUT) -> backend produced 5+ consecutive L1 timeouts,
      circuit breaker tripped -> reduce diff size, raise FORGE_LLM_TIMEOUT_S,
      or switch to a faster (non-reasoning) backend

    Ensure all additions use plain ASCII (no em dashes, smart quotes, or
    Unicode characters). Keep the existing document structure and tone.
