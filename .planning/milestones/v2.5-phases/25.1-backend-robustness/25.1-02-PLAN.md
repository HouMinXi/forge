<objective>
Implement D-4 Option B: backend-agnostic L1 truncation false-green guard. When
an L1 pass returns findings==0 but its code_excerpts do not cover every changed
file, emit a CONFIRMED INFRA finding instead of treating it as a genuine clean
pass.

Purpose: A truncated L1 response can parse as valid JSON with findings==[] and
one excerpt, passing validate_reviewer_json as a clean pass. This is a real
failure mode (observed with mimo-pro at max_tokens=8192). The guard closes the
residual false-green path by requiring excerpt coverage of every changed file
before accepting a clean pass.

  <action>
    In factories.py _provider() inner function, AFTER the validate_reviewer_json
    call succeeds (line 314) and the _collect_excerpts call (line 329), insert
    the coverage guard BEFORE the findings-append loop (line 331). The guard
    runs ONLY when len(validated["findings"]) == 0 (clean pass case).

    The guard logic:
    1. Import parse_diff_files from .verify (lazy import inside the guard block,
       NOT at module level -- this avoids circular imports AND ensures the
       monkeypatch in test (g) can intercept the import; a module-level import
       binds the name at import time and monkeypatching code_forge.verify would
       not affect the already-bound local name).
    2. Extract changed files: changed = set(parse_diff_files(diff_text).keys()).
       diff_text is already available in _provider's closure (it is a parameter
       of build_l1_provider, captured by _provider). If diff_text is empty or
       None, skip the guard (no diff = nothing to check).
    3. Deleted files are already excluded by construction: parse_diff_files
       (verify.py:43) only matches lines starting with "+++ b/". Deleted
       files have "+++ /dev/null" which does NOT match that prefix, so they
       never appear in the returned dict. No explicit filter needed. If a
       future refactor changes parse_diff_files to include /dev/null entries,
       the defense is a one-line filter: changed.discard("/dev/null").
    4. Extract covered files from the excerpts: the validated dict has
       "code_excerpts" which is a list of dicts, each with a "file" key.
       Collect covered = {exc.get("file", "") for exc in validated.get("code_excerpts", [])}.
       Filter out empty strings.
    5. Normalize both sides for comparison using a _normalize helper:
       (a) Strip leading "./" prefix (handles "./src/foo.py" -> "src/foo.py").
       (b) Strip leading "/" (handles "/absolute/repo/src/foo.py" -> relative).
       (c) Replace backslashes with forward slashes.
       (d) For matching: first try exact match of normalized paths. If no exact
       match, try basename fallback: if os.path.basename(changed_file) matches
       os.path.basename(any excerpt file), AND there is only one such basename
       match (no ambiguity from same-named files in different directories),
       count it as covered. This handles the case where an excerpt uses bare
       "foo.py" for "src/foo.py". If multiple excerpt files share the same
       basename, the basename fallback does NOT match (ambiguous).
       (e) Also try suffix match: if any excerpt file ends with "/" + changed_file
       or changed_file ends with "/" + any excerpt file, count it as covered.
       This handles cross-repo absolute paths where the excerpt uses
       "/home/user/repo/src/foo.py" for "src/foo.py".
    6. If any changed file has zero coverage (no matching excerpt): create a
       CONFIRMED INFRA StateFinding with id="l1-{pass_name}-incomplete-coverage",
       fingerprint="incomplete-coverage-{pass_name}", source="INFRA",
       disposition=Disposition.CONFIRMED, file="<coverage-guard>",
       line_range=[0, 0], description listing up to 3 uncovered files.
       Append it to all_candidates. Then continue (skip the normal findings
       append for this pass -- the pass is untrusted).
    7. If all changed files are covered, fall through to the normal path
       (the findings-append loop at line 331).

    The _provider function's closure already has diff_text available because
    build_l1_provider receives it. Verify this by reading build_l1_provider's
    signature and confirm diff_text is captured. If diff_text is not in the
    closure, it must be threaded through -- check the function signature.
  </action>
