  <action>
    CONTRACT LOADER (new file src/code_forge/contract_loader.py):

    Imports: dataclasses (frozen=True), hashlib, json, os, sys, pathlib.Path, yaml, CliError from .errors, LLMInvokeError from .llm_invoke, is_trusted_contracts from .trust.

    Three frozen dataclasses per D-08/D-12: ContractSpec (path: str, max_raw_size: int = 32768), ContractRepo (path: str, specs: list[ContractSpec]), ContractsConfig (repos: dict[str, ContractRepo]).

    Default max_raw_size = 32768 (32KB). Rationale: real OVS YNL specs are 3-23KB; 32KB keeps ovs_flow.yaml (23KB) raw while summarizing tc.yaml (80KB) and ethtool.yaml (58KB).

    _warn(msg: str) -> None: writes "code-forge: contract: {msg}\n" to sys.stderr.

    _HARD_SIZE_LIMIT = 10 * 1024 * 1024 (10 MB). Used by stat-first check (SF-4).

    _is_within_repo(path: Path, repo_root: Path) -> bool: dedicated containment check (CF-1). Returns True when repo_root.resolve() is in path.resolve().parents or path.resolve() == repo_root.resolve(). DO NOT import _symlink_guard_passes from conventions_resolver -- that function checks cwd.parent, which inverts the intended boundary for cross-repo sibling specs.

    load_contracts_config(config_path: Path) -> ContractsConfig: opens file, yaml.safe_load, validates top-level dict has "repos" key (dict), iterates repos constructing ContractRepo and ContractSpec dataclasses. Raises CliError with descriptive message on type/schema errors.

    _resolve_repo_path(raw_path: str, cwd: Path) -> tuple[Path | None, str | None]: calls os.path.expandvars(raw_path). If "$" still in result, returns (None, "env var not set in: {raw_path}"). Otherwise resolves relative paths against cwd: (cwd / expanded).resolve() if not absolute, else Path(expanded).resolve(). Returns (resolved, None). Intentional: relative repo paths like "../kernel" must resolve against the reviewed repo root, not os.getcwd() which depends on invocation context (gm r4 M).

    _read_spec_content(spec_path: Path) -> bytes | None:
    1. stat() the file first (SF-4). If st_size > _HARD_SIZE_LIMIT, _warn and return None.
    2. Read file as bytes.
    3. Check null bytes in first 1024 bytes (binary detection).
    4. Return None if binary, else return content bytes.

    _content_hash(content: bytes) -> str: hashlib.sha256(content).hexdigest().

    _spec_cache_path(cache_dir: Path, repo_name: str, spec_path_str: str, content_hash: str) -> Path: builds "{repo_name}_{spec_path_hash12}_{content_hash}.json" where spec_path_hash12 = hashlib.sha256(spec_path_str.encode()).hexdigest()[:12] (SF-3: 12 chars, matching conventions_resolver pattern).

    _read_spec_cache(cache_path: Path) -> str | None: reads JSON, returns data.get("summary"). Returns None on any exception.

    _write_spec_cache(cache_path: Path, summary: str, source: str, content_hash: str) -> None: mkdir parents, write JSON. OSError is non-fatal (pass).

    _summarize_spec(content_str: str, spec_name: str, backend) -> str: calls llm_invoke with prompt "Summarize the following specification for a code reviewer. Preserve all field names, attribute types, operation names, and constraints. Return your response as a JSON object with a single key: {\"summary\": \"your summary text here\"}.\n\nSpec ({spec_name}):\n{content_str}". CRITICAL (SF-9 + ds r3 BLOCKER): pass expected_keys=frozenset({"summary"}) -- NOT frozenset() and NOT None. Rationale: (1) None falls back to _REVIEW_ENVELOPE_KEYS ({verdict,reasoning}) which rejects summarization output. (2) frozenset() makes _extract_json_from_text reject ALL dicts (obj.keys() & frozenset() is always empty at llm_invoke.py:172), so API backends ALWAYS raise LLMInvokeError on prose responses. (3) frozenset({"summary"}) accepts only dicts containing "summary" key, which the prompt requests. After llm_invoke returns, extract: result.content.get("summary", "") if isinstance(result.content, dict) else str(result.content). The content_str parameter is already decoded from bytes (SF-2).

    _MAX_SUMMARIZE_BYTES = 512 * 1024 (512 KB). Files between max_raw_size and _MAX_SUMMARIZE_BYTES get summarized; files above get empty digest with warning "spec too large for summarization". Intentional because: an 8MB text file is a doomed LLM call; D-07 catches it but wastes time + tokens (ds H). User decision: 512KB is correct -- backends that cannot handle 512KB in a 1M context window are not worth supporting.

    resolve_contract_specs(config_path: Path, cwd: Path) -> list[tuple[str, str, str, bytes, int]]: PUBLIC function. Single source of truth for spec path resolution + file reading. Returns list of (repo_name, spec_relative_path, resolved_abs_path_str, content_bytes, max_raw_size) 5-tuples. The 5th element carries the per-spec max_raw_size from ContractSpec so load_contract_digest can apply size gating without re-parsing the config (gm r4 BLOCKER: 4-tuple left spec.max_raw_size unbound in the digest loop). Both load_contract_digest and Plan 02's _run_trust call this to ensure trust hash is computed over identical resolution (gm+ds 2/3 convergent: divergent reimplementations cause silent trust mismatch).
      1. load_contracts_config(config_path).
      2. For each (repo_name, repo) in config.repos: _resolve_repo_path(repo.path, cwd) -> repo_path. Skip + _warn on env var failure.
      3. For each spec in repo.specs: join repo_path / spec.path, resolve() -> resolved. Containment check: _is_within_repo(resolved, repo_path) -- check against the EXTERNAL REPO ROOT, NOT cwd. Intentional because: cwd is the reviewed repo (e.g. OVS), specs live in sibling repos (e.g. kernel); checking against cwd rejects all valid cross-repo specs (gm r3 BLOCKER). stat-first _HARD_SIZE_LIMIT check (SF-4). Read bytes via _read_spec_content. If _read_spec_content returns None (oversized or binary): skip this spec, continue (gm r3 M: filter None before appending). Null-byte binary check is inside _read_spec_content.
      4. Each spec wrapped in try/except OSError (CF-2). Skip + _warn.
      5. Append (repo_name, spec.path, str(resolved), content_bytes, spec.max_raw_size) to result. Return collected list. Empty on no valid specs.
      Does NOT do trust, caching, or summarization.

    load_contract_digest(config_path: Path, cwd: Path, backend=None) -> str: orchestrator.
      1. If not config_path.is_file(): return "" (SC-3).
      2. resolved_specs = resolve_contract_specs(config_path, cwd). On Exception: _warn + return "".
      3. Build trust_contents: [(abs_path, content) for (_, _, abs_path, content, _) in resolved_specs]. Trust: is_trusted_contracts(config_path, trust_contents). False: _warn + return "".
      4. cache_dir = cwd / ".code-forge" / "cache" / "contracts" (D-09/D-11).
      5. For each (repo_name, spec_path, abs_path, content_bytes, max_raw_size) in resolved_specs:
         a. len(content_bytes) <= max_raw_size: digest_text = content_bytes.decode("utf-8", errors="replace").
         b. len(content_bytes) > _MAX_SUMMARIZE_BYTES: _warn("spec too large for summarization: {abs_path}") + digest_text = "".
         c. Else (summarizable): c_hash = _content_hash(content_bytes) -- hash BYTES first (sha256 needs bytes; gm r2 M verified). content_str = content_bytes.decode("utf-8", errors="replace") -- decode AFTER hash (SF-2). Cache check with c_hash using _spec_cache_path(cache_dir, repo_name, spec_path, c_hash). Hit: cached. Miss: _summarize_spec(content_str, f"{repo_name}/{spec_path}", backend); LLMInvokeError: _warn + "". Write cache ONLY if summary is non-empty (ds r3 M: empty string poisons cache permanently -- "" is not None, so _read_spec_cache returns "" forever, summarization never retried after transient failure).
         d. digest_text non-empty: append "## Contract: {repo_name}/{spec_path}\n{digest_text}".
      6. Return "\n\n".join(sections) or "".
      7. Entire body (2-6) in try/except Exception: _warn + return "" (D-07).

    IMPLEMENTATION NOTE: resolve_contract_specs returns 5-tuples (repo_name, spec_path, abs_path, content, max_raw_size). load_contract_digest unpacks all 5 for the digest loop and extracts (abs_path, content) 2-tuples for the trust hash. Plan 02 _run_trust does the same 2-tuple extraction. The 5-tuple carries max_raw_size so the digest loop can apply per-spec size gating without re-parsing the config.

Mock llm_invoke for summarization tests. Mock trust via monkeypatch on is_trusted_contracts. Test each behavior listed above in RED-GREEN order.
