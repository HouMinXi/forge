  <action>
    Perform a live viability test of the Agent tool:

    1. Use the Agent tool (or Task tool if Agent is unavailable) to spawn a trivial
       subagent with the prompt: "Return the single word VIABLE and nothing else."
       Set a 60-second timeout. If the Agent tool does not return within 60 seconds, use TaskStop to cancel it. If TaskStop is unavailable or unresponsive, record FAIL in VIABILITY.md stating 'Agent tool hung; unable to abort gracefully' and close the task. Record whether:
       a. The Agent tool returns a response (PASS)
       b. The Agent tool hangs indefinitely at "Launching..." (FAIL)
       c. The Agent tool returns an error (PARTIAL -- record the error)

    2. If step 1 passes, test a slightly more realistic scenario: spawn a subagent
       with the prompt: "You are a code reviewer. Given this diff:\n+print('hello')\n\n
       Return JSON: {\"findings\": [], \"verdict\": \"PASS\"}"
       Record whether the subagent returns structured JSON without hanging.

    3. If step 2 passes, test fresh-context isolation: spawn TWO sequential subagents.
       First: "Set X=42. Return X." NOTE: This tests prompt isolation, not filesystem isolation. The second agent lacks X in its prompt, proving fresh context. If stronger isolation proof is needed, have agent 1 write to a temp file and agent 2 attempt to read it via context (not filesystem). Second: "Return X."  The second agent lacks X in its prompt, proving fresh context. If stronger isolation proof is needed, have agent 1 write to a temp file and agent 2 attempt to read it via context (not filesystem).
       The second should NOT know X=42 (fresh context). Record whether context
       isolation holds.

    4. Write VIABILITY.md with the following structure:
       - Date of test
       - Test environment (model, tool used)
       - Test 1 result (trivial response)
       - Test 2 result (structured JSON)
       - Test 3 result (context isolation)
       - Verdict: PASS or FAIL
       - If FAIL: describe the failure mode and recommend deferral
       - If PASS: note any caveats (latency, reliability concerns)

    IMPORTANT: If ANY test hangs for more than 60 seconds, abort and record FAIL.
    The viability gate is binary: either the Agent tool works for this use case or
    it does not. Partial success (works sometimes, hangs sometimes) is FAIL.
  </action>
