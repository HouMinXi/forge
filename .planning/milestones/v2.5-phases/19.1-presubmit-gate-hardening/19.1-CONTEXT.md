<domain>
## Phase Boundary

The AI author forgets presubmit checks (checkpatch, vng) under context pressure;
docs are not gates (anti-shirk: build systems, do not trust executors). The
naive fix -- bake checkpatch into forge -- fails scope review: forge's users are
mostly NON-kernel, so kernel-specific gates do not belong in the PUBLIC product.

Direction: forge ships a GENERIC presubmit external-linter framework. A linter
(checkpatch, go-vet, clippy, eslint, ...) is a gate.yaml entry -- config DATA,
not forge code. This scopes Phase 19.1 to the forge product side; the kernel-
specific pieces (checkpatch instance, kernel-force enforcement, vng) move to
personal dotfiles, outside this phase.

In scope (forge product -- GSD, worktree, full 9-pass):
1. gate.yaml `presubmit:` section: generic linter entries
   (command + applies_to glob + on: diff|patch|message + optional when_exists).
2. install_hooks pre-commit runs each entry and blocks on failure; a configured
   linter whose binary is missing or whose command errors FAILS the commit
   (framework-level fail-closed -- never a silent pass).
3. Built-in generic non-ASCII + AI-vocab check over the commit message and
   staged diff (extends the review-pipeline Step 0c / Step 3a coverage down into
   the install_hooks pre-commit).
4. README doc-snippet presets (checkpatch / go-vet / clippy / eslint) -- NOT
   endorsed: forge promises no upstream parity; users copy and adapt at own risk.
5. Fix SKILL.md 176 overclaim.
6. Strip D-NN plan-ref labels from tests/test_fixval.py.

Out of scope (personal dotfiles -- NOT this forge phase, recorded below for the
separate personal work):
- checkpatch as the user's own gate.yaml instance (with --strict
  --max-line-length=80 as user data);
- the "kernel tree present but no checkpatch entry -> block" fail-closed
  meta-hook (keeps the forge framework kernel-neutral);
- vng send-time receipt gate (format-patch / send-email);
- full CI pipeline;
- an ENDORSED runtime preset registry (the costly form that promises upstream
  parity) -- deferred until a demand signal.

</domain>

<decisions>
## Implementation Decisions

### Placement
- **D-01:** (Revised 2026-06-12; supersedes prior "Hybrid C".) forge product =
  a generic presubmit external-linter framework (gate.yaml `presubmit:` +
  install_hooks runner) + a built-in generic non-ASCII/AI-vocab check + non-
  endorsed README doc-snippet presets. checkpatch is NOT forge code; it is one
  gate.yaml instance the user writes. Personal dotfiles own the kernel pieces:
  the checkpatch instance, the kernel-force meta-hook, and the vng send-time
  gate. Rationale: forge's users are mostly non-kernel; a generic framework
  serves Go/Rust/JS equally and keeps the PUBLIC product free of kernel code.

### Framework (forge product side, in scope)
- **D-02:** (Revised 2026-06-12.) No hardcoded checkpatch detection in forge.
  Each `presubmit:` entry may carry an optional `when_exists: <path>` so a linter
  activates only when its tool is present (the user's checkpatch entry sets
  `when_exists: scripts/checkpatch.pl`). The framework is config-driven and
  kernel-neutral -- it never special-cases checkpatch.
- **D-09:** (Revised 2026-06-12, C-direction.) Fail-closed lives at the FRAMEWORK
  level: a `presubmit:` entry that is configured but whose binary is missing, or
  whose command errors, FAILS the commit -- never a silent pass. Linter flags are
  user config DATA, so forge needs no built-in checkpatch default (the earlier
  "what default flags" question dissolves). The kernel-policy fail-closed
  ("kernel tree present but checkpatch unconfigured -> block") is a personal
  meta-hook, deliberately outside the neutral framework. Net: forge guarantees a
  configured-but-broken linter cannot pass silently; the personal layer
  guarantees you cannot forget to configure checkpatch on a kernel tree.
- **D-12:** (New, amended twice 2026-06-12.) Built-in generic check: non-ASCII
  (Step 0c grep) + AI-vocab patterns. Implemented as TWO forge-generated hooks:
  (a) pre-commit: checks staged diff (git fires this BEFORE message is composed).
  (b) commit-msg: checks commit message text (fires AFTER message is finalized;
  receives message file path as $1; can abort the commit). Both hooks are generated
  by install_hooks and are always-on (no gate.yaml entry needed). Keeping commit-
  message checking in forge product level ensures all users benefit without relying
  on personal PreToolUse hooks. The personal P-03 hook is a complementary real-time
  layer (catches non-ASCII at Edit/Write time) and remains out of Phase 19.1 scope.
  (Amended 2026-06-12, F1 -- non-ASCII modes.) The non-ASCII check is two-mode:
  DEFAULT `ai-smell` blocks only confusable-with-ASCII typographic chars (em dash
  U+2014, en dash U+2013, smart quotes U+2018/U+2019/U+201C/U+201D, ellipsis
  U+2026, right arrow U+2192, non-breaking space U+00A0); legitimate Unicode (CJK,
  emoji, accents) passes. Opt-IN `strict` (gate.yaml `non_ascii: strict`) blocks
  ALL non-ASCII (`[^\x00-\x7F]`), for repos that must stay pure ASCII. Default is
  ai-smell; strict is opt-IN, never opt-out (safe-for-everyone default; the
  opinionated ban is an explicit opt-in). Applies to BOTH the pre-commit and
  commit-msg D-12 blocks; AI-vocab stays a fixed always-on 6-word subset. Encoding
  (UTF-8 byte sequences) is an impl detail; MUST be tested against real grep
  (catches every listed char; rejects no CJK/emoji/accent). gate.yaml schema
  (Plan 01) adds `non_ascii: ai-smell|strict` (default ai-smell), validated
  fail-closed.
- **D-13:** (New.) Presets are non-endorsed README/docs gate.yaml snippets, not a
  forge-maintained registry. Maintenance cost comes from endorsement, not from
  presets themselves; doc snippets carry no upstream-parity promise, so cost is
  ~zero. The endorsed runtime-registry form stays deferred.
- **D-10:** Non-code commits (`# docs` / `# config` / `# chore` / `# wip`) skip
  the `presubmit:` linters and D-12 staged-diff check (both placed after carve-out
  exit in the pre-commit hook). The D-12 commit-msg hook runs for ALL commits
  regardless of code/non-code (commit messages must always be AI-vocab clean).
- **D-08:** SKILL.md line 176 overclaim: narrow to "applies to code, comments,
  and commit messages". Remove emails/drafts (those belong to the standalone
  anti-ai-audit skill, not forge's per-commit pipeline).

### D-NN label strip (no gray area)
- tests/test_fixval.py lines 32, 89, 650 carry D-01, D-04/D-05, D-03 plan-ref
  labels (the test file's own labels). Strip them. Comment-only, trivial.

### Personal-side decisions (OUT of Phase 19.1 scope)
Recorded for the separate personal dotfiles work. The forge framework above must
NOT depend on, reference, or commit any of these into the forge repo.
- **P-03:** Extend `~/.claude/hooks/check_non_ascii.sh` (a real file, not a
  symlink) to also cover commit-message content + AI-vocab. Complements the forge
  built-in D-12 (realtime Edit/Write capture vs commit-time pass; mutual backup).
- **P-05:** vng receipt content-hash key = sha256(patch content + base commit
  SHA). A code edit changes the patch hash; a rebase changes the base SHA; either
  invalidates the receipt and forces a vng re-run.
- **P-06:** vng receipts stored in repo-local `.vng/` (added to the kernel repo's
  `.git/info/exclude`, since that repo is not ours). Each tree has independent
  receipts.
- **P-07:** `vng-receipt run <args>` wrapper tees real vng output to a receipt
  keyed by the content hash. Send-time gate = a PreToolUse/Bash hook matching
  `git format-patch` / `git send-email`, blocking without a passing receipt for
  the current series.
- **P-11:** The send-time gate also checks the cover letter (PATCH 0/N) for
  non-ASCII + AI-vocab when format-patch/send-email triggers -- one mechanism,
  patch receipts + cover-letter text together.
- **P-KERNEL-FORCE:** personal meta-hook -- kernel tree present
  (scripts/checkpatch.pl) but no checkpatch `presubmit:` entry -> block/warn.
  This is the kernel-policy fail-closed kept OUT of the neutral forge framework
  (see D-09).

<specifics>
## Specific Ideas

- The framework RUNS the configured linter itself and blocks on its real exit /
  output -- no self-attested token. A configured linter with a missing binary
  FAILS (D-09); it must never degrade to a silent pass.
- Anti-shirk: if implementation adds a `# linter-clean` style bypass token, that
  recreates the hole this phase closes. The gate re-runs the tool; it does not
  trust a marker.
- Keep the framework kernel-neutral: no checkpatch special-casing in forge code.
  Kernel policy (force checkpatch on a kernel tree) is a personal meta-hook.
- Two repos, do NOT confuse: forge (PUBLIC, GSD, worktree + 9-pass) vs dotfiles
  (bare repo, git --git-dir=$HOME/.dotfiles --work-tree=$HOME). Personal-hook
  changes (P-*) must NOT be committed into the forge repo.
- vng is expensive: send-time only, never a per-commit hook.

</specifics>
