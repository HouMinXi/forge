    Create docs/presubmit-presets.md with the following structure:

    Title: "Presubmit Linter Presets (Community Examples)"

    Disclaimer paragraph at top: These are community examples, not endorsed
    configurations. forge makes no promise of upstream parity with any linter.
    Copy, adapt, and test in your own workflow. If a linter changes its CLI,
    update your gate.yaml accordingly.

    Each preset is a gate.yaml snippet showing how to add a presubmit entry.
    Use the schema from Plan 01: command (list[str]), applies_to (glob),
    on ("diff" or "patch"), when_exists (optional path).

    Four presets:

    1. checkpatch.pl (Linux kernel):
       ```yaml
       presubmit:
         - command: ["scripts/checkpatch.pl", "--strict", "--max-line-length=80", "-"]
           applies_to: "*.c"
           on: diff
           when_exists: scripts/checkpatch.pl
       ```
       Note: The trailing "-" tells checkpatch to read from stdin. The
       when_exists field means this entry only activates in kernel trees.
       Adjust --max-line-length to match your project's convention.

    2. go vet:
       ```yaml
       presubmit:
         - command: ["go", "vet", "./..."]
           applies_to: "*.go"
           on: diff
       ```
       Note: go vet runs on the whole module. The applies_to filter ensures
       it only triggers when Go files are staged.

    3. clippy (Rust):
       ```yaml
       presubmit:
         - command: ["cargo", "clippy", "--", "-D", "warnings"]
           applies_to: "*.rs"
           on: diff
           when_exists: Cargo.toml
       ```
       Note: -D warnings treats all clippy warnings as errors (blocks commit).

    4. eslint (JavaScript/TypeScript):
       ```yaml
       presubmit:
         - command: ["npx", "eslint", "--ext", ".js", "."]
           applies_to: "*.js"
           on: diff
       ```
       IMPORTANT note to include in doc: `on: diff` pipes the unified git diff to
       the linter's stdin. eslint does NOT read diff format -- it expects file
       paths. This snippet triggers eslint on the whole project when JS files are
       staged; it effectively ignores stdin. Mark this as "requires adaptation":
       for a true staged-file-only scan, users need a wrapper that extracts
       filenames from diff and passes them as arguments. For TypeScript, change
       `--ext .js` to `--ext .ts` and `applies_to: "*.ts"`.

    Each preset includes a "How it works" note explaining what the fields do
    in context (e.g., when_exists makes checkpatch activate only in kernel
    trees, applies_to prevents triggering on unrelated file types).

    End with a "Combining presets" example showing multiple entries in one
    presubmit list, and a note that all entries run sequentially and the hook
    short-circuits on first failure.

    IMPORTANT: This file is documentation only. No code changes. The presets
    are non-endorsed per D-13 -- make this clear in the disclaimer.
