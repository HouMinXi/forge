<objective>
Build the canary_gen.py module: the M2 core that generates semantic mutations of real
diffs, verifies they are non-equivalent via AST structural comparison, injects them into
an isolated diff copy, dispatches a fresh-context review via an injected provider seam,
and orchestrates the full gate pipeline (generate -> inject -> dispatch -> validate ->
partition -> cite-verify -> evaluate).

Purpose: This is the engine behind the inline canary opt-in. All LLM calls go through
injected callables (CanaryProvider / ReviewProvider) so the entire module is unit-testable
with stub providers and zero network calls. The M1 harness (canary.py, evidence.py,
findings.py) handles gate evaluation, partitioning, and cite verification -- this module
generates, injects, dispatches, and wires them together.

Output: src/code_forge/canary_gen.py (new module) + tests/test_canary_gen.py (TDD suite)

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| LLM provider seam | Injected callable returns arbitrary strings; must be validated before trust |
| Diff text input | Untrusted diff content from git; used as prompt input, never executed |
| Reviewer JSON output | LLM-generated JSON; must pass validate_canary_findings + reverify_finding_cites |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-28-01 | Tampering | canary_gen.py | mitigate | D-28-04: injection is string manipulation on a copy; original diff_text never mutated; no filesystem write |
