  <action>
    Add a "### Canary (inline outlet)" subsection to docs/configuration.md, placed after the existing optional sections (graph_triage, daemon_state, siblings, presubmit) following their pattern. Content:

    1. Brief description: Opt-in objective laziness check for the inline review outlet. When enabled, forge plants semantic defects into the diff and gates on how many the reviewer catches. A rubber-stamp reviewer that returns empty findings is detected and flagged UNRELIABLE (exit 7).

    2. gate.yaml snippet (using D-28-03 ranges):
       canary:
         enabled: true              # bool -- required for opt-in
         n: 5                       # int, 3..5 -- canaries to plant per review
         threshold_ratio: 0.6       # float, >0.0..1.0 -- catch ratio to pass

    3. Field descriptions:
       - enabled: Activates the canary check. Equivalent to passing --canary on the CLI.
       - n: Number of canary mutations to plant. Range 3..5. Default 5.
       - threshold_ratio: Minimum fraction of canaries the reviewer must catch. Default 0.6 (i.e., catch >= ceil(0.6 * n) canaries). Range >0.0 to 1.0 (0.0 is rejected because it would produce a threshold of 0, which is meaningless).

    4. Behavior notes:
       - With no opt-in (no --canary flag, no canary: block, or canary.enabled: false), the inline outlet is unchanged (returns DELEGATED, exit 5).
       - When fewer than 2 verified canaries can be generated, the check is skipped with a notice (graceful degradation, not a hard failure).
       - If the canary dispatch fails (LLM timeout, network error), the check degrades to DELEGATED (never crashes).
       - The canary result never alters outlet or model selection (D-16).
       - Planted defects are never written to the working tree or git history.
       - Currently Python diffs only; non-Python diffs skip the canary with a notice.

    5. CLI alternative: --canary flag on code-forge review achieves the same opt-in with default n=5, threshold_ratio=0.6.
  </action>
