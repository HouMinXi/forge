<objective>
Implement the install-hooks subcommand: write a real .git/hooks/pre-commit that
calls `forge gate-check` with an absolute path. Handle backup+chain of existing
hooks, core.hooksPath abort, and hooks dir resolution via git rev-parse.

Purpose: This is the delivery mechanism for R1 -- the pre-commit hook is what
actually gates commits. Without install-hooks, users would need to manually create
the hook file. The absolute path embedding solves the "forge: command not found"
problem in minimal hook shells (SPEC v3.2 round-3 finding).

Output: src/forge/install_hooks.py module + wiring in cli.py + tests.

NOTE: Wave 3 (after Plan 02) because both Plan 02 and Plan 03 modify cli.py.
Plan 02 wires gate-check into cli.py; this plan wires install-hooks into the
same cli.py. Sequential execution prevents merge conflicts.

  <action>
Create src/forge/install_hooks.py with these components:

1. **resolve_hooks_dir(cwd: Path, run_cmd=subprocess.run) -> Path**:
   - Run `git rev-parse --git-path hooks` via subprocess.run (list args)
   - Parse stdout.strip() to get the hooks directory path
   - If the path is relative, resolve it relative to the git repo root
     (git rev-parse --show-toplevel)
   - Raise RuntimeError if not in a git repo or git command fails

2. **check_hooks_path_override(cwd: Path, run_cmd=subprocess.run) -> str | None**:
   - Run `git config --get core.hooksPath`
   - Return the value if set and non-empty, None otherwise
   - Does not raise; returncode 1 from git config --get means "not set"

3. **resolve_forge_path() -> str**:
   - Try shutil.which('forge') first
   - If None (forge not on PATH): fall back to sys.executable + ' -m forge'
     (construct as list: [sys.executable, "-m", "forge", "gate-check"])
   - Validate resolved path exists and is executable: os.access(path, os.X_OK)
     for the single-executable case. For python -m case, validate sys.executable.
   - Raise RuntimeError if neither method produces a valid executable path
   - Return the absolute path string that will be embedded in the hook
   - The hook template must handle both cases:
     a. Single executable: exec /path/to/forge gate-check
     b. Python module: exec /path/to/python3 -m forge gate-check

4. **generate_hook_content(forge_invocation: str, chain_path: Path | None) -> str**:
   - Returns the shell script content for the pre-commit hook
   - If chain_path is not None (existing hook backed up):
     ```sh
     #!/bin/sh
     # Forge pre-commit gate-check (installed by forge install-hooks)
     # Chained existing hook: {chain_path}
     "{chain_path}" "$@" || exit 1
     exec {forge_invocation} gate-check
     ```
   - If chain_path is None (no existing hook):
     ```sh
     #!/bin/sh
     # Forge pre-commit gate-check (installed by forge install-hooks)
     exec {forge_invocation} gate-check
     ```
   - forge_invocation is already the absolute path from resolve_forge_path()

5. **run_install_hooks(args=None, env=None, cwd=None, stdout=None, stderr=None) -> int**:
   Main entry point called from cli.py. Returns EXIT_PASS (0) or EXIT_FAIL (1).

   Flow:
   a. Check core.hooksPath override:
      - If set: print error to stderr: "core.hooksPath is set to '{value}'. "
        "forge install-hooks cannot install to a custom hooks path. "
        "Add 'exec /path/to/forge gate-check' to your pre-commit hook manually."
      - Return 1 (abort).

   b. Resolve hooks directory via git rev-parse --git-path hooks.

   c. Check for .pre-commit-config.yaml in repo root:
      - If exists: print warning to stderr: "pre-commit framework detected. "
        "forge hook will chain after existing hooks."

   d. Resolve forge absolute path.

   e. Check for existing pre-commit hook:
      - hooks_dir / "pre-commit" exists?
      - If yes: check if it is already a forge-generated hook by reading the
        first 3 lines for the string "forge gate-check". If so, this is a
        re-install (idempotent): skip backup, overwrite in place, print
        "forge: re-installing hook (existing is forge-generated)".
      - If existing hook is NOT forge-generated: back up to
        hooks_dir / "pre-commit.forge-backup" (shutil.move, not copy).
        If backup target already exists, it was from a previous non-forge
        hook -- preserve it by NOT overwriting (the original backup is
        more valuable than a stale forge backup).

   f. Generate hook content (with or without chain).

   g. Write hook file (hooks_dir / "pre-commit").

   h. chmod 0o755 on the hook file (make executable).

   i. Print success message to stderr:
      "forge: pre-commit hook installed at {hook_path}"
      If chained: "forge: existing hook backed up to {backup_path}"

   j. Return 0 (EXIT_PASS).

   Error handling: any exception in steps b-h -> print error to stderr,
   return 1 (EXIT_FAIL). Never raise to caller.

All subprocess calls use list args (never shell=True) following runner.py pattern.

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| git rev-parse output -> Path | Git command output used to determine filesystem write target |
| shutil.which -> hook content | Resolved path embedded into executable script |
| existing hook -> backup | Existing hook file moved before replacement |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-03-01 | Tampering | Hook file overwrite | mitigate | Backup existing hook to .forge-backup before writing; never silently overwrite |
| T-03-02 | Tampering | forge path injection in hook | accept | shutil.which returns absolute path; if forge is compromised, the system is already compromised |
| T-03-03 | Denial of Service | core.hooksPath misdirection | mitigate | Abort with error when core.hooksPath is set; do not write to wrong directory |
| T-03-04 | Tampering | Hardcoded .git/hooks bypasses worktree | mitigate | Use git rev-parse --git-path hooks; handles worktrees, submodules correctly |
</threat_model>
