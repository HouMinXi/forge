  <action>
Restructure _build_parser() to use argparse subparsers per D-01. Specific changes:

1. Create subparsers via parser.add_subparsers(dest='subcommand'). Do NOT set
   required=True (Python 3.7+ changed the default; we need None when bare forge
   is invoked for backward compat per RESEARCH.md Pitfall 1).

2. Create three subparsers:
   a. 'review' -- move ALL existing flags (--mode, --baseline, --head, --registry,
      --state-dir, --max-total-rounds, --max-fix-attempts, --quiet, --staged,
      --falsification-engine, --sandbox, paths positional) onto this subparser.
      Keep the existing help text for each flag.
   b. 'gate-check' -- minimal flags: no args needed (config comes from gate.yaml).
      Add only --quiet flag (for message suppression).
   c. 'install-hooks' -- minimal flags: no args needed.
      Add only --quiet flag.

3. Keep --version on the ROOT parser (not on subparsers) so `forge --version` works.

4. In main(), after parse_args():
   - If args.subcommand is None: set args.subcommand = 'review' (backward compat).
     This ensures `forge a.py b.py` still works: argparse sees no subcommand
     (a.py is not review/gate-check/install-hooks), main() defaults to 'review',
     and the positional paths are on the review subparser. BUT argparse won't
     parse positional args for a subparser that wasn't explicitly selected.
     Fix: use parse_known_args() on the root parser first. If no subcommand is
     recognized, re-parse with ['review'] + sys.argv[1:] to route positional
     args to the review subparser. This preserves `forge a.py` backward compat.
   - Route: 'review' -> existing _run(args, env, cwd), 'gate-check' -> placeholder
     that prints "gate-check not yet implemented" and returns EXIT_CLI_ERROR,
     'install-hooks' -> placeholder that prints "install-hooks not yet implemented"
     and returns EXIT_CLI_ERROR.

5. The _run() function, _run_hold_loop(), _build_baseline_specs(), _paths(), and
   _emit_ci_output() are UNCHANGED. Only _build_parser() and main() change.

CRITICAL: the existing forge behavior (all flags, all pipeline steps) MUST remain
identical when invoked as `forge` (no subcommand) or `forge review`. This is a
pure routing refactor for review, with stub routing for the two new subcommands.

Do NOT add gate-check or install-hooks logic here -- those are Plan 02 and Plan 03.
