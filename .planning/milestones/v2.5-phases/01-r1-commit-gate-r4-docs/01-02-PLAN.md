  <action>
Create src/forge/gate_check.py with these components, all as pure functions with
injected dependencies for testability (following mode_resolver.py pattern):

1. **load_gate_config(config_path, fs_open=open)** -> dict:
   - yaml.safe_load the gate.yaml file
   - Validate required keys: test.command (must be list), test.env (dict or absent),
     test.timeout_seconds (int or absent, default 120), test.cwd (str or absent,
     default "."), test.source_patterns (list or absent, default [])
   - Raise ValueError on missing/invalid fields with clear error messages
   - Raise FileNotFoundError if config_path does not exist

2. **validate_command_safety(command: list[str])** -> None:
   - command must be a non-empty list
   - command[0] must be in KNOWN_RUNNERS = {"python3", "python", "pytest", "cargo",
     "go", "make", "npm", "npx", "node"}
   - No element may contain shell metacharacters: |;&$><`
   - Raise ValueError on any violation

3. **is_ci_mode(env: Mapping[str, str]) -> bool**:
   - Return True if ANY of these env vars is set and non-empty:
     FORGE_MODE (case-insensitive == "ci"), CI, GITHUB_ACTIONS, GITLAB_CI,
     JENKINS_URL, BUILD_URL
   - This extends mode_resolver.py's resolve_mode() -- gate-check needs a simpler
     boolean "am I in CI?" check that also considers platform vars (EC-4)

4. **match_source_patterns(staged_files: list[str], patterns: list[str]) -> bool**:
   - Use fnmatch.fnmatch to check if ANY staged file matches ANY pattern
   - Empty patterns list -> return True (run tests on everything)
   - Empty staged_files -> return False (no source changes, skip tests)

5. **load_test_baseline(baseline_path, fs_open=open) -> dict | None**:
   - json.load the test_baseline.json
   - Return None if file does not exist (bootstrap case)
   - Raise ValueError on invalid JSON or missing schema_version

6. **compute_baseline_delta(test_output: str, baseline: dict | None) -> tuple[bool, list[str]]**:
   - Parse pytest -q output to extract test names and pass/fail status
   - If baseline is None: return (False, []) -- no baseline = allow (bootstrap)
   - Compare current results against baseline["test_results"]:
     - A test in baseline that was "passed" but now fails -> NEW failure -> block
     - A test NOT in baseline that fails -> NEW failure -> block
     - A test NOT in baseline that passes -> not a failure (fold into baseline)
     - A test in baseline that was "failed" (known_failures) and still fails -> not new
   - Return (should_block: bool, new_failure_names: list[str])

7. **translate_exit_code(test_returncode: int) -> int**:
   - 0 -> 0 (allow)
   - 1 -> 1 (BLOCK -- real test failure)
   - 2, 3 -> 0 (allow + stderr warning emitted by caller)
   - 4 -> 1 (BLOCK -- usage error = misconfigured command)
   - 5 -> 1 (BLOCK -- no tests collected with source in diff = toothless gate)
   - timeout or >5 -> 1 (BLOCK)
   This is a PURE FUNCTION. It returns hook exit codes (0 or 1 only).

8. **run_gate_check(args=None, env=None, cwd=None, stdout=None, stderr=None) -> int**:
   The main entry point called from cli.py. Returns EXIT_PASS (0) or EXIT_FAIL (1).
   NEVER returns EXIT_CLI_ERROR (2) -- that would be mistranslated by a hook.

   Flow:
   a. FAIL-OPEN guard (try/except around all config/parse):
      - load_gate_config() -- raises on missing/parse
      - validate_command_safety() -- raises on unsafe
      - load_test_baseline() -- OK if None (bootstrap)
      On ANY exception: print error to stderr, return 1 (BLOCK). This is the
      FAIL-OPEN guard (SPEC v3.2 round-3 finding). Config errors BLOCK, never warn.

   b. Check FORGE_SKIP_TESTS:
      - If env.get("FORGE_SKIP_TESTS") == "1" AND NOT is_ci_mode(env):
        print warning to stderr, return 0 (allow). (EC-4: CI ignores skip)
      - If is_ci_mode(env) AND FORGE_SKIP_TESTS is set:
        print "CI mode: FORGE_SKIP_TESTS ignored" to stderr.

   c. Get staged files via git diff --cached --name-only (subprocess, list args).
      If match_source_patterns() returns False: print "no source files staged,
      skipping tests" to stderr, return 0.

   d. Run test command via subprocess.run():
      - command = config["test"]["command"]
      - env = {**os.environ, **config["test"].get("env", {})}
      - timeout = config["test"].get("timeout_seconds", 120)
      - cwd = config["test"].get("cwd", ".")
      - capture_output=True, text=True, check=False
      - On subprocess.TimeoutExpired: print timeout error, return 1 (BLOCK)

   e. Translate exit code via translate_exit_code().
      - If test exit 2 or 3: print to stderr:
        "forge: warning: tests exited with code {code} ({reason}); allowing commit"
        where reason = "keyboard interrupt" for 2, "internal error" for 3.
      - If translated to BLOCK (1) AND test_returncode == 1 (real test failure):
        check baseline delta -- if all failures are known (in baseline),
        downgrade to allow (0) + warning. If any NEW failure: BLOCK (1) +
        print new failure names.
      - If translated to BLOCK (1) AND test_returncode in (4, 5, timeout, >5):
        BLOCK immediately, do NOT check baseline delta. Exit 4/5 are pipeline
        problems (misconfigured command / no tests collected), not test
        failures -- baseline delta is irrelevant.

   f. Return translated exit code (0 or 1).

CRITICAL CONSTRAINT: run_gate_check MUST return only 0 or 1. NEVER 2 (EXIT_CLI_ERROR).
If the function returned 2, and the pre-commit hook propagated it, the hook's own
exit-code translation would treat 2 as "allow+warn" (test exit 2 semantics), causing
FAIL-OPEN on config errors. This is the core FAIL-OPEN guard.

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| gate.yaml -> gate_check.py | YAML config parsed from filesystem; attacker could craft malicious command |
| test.command -> subprocess.run | User-controlled command list executed as subprocess |
| env vars -> CI detection | Environment variables used for security-relevant mode decision |
| test_baseline.json -> delta | JSON baseline data from filesystem |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-02-01 | Tampering | test.command in gate.yaml | mitigate | validate_command_safety: known_runners allowlist + metachar rejection; subprocess.run with list args, never shell=True |
| T-02-02 | Security Feature Bypass | FAIL-OPEN on config error | mitigate | run_gate_check returns only 0 or 1; config/parse errors caught in try/except -> return 1 (BLOCK); NEVER return 2 (EXIT_CLI_ERROR) |
| T-02-03 | Security Feature Bypass | FORGE_SKIP_TESTS in CI | mitigate | is_ci_mode() check: CI mode ignores FORGE_SKIP_TESTS; tests always run in CI |
| T-02-04 | Tampering | test_baseline.json manipulation | accept | Local dev tool; baseline is gitignored generated data; attacker with filesystem access already has full control |
| T-02-05 | Elevation of Privilege | subprocess.run command injection | mitigate | List args (never shell=True) + metacharacter rejection + known_runners allowlist per runner.py security pattern |
</threat_model>
