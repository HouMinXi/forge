# Phase 24-03: Corpus Round-Trip Test

## Objective

Write tests/test_schema_corpus.py -- a pytest module that validates every
corpus snippet against BOTH gate.schema.json (via jsonschema) AND the real
loader (load_backend_configs / load_gate_config). Valid snippets must pass
both. Invalid snippets must fail the loader. Loader-only constraints (those
the schema cannot enforce) are declared in $comment fields in the schema and
tested against the loader separately. This test is the anti-drift teeth that
justify shipping gate.schema.json.

This plan is logic-bearing Python. It requires three-cycle review and a smoke
test before commit.

## Tasks

### Task 1: Write the corpus round-trip test module

**Files:**
- `tests/test_schema_corpus.py`

**What:**

Create a new pytest file. Structure:

**Imports and setup:**
```python
import importlib.resources
import json
import tempfile
import pathlib
# yaml not imported -- yaml_text strings are constructed as Python string literals
# and written via tempfile; the loaders parse YAML internally.
import jsonschema
from jsonschema import Draft202012Validator
from code_forge.backend import load_backend_configs
from code_forge.gate_check import load_gate_config
from code_forge.outlet_resolver import resolve_outlet
from code_forge.errors import CliError
```

Load gate.schema.json at module level:
```python
_SCHEMA_TEXT = importlib.resources.files('code_forge').joinpath('gate.schema.json').read_text(encoding='utf-8')
SCHEMA = json.loads(_SCHEMA_TEXT)
```
(always pass encoding='utf-8' for deterministic decoding).

Use `pathlib.Path` and `tempfile.mkstemp` (not deprecated `mktemp`) for loader
tests that need a file path.

Ensure `pip install -e ".[dev]"` has been run so importlib.resources resolves
to the worktree src AND dev dependencies (including jsonschema>=4.18) are
installed (same prerequisite as 24-02 -- must include [dev]).
Verify: `python3 -c "import code_forge; print(code_forge.__file__)"` must
print a path inside `.worktrees/onboarding-step1/src/`.

Also check that `[tool.pytest.ini_options].pythonpath` includes `src` in
pyproject.toml (already present -- verified before writing tests).

Define a shared constant for tests requiring a full gate.yaml with test section:
```python
VALID_YAML_WITH_TEST = """
test:
  command: [pytest, -q]
  timeout_seconds: 60
"""
```
Use this string wherever `_loader_accepts` needs a complete yaml (e.g.,
`valid_presubmit_diff` and `invalid_presubmit_on_message`).

**Helper: `_schema_validate(doc: dict) -> None`**
Runs Draft202012Validator(SCHEMA).validate(doc). Raises jsonschema.ValidationError
on failure. No return value.

**Helper: `_loader_accepts(yaml_text: str) -> bool`**
Writes yaml_text to a temporary file, calls load_gate_config on it, returns True
if no exception. Catches ValueError and returns False. Does NOT catch
FileNotFoundError (that would mask a path bug).

**Helper: `_backends_accept(data: dict) -> bool`**
Calls load_backend_configs(data), returns True if no exception. Catches
CliError (from code_forge.errors) and returns False.

**Corpus: VALID snippets (schema passes AND loader passes):**

Each snippet is a dict and its yaml-text equivalent (or just a dict for
backends-only tests). Name them clearly. Cover:

1. `valid_empty` -- `{}` (all optional, no test section, no backends).
   Schema: passes. Loader (backends): load_backend_configs({}) == [].

   (b) `cfgs = load_backend_configs(data); assert len(cfgs) == 1 and cfgs[0].type == "api" and cfgs[0].format == "anthropic"`
   (call load_backend_configs directly, not _backends_accept, to verify attributes)

3. `valid_api_openai` -- single api backend, format openai, generic name

4. `valid_api_vertex` -- single api backend, format vertex, generic name

   Schema: passes.

8. `valid_outlet_subagent` -- `{"outlet": "subagent"}`.
   Schema: passes.

9. `valid_non_ascii_strict` -- `{"non_ascii": "strict"}`.
   Schema: passes.
   Loader: Assert _loader_accepts(VALID_YAML_WITH_TEST + "\nnon_ascii: strict\n") is True.

10. `valid_graph_triage_enabled` -- `{"graph_triage": {"enabled": True}}`.

**Corpus: INVALID snippets (loader MUST reject; schema may or may not reject):**

For each, assert that the loader raises the expected error type.

1. `invalid_backends_as_list` -- `{"backends": [{"name": "x", "type": "api"}]}`.
   Loader: load_backend_configs raises CliError ("backends must be a dict").
   Schema note: schema defines backends as object, so schema also rejects.
   Assert: _backends_accept(data) is False.

2. `invalid_api_missing_format` -- backends dict, one entry type="api", no format.
   Loader: CliError ("missing required field 'format'").
   Assert: _backends_accept(data) is False.

3. `invalid_api_missing_base_url` -- type="api", format="anthropic", api_key_env set,
   no base_url.
   Loader: CliError ("missing required field 'base_url'").
   Assert: _backends_accept(data) is False.

4. `invalid_api_missing_api_key_env` -- type="api", format="openai", base_url set,
   no api_key_env.
   Loader: CliError ("missing required field 'api_key_env'").
   Assert: _backends_accept(data) is False.

5. `invalid_vertex_missing_project_id` -- type="api", format="vertex", no project_id.
   Loader: CliError ("missing required field 'project_id'").
   Schema: also rejects (allOf condition for format="vertex" requires project_id).
   Assert BOTH: _schema_validate({"backends": {"v": {"type": "api", "format": "vertex"}}})
   raises jsonschema.ValidationError AND _backends_accept(data) is False.

6. `invalid_multiple_defaults` -- two backends both with default: true.
   Loader: CliError ("multiple default backends").
   Assert BOTH: _schema_validate(doc) does NOT raise (schema cannot enforce
   cross-item cardinality -- this verifies the $comment boundary documented in
   gate.schema.json) AND _backends_accept(data) is False.
   This test also covers the `loader_only_multiple_defaults` case; the two are
   merged because they share the same data. No separate loader-only test function
   needed for this constraint.

7. `invalid_inline_api_key` -- backends entry contains `api_key` field (raw secret).
   Schema: also rejects (backend entry has additionalProperties: false, per 24-01
   schema design decision -- loader explicitly rejects api_key at backend.py:102-106,
   so it is NOT a forward-compat case).
   Loader: CliError ("store the env-var NAME in api_key_env").
   Assert: both _schema_validate raises AND _backends_accept returns False.

8. `invalid_test_command_string` -- test.command is a string, not a list.
   Loader: load_gate_config raises ValueError ("must be a list").
   Use yaml_text with a test section (gate_check.py:63 requires test section):
   ```python
   yaml_text = "test:\n  command: 'pytest'\n  timeout_seconds: 60\n"
   ```
   Assert: _loader_accepts(yaml_text) is False.

9. `invalid_test_command_empty` -- test.command is [].
   Loader: ValueError ("cannot be empty").
   Use yaml_text with a test section:
   ```python
   yaml_text = "test:\n  command: []\n  timeout_seconds: 60\n"
   ```
   Assert: _loader_accepts(yaml_text) is False.

10. `invalid_non_ascii_bad_value` -- non_ascii="unicode".
    Loader: ValueError ("must be 'ai-smell' or 'strict'").
    Use yaml_text built from VALID_YAML_WITH_TEST (test section required for
    gate_check to reach the non_ascii validator):
    ```python
    yaml_text = VALID_YAML_WITH_TEST + "\nnon_ascii: unicode\n"
    ```
    Assert: _loader_accepts(yaml_text) is False.

11. `invalid_presubmit_on_message` -- presubmit entry with on="message".
    Schema: also rejects (enum ["diff","patch"] excludes "message").
    Loader: ValueError starting with "presubmit entry 'on: message' not yet supported"
    (gate_check.py:381). Use yaml_text built from VALID_YAML_WITH_TEST:
    ```python
    yaml_text = VALID_YAML_WITH_TEST + "\npresubmit:\n  - command: [ruff, check]\n    applies_to: '*.py'\n    on: message\n"
    ```
    Assert BOTH: _schema_validate({"presubmit": [{"command": ["ruff"], "applies_to": "*.py", "on": "message"}]}) raises
    AND _loader_accepts(yaml_text) is False.

12. `invalid_test_timeout_zero` -- test.timeout_seconds = 0.
    Schema: also rejects (test.timeout_seconds has minimum:1; value 0 violates it).
    Loader: ValueError ("'test.timeout_seconds' must be positive") (gate_check.py:86).
    Assert BOTH:
    ```python
    _schema_validate({"test": {"command": ["pytest"], "timeout_seconds": 0}})
    # raises jsonschema.ValidationError (minimum: 1 violated)
    yaml_text = "test:\n  command: [pytest]\n  timeout_seconds: 0\n"
    assert _loader_accepts(yaml_text) is False

13. `invalid_backend_missing_type` -- backend entry with no `type` field.
    Schema: rejects (backend entry has global `required: ["type"]`).
    Loader: CliError (loader requires type as discriminator).
    Assert BOTH: _schema_validate({"backends": {"noType": {"format": "openai"}}}) raises
    jsonschema.ValidationError AND _backends_accept({"backends": {"noType": {"format": "openai"}}}) is False.
    This test locks the global required: ["type"] constraint on backend entries.

14. `invalid_presubmit_missing_required` -- three parametrized presubmit entry cases,
    each missing one required field (command, applies_to, on).
    Schema: rejects each (presubmit items schema requires command, applies_to, on).
    Note: use pytest.mark.parametrize since these are structurally identical cases.
    ```python
    @pytest.mark.parametrize("entry,_missing_field", [
        ({"applies_to": "*.py", "on": "diff"}, "command"),
        ({"command": ["pytest"], "on": "diff"}, "applies_to"),
        ({"command": ["pytest"], "applies_to": "*.py"}, "on"),
    ])
    def test_invalid_presubmit_missing_required(entry, _missing_field):
        # _missing_field is the parametrize id (unused in body per Python convention)
        with pytest.raises(jsonschema.ValidationError):
            _schema_validate({"presubmit": [entry]})
    ```
    This test ensures the schema's required: [command, applies_to, on] on presubmit
    items is actually enforced (schema/loader divergence if implementer forgets it).

**Loader-only constraint tests (schema uses $comment; tested against loader separately):**

These are constraints the schema cannot enforce mechanically. Group under:
`# Loader-only constraints: schema uses $comment, loader enforces.`

Note: `invalid_inline_api_key` (above) is NOT loader-only -- schema also rejects
it because backend entry uses `additionalProperties: false`.

1. `loader_only_outlet_cli_alias` -- `{"outlet": "cli"}`.
   Schema: raises ValidationError (cli is not in the enum ["subprocess","inline","subagent"]).
   Loader: `resolve_outlet(env={}, cli_value="cli")` returns "subprocess" (deprecated alias,
   maps via outlet_resolver.py:53 _DEPRECATED_OUTLET_ALIASES dict, emits stderr warning).
   Pre-execution: verify signature with:
   ```bash
   python3 -c "import inspect; from code_forge.outlet_resolver import resolve_outlet; print(inspect.signature(resolve_outlet))"
   ```
   Assert ALL THREE:
   (a) `_schema_validate({"outlet": "cli"})` raises jsonschema.ValidationError
   (b) `resolve_outlet(env={}, cli_value="cli") == "subprocess"`
   (c) `_loader_accepts(VALID_YAML_WITH_TEST + "\noutlet: cli\n") is True`
       (load_gate_config does NOT validate the outlet field at all -- gate_check.py
       ignores outlet entirely. Assertion (c) passes because the unknown outlet
       value is silently ignored by load_gate_config, NOT because cli is resolved
       as an alias. The alias resolution happens in resolve_outlet, tested by (b).
       Assertion (c) documents that load_gate_config is outlet-agnostic.)
   This test locks the known schema/loader divergence for the deprecated cli alias.

**Test function structure:**

Each valid snippet: one pytest function named `test_valid_<name>` that calls
`_schema_validate(doc)` (must not raise) and the appropriate loader helper
(must return True or return a non-empty list).

Each invalid snippet: one pytest function named `test_invalid_<name>` that
asserts the loader helper returns False (or raises the specific exception
type using pytest.raises).

Do NOT use pytest.mark.parametrize for the full corpus -- each case must be
individually named for readable failure output. Parametrize is acceptable only
for groups of structurally identical cases (e.g., the three cases in
item 14 invalid_presubmit_missing_required -- all test the same required-field
pattern on presubmit entries). Items 6/7/8 (valid outlet values) are individually
named functions even though structurally similar -- named for clarity.
