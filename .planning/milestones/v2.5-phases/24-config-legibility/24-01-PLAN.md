**What:**

Replace GATE_YAML_TEMPLATE in its entirety. The new template must:

1. Open with `# yaml-language-server: $schema=./gate.schema.json` as the
   first non-blank line so offline IDE schema resolution works (E6).

2. Document `outlet:` with all three canonical values and their meanings:
   - `subprocess` (default) -- fresh claude subprocess per pass
   - `inline` -- review runs in the current session
   - `subagent` -- fresh Agent per pass
   Note that `cli` is a deprecated alias for `subprocess` (emits a stderr

   keep it verbatim).

4. Document the `backends:` block as a DICT keyed by name -- NOT as a list.
   The backends in the template must use GENERIC names only:

   CRITICAL: vertex-claude must be type: api, format: vertex -- NOT type: cli.
   Current template may show vertex as cli; fix it. Ground truth: backend.py
   api fields include format in {anthropic, openai, vertex} -- vertex is api.

5. For every commented-out optional field, include a "# Defaults to X" or
   "# omit = <behavior>" annotation on the same or next comment line.

6. Cover all loader-recognized fields with comments: for `test:` --
   command (list, required), timeout_seconds (int > 0, default 120),
   env (dict), cwd (str), source_patterns (list); for `non_ascii:` --
   valid values ai-smell (default) and strict; for `presubmit:` --
   each entry fields command (list), applies_to (glob), on (diff|patch),
   when_exists (str, optional); for `graph_triage:` and `daemon_state:` --
   enabled (bool) and their optional sub-fields as documented in
   gate_check.py validators.
   IMPORTANT: the current template (init_template.py:71) has `# pattern: "*.py"`.
   This field is NOT read by the loader -- only `source_patterns` is read
   (gate_check.py:91). Explicitly REMOVE the `pattern:` commented example and
   REPLACE it with `# source_patterns: ["*.py"]`. Zero occurrences of `pattern:`
   must remain in the template (verified by E2 post-check below).

7. The all-commented form (no uncommented fields except the schema directive)
   must parse gracefully: yaml.safe_load returns None (not a dict -- this is
   normal Python yaml behavior for an all-comment document), which the E2
   verification handles via `load_backend_configs(data or {})`. The shipped
   template should have at least `outlet: subprocess` uncommented so
   yaml.safe_load returns a dict with one key.

Write `src/code_forge/gate.schema.json` as a new file. It must conform to
JSON Schema draft-2020-12 (`"$schema": "https://json-schema.org/draft/2020-12/schema"`).
It must describe the full gate.yaml top-level structure:
Set `"additionalProperties": true` at the top level of the schema so unknown
keys (e.g., future fields not yet in the schema) are accepted rather than
rejected. The gate.yaml loader ignores unknown top-level keys; the schema
should match that permissive behavior.

- `outlet`: enum of ["subprocess", "inline", "subagent"] with descriptions.
  Do NOT include "cli" as a valid enum value (it is a deprecated alias the
  loader accepts, not a documented value).
- `backends`: object (`additionalProperties` = backend entry subschema).
  Each backend entry uses `allOf` with independent `if/then` pairs. JSON Schema
  draft-2020-12 does NOT define behavior for multiple `if` keywords at the same
  schema level (implementations may silently ignore all but the last). Use `allOf`
  to express each condition as a separate, unambiguous pair:
  ```json
  "allOf": [
    {
      "if": {"properties": {"type": {"const": "api"}}, "required": ["type"]},
      "then": {"required": ["format"]}
    },
    {
      "if": {
        "properties": {"type": {"const": "api"}, "format": {"enum": ["anthropic", "openai"]}},
        "required": ["type", "format"]
      },
      "then": {"required": ["base_url", "api_key_env"]}
    },
    {
      "if": {
        "properties": {"type": {"const": "api"}, "format": {"const": "vertex"}},
        "required": ["type", "format"]
      },
      "then": {"required": ["project_id"]}
    }
  ]
  ```
  Each `if` must include `required: [...]` for the discriminator fields. Without
  `required`, JSON Schema's `properties` only validates PRESENT fields -- a missing
  `type` satisfies any `if { type: X }` check, causing incorrect `then` application.
  This is the only correct approach: putting `format` in global required would
  break type=cli backends; omitting required on if-conditions lets invalid entries
  pass schema silently.
  Backend entry level: `"additionalProperties": false` -- the loader explicitly
  rejects `api_key` (backend.py:102-106 raises CliError), so unknown keys are
  not forward-compat here.
  Backend entry level ALSO requires `"required": ["type"]` at the top level of
  each entry subschema (NOT inside allOf conditions). Without this global required,
  a backend entry missing `type` entirely would pass schema (no allOf condition
  matches without type present) but be rejected by the loader -- schema/loader
  divergence. The loader (backend.py) always requires `type` as a discriminator.
  The allOf conditions handle conditional requirements GIVEN type is present; this
  global required ensures type must always be present.
  CRITICAL: with `additionalProperties: false`, every loader-accepted field must
  appear in `properties` or the schema will reject valid configs. Declare ALL
  known backend entry fields with their correct types:
  - `type`: enum ["api","cli"] (required globally -- enforced by required:["type"])
  - `format`: enum ["anthropic","openai","vertex"] (optional; api-only in practice)
  - `command`: string (cli backend -- the claude binary path)
  - `model`: string (optional)
  - `max_tokens`: integer, minimum:1 (NOT string -- a valid config uses 4096 etc.)
  - `base_url`: string (api backends with anthropic/openai format)
  - `api_key_env`: string (api backends with anthropic/openai format)
  - `project_id`: string (vertex backends)
  - `region`: string (vertex backends, optional)
  - `credentials_path`: string (vertex backends, optional)
  - `default`: boolean (optional, marks the default backend)
  Note: there is NO `name` field inside backend entries (the dict key IS the name).
  Using `additionalProperties: false` correctly rejects any `name:` subkey.
  Adding `enum` constraints to `type` and `format` ensures invalid values
  (e.g. type="foo") are rejected by schema, not just by the loader.
  Use top-level `$comment` to document loader-only constraints:
  (a) "at most one entry may set default: true (cross-item, enforced by loader)".
  (b) "outlet value 'cli' is a deprecated alias for 'subprocess'; intentionally
      excluded from this enum because it is not a canonical value. Note: load_gate_config
      does NOT validate the outlet field (gate_check.py ignores it); alias resolution
      happens via resolve_outlet (outlet_resolver.py:53 _DEPRECATED_OUTLET_ALIASES)
      called from the cli runtime path, not from the config loader".
  Note: `api_key` is rejected by BOTH schema (additionalProperties: false) and
  loader -- NOT a loader-only constraint.

- `test`: object with `command` (array of strings, `minItems: 1`, required),
  `timeout_seconds` (integer, `minimum: 1`), `env` (object), `cwd` (string),
  `source_patterns` (array of strings).
  Use `"additionalProperties": true` -- the loader ignores unknown keys like the
  legacy `pattern` field rather than rejecting them.

- `non_ascii`: enum ["ai-smell", "strict"].

- `presubmit`: array of objects, each with `command` (array of strings,
  `minItems: 1`, required), `applies_to` (string, required),
  `on` (enum ["diff", "patch"], required), `when_exists` (string, optional).
  Use `"additionalProperties": true` for presubmit entries -- the loader injects
  internal fields (e.g. `applies_to_grep`) when processing entries; setting
  false would cause schema/loader divergence.
  Note: "on: message" is rejected by BOTH schema (enum ["diff","patch"] excludes
  "message") AND loader (gate_check.py:381). This is NOT a loader-only constraint.

- `graph_triage`: object with `enabled` (boolean), `db_path` (string).
  Use `"additionalProperties": true` for forward compat.

- `daemon_state`: object with ALL fields optional (loader uses defaults when absent):
  `enabled` (boolean, optional), `subsystems` (array of strings, optional),
  `patterns` (array of strings, optional), `conflicts` (array of objects, optional),
  `conflicts_file` (string, optional).
  No top-level daemon_state field is required -- the entire section itself is optional.
  Only the nested `conflicts[i]` entry's three keys (`subsystem`, `mutates`,
  `interferes_with`) are required (by the loader at gate_check.py:214-229).
  Use `"additionalProperties": true` for forward compat on the parent
  `daemon_state` object (new top-level keys may appear in future versions).
  For the nested `conflicts[i]` entry objects: use `"additionalProperties": true`
  (loader does not reject unknown keys) AND `required: ["subsystem", "mutates",
  "interferes_with"]` (loader DOES reject missing required keys -- without this
  required list, a conflict entry missing any of the three keys would pass schema
  but fail the loader, creating schema/loader divergence).
