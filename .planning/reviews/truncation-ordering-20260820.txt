# Review: fix/anthropic-truncation-ordering (truncation-before-extraction)

Date: 2026-08-20. Reviewer: independent agent, fresh context (round 1).
Commit under review: b4022a3 (llm/truncation: decide anthropic-style
truncation before text extraction). Base main@60336c9.

Origin: T6 human checkpoint (Phase 54) found doctor --live reporting
mimo-pro as "unclassified -- unexpected response structure" roughly 2
of 5 runs. Live experiment: 5 identical probe-shaped requests to
mimo-v2.5-pro (anthropic surface, max_tokens=32) returned
stop=max_tokens + thinking-only content 2/5 times. Root cause:
text-block extraction ran before the stop_reason check, so
budget-exhaustion-by-reasoning was misreported as a structure error.

Bug-injection: proven per site. Disabling the hoisted check at the
anthropic site (sed `if False and`) -> 2 anthropic tests FAIL
(new thinking-only test + pre-existing max_tokens test), vertex 12/12
wait 10/12 pass; same at vertex site symmetrically. Restored, 12/12
pass. Full suite 3545 passed / 0 failed.

## Round 1 findings

P1 (REQUEST_CHANGES): hoisted unconditional resp_data.get(...) calls
(llm_invoke.py anthropic ~1843-1844, vertex ~2025-2026) crash on
non-dict 200-bodies. _parse_response_body returns whatever json.loads
produces; a top-level list/string/number/null body previously hit the
extraction try's TypeError/KeyError and was classified as
LLMInvokeError("unexpected response structure"), but now raises a raw
AttributeError that escapes _invoke_api's LLMInvokeError-only retry
loop and probe_backend_live's handler (doctor crashes instead of
reporting). Reviewer demonstrated experimentally: list body, string
body, 42 body, null body -> AttributeError; {"content": 5,
stop_reason: max_tokens} -> TypeError from the comprehension. Also
noted: content=5 + max_tokens inside a dict is NOT covered by an
isinstance(resp_data, dict) guard alone (iterating 5 still TypeErrors).

Remedy adopted: isinstance(resp_data, dict) gate on the hoisted block
+ isinstance(raw_blocks, list) guard on the partial extraction;
non-dict bodies fall through to the unchanged extraction failure.

Categories 2 (end_turn contract), 3 (dead code), 4 (downstream
consumers incl. probe -> truncated-output classification), 6
(non-truncating backends): CLEAN, experimentally verified by reviewer
against the pre-change baseline.

P3 gaps accepted (not blocking): (a) no test for content missing/null
+ max_tokens (collapses into the same or-[] path); (b) no
probe_backend_live e2e test mocking a thinking-only anthropic response
-- the llm_invoke fix -> classification wiring was only established by
tracing; added in round 1 rework (see below).

Verdict round 1: REQUEST_CHANGES (1 P1).
