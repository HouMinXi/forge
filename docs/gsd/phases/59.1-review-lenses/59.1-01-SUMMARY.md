- Conflict rule with plans 59-06 and 59-08: if either changes the same prompt builders or `_make_subagent_spawn`, the byte-identity oracles decide; rebase the lens parameters onto their change and rerun the oracles. Lens work never relaxes an oracle.
- The new Outlet C oracle test and a `**keywords` wrapper in `tests/test_kernel_context_integration.py` were needed to keep the C spawn contract observable; the latter file is outside the plan's file list.
- One warning-string test was adjusted with `startswith` for the new lens warning text. The original `trust` and `trust --status` stderr wording is unchanged for a gate.yaml that never mentions lenses; the lens status lines print only when `review_lenses` is present or a lens hash is stored.
- `scripts/capture_l1_digests.py` was ruff-formatted, so its diff is larger than the logical change.
- An unknown-pass guard was added in the C spawn.
- The repository's ledger lint rejected the staged code-forge SKILL.md because of 12 pre-existing open `- [ ]` checklist lines in the base file. By the owner's decision each of those 12 lines now ends with `-- judge: pre-existing base checklist item, not part of the review-lens change`; no other wording changed and nothing was bypassed.
- `lenses.lens_of` and `lenses.lens_mismatch` from the spec were dropped as unused; the tag grammar is pinned through `strip_lens_tag`, the one regexp that `machine.py` and `legacy.py` use (and the style-downgrade keyword match in `machine.py`). The spec and plan carry an erratum.
- `setup_mcp` and the eval harness record trust through `record_trust`, so they also store `lens_hash`; this is the accepted behaviour in the spec and is pinned by real calls in `tests/test_trust_lenses.py` through `setup_mcp._auto_trust_gate` and `eval.runner._trust_eval_gate`, with literal expected hashes.
- The lens bytes for the token estimate come from `lenses.estimate_lens_text`; Outlet A, Outlet C and the estimate are pinned to the same helpers in `tests/test_lens_prompts.py`; the `_run` wiring of the estimate is pinned in `tests/test_lens_wiring_ast.py`. `trust.stored_lens_hash` is now public for `trust --status`; the status branch reads the stored hash once itself, and `lens_trust_state` may read it once more, so a status run reads it at most twice.
