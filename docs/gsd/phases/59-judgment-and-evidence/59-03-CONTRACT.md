Construction copies/validates host inputs but performs no admission or dispatch; a validation fault is kept as safe recorder state for open() to return, rather than manufacturing an admitted recorder. open() automatically prepares a fresh ordinary host-controlled repository audit root, checks the supported local profile and actual owned operations, then admits a fresh run with a durable full reservation. It requires no per-repository attestation, caller-passed qualification hash/boolean or manual bootstrap. It never silently reopens an existing UUID directory. open/start/acquired/finish/finalize/set_frozen return typed faults rather than converting a sink failure into success. Programmer/type/identity rejection likewise produces a safe typed fault at the public method boundary; no unsafe repr/str fallback is serialized. snapshot/summary are read-only in-memory observations. reopen is read-only disk reconstruction, not a second writer or transfer of an active run's ownership. The thin maintenance function operates under the same root lock and does not create a daemon or central index.

admitted=True requires fault=None and the method's declared durable commit. start additionally requires a non-null host attempt UUID; an ID with admitted=False never permits dispatch. acquired may return a partial ref with admitted=False after a committed bounded prefix, but a non-durable raw/event never receives a usable ref. Other acknowledgements carry no implicit result or clean status. Audit faults normally latch audit_complete=False and refuse further start admission; later successes cannot clear that latch. The owner may still finish/finalize already admitted attempts safely to preserve evidence. The sole exception is quota_refused for a requested post-terminal unfrozen-to-frozen transition rejected BEFORE its first write: return AuditAcknowledgement(admitted=False, fault=AuditFault(quota_refused,freeze,None)), with no mutation of recorder fields (including audit_complete/faults), journal, markers, terminal/freeze state or charge. The returned acknowledgement is a safe caller-visible fault observation, not a new persisted audit event; snapshot and read-only reopen retain the prior terminal history identically. This optional transition-capacity refusal is not evidence that a prior durable audit commit failed. All other faults, including a primitive failure after freeze admission/write begins, follow the normal incomplete latch. Returning a fault does not guarantee the fault itself was writable to the failed disk.

Fault codes: invalid_input, identity_conflict, finalized, unsupported_profile, lock_timeout, quota_refused, persistence_error, integrity_error. Phases: open, start, acquired, finish, finalize, freeze, replay, maintenance. Diagnostic metadata is only code/phase/host attempt ID; caller exceptions, arbitrary messages and traceback payloads are excluded. The caller owns exception precedence: an existing transport exception is re-raised as the exact same exception object; a separate audit fault is observed safely. Successful acquired work plus mandatory audit loss becomes incomplete/nonretryable audit_persistence_error in59-05, never an accepted clean result. That exception and partial-result wiring are not implemented in59-03.

## 2. Identity, schema and replay

The context run_id and logical/attempt/observation/artifact IDs are host UUIDs. Each record owns schema_version=1, an immutable run_id and sequence, event type and a UTC timestamp. Monotonic elapsed is relative to this owner process's captured origin; nonfinite/negative elapsed is invalid. Context round_index is null or a nonnegative int excluding bool. Source hash, snapshot ID and group hash are host-bound identities. Generic standalone context has source_hash=snapshot_id=null and derived source_binding='unknown'; actual review-owned contexts require both bound. One-sided source binding, cross-run parent links, unknown finish IDs, reparenting, drift of the fixed run/source/snapshot binding or same-logical-operation context, and writes after finalization refuse. Provider-native IDs never replace host IDs or affect deduplication, admission, freezing or terminal state. parent_id is the immediate causal attempt UUID, null for a root send and otherwise an already admitted same-run attempt. Context parent_logical_id is independently the known host logical operation UUID; it never substitutes for a physical attempt. First start of a new logical_id registers its full context. The fixed run invariants are run_id/source_hash/snapshot_id from run_open and must match exactly for every start, including both-null generic source binding. Distinct new logical operations may legitimately supply different round_index/pass_name/group_id/group_diff_sha256/purpose/parent_logical_id within that same fixed run binding. A new root logical operation has parent_id=parent_logical_id=null; a new child logical operation binds parent_logical_id to the already admitted causal parent attempt's logical_id. Initial/retry attempts for an existing logical_id reuse the EXACT full nine-field context registered for it; retry may advance its immediate causal parent_id within that same logical operation, without changing its original parent_logical_id. Child correction/continuation/headroom/repair/tool operations register distinct logical IDs, not a retry rebinding. Group hash and the entire new context are validated host inputs, never model/provider authority. Copy all nine fields into every start event before acknowledgement; later caller mutation cannot alter any admitted attempt. Raw refs are not provider filenames.

Journal event vocabulary: run_open, start, acquired, finish, run_final, freeze, audit_fault. Each schema has a closed field set projected from the signatures above; unrecognized fields refuse. Common fields are schema_version/run_id/event_id/sequence/event/utc/elapsed_s. run_open contains context, observed capability, host owner identity and the fixed reservation policy. start adds context/attempt_id/logical_id/parent_id/cause/backend/request_digest/request_bytes; acquired adds attempt_id/observation_id/layer/ref/complete/usage; finish adds attempt_id/outcome/error_class/duration_s/dispatch_state; run_final adds outcome/audit_complete; freeze adds frozen; audit_fault adds the safe fault fields. Host markers contain only schema/run/owner/event identity, terminal/frozen/tombstone state and byte partition facts. Every start.context has exactly the nine InvocationContext fields, including explicit nulls, and remains inside the existing2KiB event cap; oversized context refuses before admission, never drops attribution fields. run_open.context supplies fixed run binding, not a substitute for a later start.context. No request/response dictionary can supply any marker or event type.

cause is initial, retry, correction, continuation, headroom, excerpt_repair or tool. Layer is wire, stdout, stderr or decoded. Outcome is completed, failed, refused, cancelled or incomplete. dispatch_state is not_dispatched, entered_api_send, entered_cli_launch, possibly_sent or unknown. entered_* means the owner actually entered its observable transport boundary; it does not prove provider receipt/completion or CLI-internal send count. A durable start alone proves only admission, not a send. Missing final/dispatch evidence reconstructs unknown, never guessed zero or a completed send. Terminal run state is completed, failed, cancelled or incomplete. finalize requires the owner to have settled its admitted attempts with explicit finish observations and all owned transport cleanup; no still-running child/transport may be converted to a reclaimable terminal run. An unclosed attempt remains ambiguous/full charge. completed additionally requires no latched fault.

BackendObservation has only its declared fields; format is openai, anthropic, vertex, cli or tool. Optional observed fields are untrusted labelled observations, never authority or replacements for requested settings. Host projections reject credential-bearing endpoint data; record only a host-produced SHA256 endpoint fingerprint from an explicitly credential/query-free route identity. request_digest is host SHA256 of request bytes, request_bytes is their observed length, not request content. No request body, API key, authorization header, environment, endpoint URL/query, CLI argv/environment or secret-file bytes enter metadata. String values are bounded and the entire encoded event must fit2KiB; no hidden request objects or unconstrained backend/native dictionaries are retained.

Replaying an event is idempotent by immutable host event/observation identity, not by equal numeric values or provider ID. Same identity plus identical admitted content is one event; the same identity with different content is integrity_error. acquired generates an observation UUID once when none is passed; an explicitly reused ID must be an already host-owned ID of that attempt. Equal-valued incremental observations with distinct IDs remain distinct. finish and finalize are idempotent only for identical already committed arguments; conflicting repeats refuse. Identical already committed finish/finalize calls may return their previous acknowledgement without writing. No new append occurs after durable finalization, except one bounded host transition from unfrozen to frozen under the root lock after the charge-growth admission in section5. An already committed identical freeze repeats its prior acknowledgement without appending or charging twice. A pre-write quota-denied post-terminal freeze has no admitted event identity or state change; repeating the request with unchanged inventory refuses identically, while a later explicit retry may reevaluate capacity after independently admitted maintenance changes inventory. This is a rejected transition request, not replay of an admitted freeze event. set_frozen(False) is an idempotent no-op only while unfrozen; unfreezing a frozen run refuses in this first release. Reopen retains torn journal/raw bytes unchanged and marks incomplete/ambiguous with a full reservation; it never truncates, edits or treats torn data as completed. Known closed-owner evidence may label an unclosed attempt interrupted for observation, but cannot reclaim its reservation. PID absence alone is not such evidence and never admits pruning.

Summary schema-v1 is a fixed JSON projection with: schema_version, run_id, state, audit_complete, source_binding, logical_call_count, admitted_attempt_count, observed_api_send_count, observed_cli_launch_count, unknown_dispatch_count, outcome_counts, observation_count, usage, timing, cost, fault_codes. outcome_counts has exactly completed/failed/refused/cancelled/incomplete/unknown integer keys. Unknown unclosed attempts are distinct from explicit refused/not_dispatched attempts. usage contains input_tokens/output_tokens/cached_input_tokens/reasoning_tokens; each is an object with known_subtotal:int, total:int|None, unknown_attempt_count:int, invalid_attempt_count:int. timing contains work_s:float|None, wall_s:float|None, known_work_s:float, unknown_duration_count:int. No price inference: cost is null, never zero or a current price estimate. No native counts from opaque CLI internals are fabricated. RecorderSnapshot additionally exposes attempt_contexts as an immutable host copy mapping each valid durably admitted attempt UUID to its complete InvocationContext. snapshot() and read-only reopen reconstruct the same mapping solely from admitted start records, not run_open defaults or provider fields; invalid/missing/torn start context marks integrity/incomplete ambiguity and is never invented. Summary counts/totals and its fixed JSON field set are unchanged by this separate attribution mapping.

## 3. Nullable accounting known answers

Usage counts are null or nonnegative finite builtin ints excluding bool; floats, negative, nonfinite, custom objects, cycles and invalid nesting refuse before serialization. availability is known, partial, unknown or invalid, validated against actual fields rather than trusting a label. observation_source is native or derived; scope is attempt or cli_process. input_semantics is total_includes_cache, uncached_excludes_cache or unknown; output_semantics is total_includes_reasoning, visible_excludes_reasoning or unknown. snapshot_kind is final, cumulative or incremental. final is a terminal cumulative total, may seal the same cumulative stream, and is never an additional increment; conflicting/repeated final totals follow the same identity/regression rules. A final cumulative total cannot be mixed into an incremental stream in this first release. native_usage is a bounded read-only host copy made from an admitted builtin dictionary, serialized through its declared numeric projection only: input_tokens, output_tokens, prompt_tokens, completion_tokens, cached_input_tokens, reasoning_tokens, cache_read_input_tokens, cache_creation_input_tokens, promptTokenCount, candidatesTokenCount, cachedContentTokenCount, thoughtsTokenCount. Values are null/nonnegative int; no arbitrary provider metadata or nested dump. Declared cache components must not be added twice, and creation/read semantics must be mapped explicitly by later dialect wiring. If their relation is unknown, normalized total remains null.

Normalize input/output totals according to declared semantics: included subsets are not added; excluded components are added only when both operands are known. Included cache/reasoning cannot exceed the corresponding known total. Successive cumulative2/5/9 observations use distinct host observation IDs and yield9; replaying the identical9 observation with its same host observation ID still yields9. Reusing the same host observation ID with different content refuses with integrity_error, independently of cumulative normalization. Regression or conflicting component semantics marks invalid/incomplete without erasing an earlier measured subtotal. Explicit incremental2/3/4 yields9; same host event replay contributes once, distinct equal values contribute separately. Cumulative and incremental streams cannot be mixed within an attempt/field without an explicit scoped reset (no reset authority is supplied by this first release), so mixed semantics refuse. Missing fields never erase prior known cumulative data. A field with no valid observation stays null, never inherits legacy Usage defaults. A failed attempt with known usage contributes the same as a successful one. A not_dispatched attempt is excluded from transport usage aggregation; an unknown/possibly_sent attempt contributes an unknown-attempt count and makes its total null. For actually observed sends, every unavailable/invalid final field makes the corresponding run total null while preserving independent known_subtotal and unknown/invalid counts.

Timing is from observed owner intervals, not a divided legacy aggregate. work is the sum of independently observed completed transport intervals; wall is the observed run_open-to-terminal elapsed interval (including overlap, gaps and owned cleanup), never sum of durations or machine's legacy /3. Unclosed durations remain unknown. Reopen can reuse persisted completed interval offsets from the same run clock epoch; it cannot subtract clocks from different processes or invent an end. Golden run_open0/terminal4 with concurrent intervals [0,3] and[1,4] produces work6/wall4, independently of usage. Legacy Usage and LLMResult arithmetic remain unchanged.

## 4. Automatic supported Linux ownership and durable commit

The NEW audited capability initially supports the linux-local-audit-v1 implementation profile on Linux ext4/btrfs. This is a prospective engineering support envelope, not evidence that tests passed or every device/mount is crash-safe. Development/release controls on the declared runtime/filesystem profiles qualify lock/file/directory-fsync/fault behavior; their output is test evidence, not a per-repository certification receipt. All supported first-run operations are automatic inside03. Unsupported OS/filesystem, unavailable or malformed kernel profile observation and a failed required primitive explicitly refuse new audited readiness.05must separately admit a named legacy_compatibility_gate before changing currently supported legacy behavior on unsupported profiles; never silently bypass auditing or relabel compatibility.

The Linux/profile check precedes any unsupported-OS write. The small PRIVATE producer _prepare_audit_root(root:Path, *, create:bool)->_RootHandle|AuditFault lives in the SAME03module. It is called by open(create=True), read-only reopen(create=False), and maintain(create=False). _RootHandle is an internal owned directoryFD plus its observed AuditCapability; the caller closes its FDs in finally, not an externally supplied capability token. With create=True, create only missing trusted-host-selected audit path components0700 and sync each newly created component's parent directory; preserve preexisting foreign ancestors and refuse symlink/identity changes rather than chmod/delete them. An absent root with create=False yields an explicit observation fault/no maintenance deletion. Validate the final root owner/mode/regular-directory identity, open it anchored with close-on-exec/no-follow semantics and retain its dev/inode identity. No child subprocess, provider call, external attestation or new service is involved.

Observe Linux filesystem type via that ACTUAL opened directoryFD's /proc/self/fdinfo mnt_id matched to exactly one /proc/self/mountinfo record's mount ID and filesystem field after its separator; do not infer from sys.platform, filename or longest pathname alone. Read fdinfo<=16KiB and mountinfo<=1MiB; absent/malformed/ambiguous/oversized observation refuses. Only ext4/btrfs are in this first profile; network/overlay/tmpfs/unknown types are unsupported. Kernel mount ID, root dev/inode and type are observed state, not response/settings-supplied authority. Revalidate held directory/path/lock identity at each root transaction; changed mount/root identity refuses. The helper performs an actual directory fsync; open then obtains the real exclusive kernel lock and performs the normal admission-file fsync/directory commits below before admitted=True. These normal owned commits are the file capability check, not an extra uncharged sacrificial probe. There is no manually generated evidence file outside quota to obtain before a new repository works.

AuditCapability is produced only by these observations/owned operations and exposed for diagnostics through snapshot; no caller parameter may provide it as permission. A profile observation alone never grants dispatch: open and each start must independently satisfy their full durable commit acknowledgement. Field runtime_fingerprint is host-computed from the observed implementation/runtime version, not an arbitrary supplied hash. Failure to sync or validate identity is a typed fault/unsupported refusal, never an admitted ID. A device failure after readiness remains a persistence fault; successful small operations are not a universal power-loss proof.

One owner process per run, serialized threads. All filesystem mutations/inventory/commit/maintenance use one automatically created/validated empty0600regular root lock file with fcntl.flock(LOCK_EX|LOCK_NB), released and its owned FD closed in finally. No nested ForgeLock, PID-file release, signal-handler installation, service or central index. Never unlink/replace the lock inode while it coordinates the root. Root lock acquisition has a maximum1second elapsed budget; start/maintenance use min(1second, remaining absolute action_deadline), reject nonfinite deadlines, and refuse at/after zero remaining. Other operations use the same1second bound. OS sync calls may block and are not claimed to have a cancelable1second durability timeout; caller action_deadline must be rechecked after commit before dispatch. Test finite lock acquisition with owned processes, not a promise that filesystem I/O always finishes in1second.

Lock order is owner thread mutex, then root lock. Maintenance acquires only root lock and never waits for another live run's mutex. Public methods do not recursively acquire another open description of the lock. No fork/exec/network/caller wait occurs while holding it; open owned lock FDs close-on-exec and never export/dup them. Linux locks belong to an open file description: fork/dup share them, and another open description may contend even in the same process. A forked copy of a recorder is invalid for writes; it must not unlock a parent's description. Its only allowed cleanup closes the inherited duplicate; a fresh recorder must open a fresh description and pass normal admission. This rule receives an owned fork/descriptor qualification control and no broad multiprocessing API.

Durable open: under root lock inventory plus prospective full-run charge must fit; create the fresh owner-only run directory, commit run_open/admission marker with file fsync, then fsync run and root directories before admitted acknowledgement. A failed/missing/partial admission remains charged as an ambiguous full run; never admit another writer to it. An in-memory ledger does not substitute for the next holder's locked directory inventory.

Durable start: append one framed bounded journal event, flush if buffered and fsync the file (and run directory when the journal name is created) before StartAcknowledgement.admitted=True. Durable acquired: precharge all prospective temp/overlap bytes under the root lock, write a uniquely owned temp, fsync its contents, rename atomically inside the run, fsync that directory, then append/fsync its acquired event. Only then acknowledge its ref. A published file without a durable event stays orphaned evidence and charged, not a successful observation. Finish fsyncs its event; finalize commits event and terminal marker plus directory sync before changing charge/acknowledging terminal state. Existing immutable raw paths are not overwritten; same-event replay reuses the same committed ref. Close/fsync failures latch incomplete. On failure preserve the primary caller exception; known owned resources close in finally regardless of secondary diagnostic/persistence errors. No unknown resource cleanup.

Freeze is host-only durable marker state under root lock; frozen records are never pruned. For a terminal run, compute and admit its full-reservation charge delta BEFORE the first freeze event/marker/temp write, then retain the same lock through freeze file/event and directory commits as specified in section5. Never publish a frozen marker or release the lock between capacity admission and durable transition. Active runs already charged full16MiB have delta0 but still require the bounded durable transition. A failure after admitted freeze mutation begins remains ambiguous/full charge; the admitted delta ensures even that conservative failure state cannot exceed root512MiB. Unknown ownership, lstat/symlink/hardlink escape, integrity or inventory error refuses admission/maintenance rather than following paths or deleting unknown files. Root/run0700 and owned regular files0600, no accepted-receipt name prefix or discovery path. Header/source/response/model fields never turn this observational journal into accepted clean evidence.

## 5. Reservation, temporary bytes and retention

All sizes are encoded logical file bytes, not a claim to bound filesystem allocation overhead or guarantee available storage. MiB=1024*1024. Constants: root512MiB; run16MiB; transport raw(wire/stdout/stderr combined per attempt)256KiB; decoded per attempt256KiB; event2KiB; preview400escapedcharacters; terminal retention7days. Atomic temp bytes, old/new overlap, interrupted/orphan temps, journal framing and all per-run metadata are counted before acknowledgement. Raw rename normally moves one inode, not a second copy, but any actual simultaneous files are charged. Do not account only final published length or unlink orphan evidence to make room.

Each full16MiB active envelope has ordinary-partition capacity16MiB-16KiB and a16KiB marker partition. All run_open/admission metadata, journal events other than the fixed marker records, raw/decoded/temp bytes are ordinary bytes. The marker partition reserves four logical records of at most1KiB encoded each (final, first audit refusal/fault, one-way freeze, tombstone), with at most one journal copy, one committed marker copy and one simultaneous atomic-temp copy per record (12KiB combined maximum, leaving4KiB framing slack). Identical repeats do not append; no repeated faults or toggled freeze events accumulate. No additional encoded central root index/marker is created: the only root coordination file is empty. Journal representation of the fixed final/fault/freeze records counts in this marker partition as well, so journal+marker+temp copies together must fit its16KiB; implementations cannot budget each copy independently. If a fixed record cannot fit, return explicit fault, never declare closure. At no point may ordinary+marker physical file bytes exceed16MiB.

Under root lock, charge = sum of owned run charges. Active/frozen/ambiguous/torn run charge is full16MiB (or observed bytes if unexpectedly greater, which refuses further admission). Durable nonfrozen terminal/tombstone charge is ordinary retained bytes +16KiB reserved marker partition, including retained marker/journal/temp bytes within that partition. Actual marker bytes are not charged twice, but the unused reserve remains charged. Unknown root files or malformed partition facts refuse admission; no uncounted extra central metadata is tolerated. Thus32full envelopes fit512MiB only if there is no separately retained terminal/tombstone charge; a nonzero tombstone consumes room. Admission of N+1 cannot use uncommitted terminal shrink or PID-only reclamation. A post-terminal freeze is a capacity-increasing transaction: while holding the same root lock, revalidate the run and locked inventory, compute its prior charge Q=ordinary retained bytes+16KiB and delta=16MiB-Q, and require locked root charge+delta<=512MiB BEFORE any freeze write. Unexpected Q>16MiB or malformed facts refuse with integrity/inventory fault. Hold the lock until durable freeze event/marker file and directory commit; success changes charge to full16MiB exactly once. Quota denial before any write preserves all recorder and persisted state under the explicit section1 exception, with no fault event/marker allocation. If a primitive fails after mutation starts, retain conservative full16MiB ambiguous charge using the already admitted delta, never shrink/erase the partial transition to regain capacity. Every later locked inventory treats a partial/torn freeze transition as full charge. The former legal31full plus two4MiB-ordinary terminal runs charges504.03125MiB; freezing either would charge516.015625MiB and must be refused before mutation. There is no new service/index, second envelope or PID-based reclamation.

Before each write, charge actual currently retained ordinary+temp+orphan bytes and worst-case proposed simultaneous bytes; refuse/persist bounded prefix only if a safe next commit fits the existing envelope. body/decoded overflow retains an exact prefix under its cap, hashes retained bytes only, marks partial and latches incomplete/refuses further audited dispatch. original_bytes is the actual acquired byte count when known, null for an unknown whole-stream size; a truncated digest is never labelled a full-response digest. If nothing can be committed, acquired.admitted=False/ref=None still preserves the separately retained caller result/error in later05. Marker reservation cannot promise a successful write under disk-full/I/O failure; no durable ack follows such failure.

Explicit next-run maintenance under the root lock prunes only durably terminal, nonfrozen runs older than7days using host timestamps and known immutable run identity. Write/fsync a bounded tombstone in that run and sync its directory before any owned raw deletion; retain the directory/tombstone and its16KiB charge, remove only its qualified ordinary files, and sync removal before reducing ordinary charge. A torn/failed transition remains conservatively charged and cannot become silent success. Tombstones remain7days after durable prune, then their known terminal directory may be durably removed/root-synced under the same lock. Frozen/active/ambiguous runs never age into reclaimable state; no automatic service or PID liveness heuristic is allowed. If clock/state/ownership is uncertain, refuse pruning/new admission rather than invent age. Run metadata itself lives inside its envelope; quota does not assume32reservations plus an extra uncharged index.

## 6. Exact local raw and previews

Retained raw is exact admitted acquired bytes or explicitly labelled retained prefix; no semantic redaction while claiming exactness. Response/source bytes may contain sensitive values. Permissions and bounds limit exposure but do not make raw semantically secret-free. Only structural request/auth/environment/endpoint exclusions are promised for metadata. preview_enabled defaultsFalse and may be enabled only by an explicit trusted owner setting, never response content; opt-in previews are labelled sensitive, escaped and bounded400characters, with their encoded metadata bytes charged. Preview processing cannot expand authority or feed receipt completion. Derived decoded bytes carry a distinct layer/ref/digest and do not replace original wire bytes.
