## Focused official literature refresh

Read2026-10-05 as an addendum to the already retained literature/design ancestry. Current Python documentation says3.14.8; it is not evidence that either installed profile runs that version. The plan selects a prospective qualified Linux local-filesystem capability, not universal Unix/Windows support. No durability or locking experiment ran during this refresh.

- [Python fcntl documentation](https://docs.python.org/3/library/fcntl.html), availability and flock sections: Unix availability and syscall failure reporting support explicit unsupported/error handling. This is API documentation, not a filesystem qualification receipt.
- [Python os.fsync documentation](https://docs.python.org/3/library/os.html#os.fsync), fsync section: buffered file content must be flushed before native synchronization. The plan distinguishes encoded writes from durable acknowledgements.
- [Linux flock(2)](https://man7.org/linux/man-pages/man2/flock.2.html), DESCRIPTION/NOTES: open descriptions own locks; fork/dup aliases can unlock them, while independent opens contend. Nonblocking acquisition does not detect deadlock. Remote-filesystem semantics differ. The plan forbids inherited-writer use and qualifies local profiles only.
- [Linux fsync(2)](https://man7.org/linux/man-pages/man2/fsync.2.html), DESCRIPTION/ERRORS: file synchronization alone does not persist directory entries; directory synchronization is separately needed. Storage completion may block and report I/O/space errors. The plan does not promise a one-second bound for fsync itself.

- [Linux proc_pid_fdinfo(5)](https://man7.org/linux/man-pages/man5/proc_pid_fdinfo.5.html) and [proc_pid_mountinfo(5)](https://man7.org/linux/man-pages/man5/proc_pid_mountinfo.5.html): the opened descriptor exposes its mount identifier; mountinfo labels that identifier and filesystem type. The small automatic helper matches descriptor identity, not a filename heuristic.

These primary sources justify explicit file-description ownership and directory commit rules. They do not justify claiming arbitrary filesystems crash-safe or overriding legacy platform support. Release engineering requires actual finite owned-file/lock/directory-sync controls; each new root automatically checks the supported profile and its normal owned operations before admitting readiness, without an external qualification receipt. Later05unsupported legacy policy remains a named independent gate. Full16MiB reservation/16KiB marker partition are parent-selected product accounting rules, not requirements asserted by these sources.
