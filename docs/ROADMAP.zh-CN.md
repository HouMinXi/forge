## 当前：v3.0，评审质量实测

2026-08-30 开启。在这之前，「三轮收敛评审比单次评审强」这个说法从来没有在这个工具自己的输出上测过。这个里程碑就是把仪器搭起来，然后跑一遍。

| 步骤 | 状态 | 在哪里看 |
|---|---|---|
| 指标聚合 | 2026-08-30 合入 | `src/code_forge/eval/scorer.py` 里 `EvalSummary` 的 precision、recall、F1 和信噪比属性；分母为零时返回 `None` 而不是假的 0.0；best-of-N 换成均值加标准误；表格里的比率要满 30 条才显示。 |
| 评测语料 | 2026-08-31 合入 | 150 条来自 SWE-bench Verified：75 条缺陷 diff（把修复反过来打）和 75 条干净对照（修复本身），11 个仓库，每个仓库最多 8 条，`python3 -m code_forge.eval.build_corpus` 从固定种子重新生成。干净对照可以声明「没有任何发现属于我」。 |
| 深度扫描 | 账本 2026-09-04 跑完 | 同样 150 条，分别要求 1、2、3 轮连续干净。结果见 [EVALUATION.md](EVALUATION.md)。 |
| 证伪消融 | 两臂 2026-09-05 跑完 | 同一语料，证伪门开与关，轮数上限 3。结果见 [EVALUATION.md](EVALUATION.md)。 |
| 可续跑、可并发的评测运行器 | 2026-09-04 合入 | `code-forge eval --jobs N --resume-log FILE`：有界进程池，每条落地即追加写入的 JSONL 账本，实验臂设置按值传给每个子进程并在花掉任何一次评审之前先核对。`scripts/analyse_arms.py` 把账本变成报告里的数字，并打印每个数字背后的账本行号。 |
| 切换服务商 | 2026-09-03 合入 | `scripts/forge-provider.py`：一条命令把一台机器上所有 `gate.yaml` 指向某个评审后端，信任记录同步更新。 |

这个里程碑还挂着一项没有开工的：裁决前执行那一步的容器化。它在等一个真实需求出现；到目前为止原生子进程路径已经覆盖了所有评审过的场景。

## 下一步：v3.1，拆分评审

Phase 59，进行中。深度扫描显示轮数加多只抬召回、不动精度，所以这个里程碑针对外部证据说会作用于精度的两个杠杆：证伪判断怎么问，以及有多少带来源的事实能到达评审者。这个框架背后的论文见 [REFERENCES.md](REFERENCES.md)。

两条线，各自以小的独立合并落地：

判断线。

- A1，2026-09-05 合入（`ee45427`、`bf3cc09`）：证伪器返回格式不对（不是 dict、没有 verdict、verdict 不在枚举里，或者返回了证伪器永远不该返回的 FIXED），现在记为 `FalsifyProtocolError`，归到基础设施故障，不再静默读成「不确定」。收敛行为没变，变的只是归因。
- A2，计划中：从 Phase 58 账本里挑出人工裁定过的发现，做一份标定集，测证伪器本身判对的比例。
- A3 / A4，取决于 A2 的数据：如果标定准确率低，把那条十步的证伪 prompt 拆成几个独立的是/否问题。

证据线。

- B1，2026-09-05 合入（`59dcd03`、`4104e37`）：`src/code_forge/context_sources.py`，给评审 prompt 提供外部事实的 provider 契约。每条事实带来源；provider 索引的 commit 和被评审的 commit 不一致时拒绝使用，除非操作者显式同意；provider 抛异常记为错误，不会变成一张空表；`gate.yaml` 写坏了是错误，不是空配置。
- B2，进行中：把 context source 接进 prompt 构建器，对没有用它的配置，prompt 一个字节都不能变，共享前缀才能继续命中缓存。
- B3 / B4，计划中：在同一语料上开一个 context source 跑一臂，然后写报告。

任何一条线跑出零结果，就照零结果发布。

## 不在路线图上的

常有人问但这个工具不做、近期也没打算做的：从被驳回的发现里学习，技术债评分，性能回归基准，以及超出现有双仓库联合评审的多仓库依赖分析。README 的「Honest limitations」一节是权威清单。
